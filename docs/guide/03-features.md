## 一、先看清这个站（侦察）

| 功能 | 命令 / 位置 | 产物 | 用它当 |
| --- | --- | --- | --- |
| 全站侦察 | `recon <url> [页数]` / 顶部「侦察」 | `recon/atlas.json` + 缩略图 | 后面一切的上下文：克隆、审计、对标都以它为基础 |
| 看站点配方 | `profile <host>` | 合并后的规则 | 想知道"这个站的哪些路径被算成什么类型" |

侦察做三件事：跟随重定向拿到真实 origin → 读 sitemap 并做 BFS 抓站内链接 →
用**路径规则 + 页面特征**（有没有价格、有没有密码框、正文密度）给每页分类。
有页数上限（配方里的 `maxPages`），因为定位是几百页的竞品站，不是全网爬虫。

**站点配方**是三层合并的：内置默认 → 运行时学到的 → 人工整理的（`core/sites/*.json`，进 git）。
换一个站不用改代码，只加一份配方。

## 二、复刻（克隆）

| 功能 | 命令 / 位置 | 说明 |
| --- | --- | --- |
| 单页完整克隆 | `forge <url>` / 顶部「只克隆此页」 | 跑完六段（捕获→构建→截图→比对→校准→情报） |
| 整站批量克隆 | `queue <host>` / 菜单「整站克隆」 | 持久化队列 + 断点续跑 + 单页超时熔断 |
| 增量重跑 | `queue <host> --incremental` / 菜单「增量克隆」 | 只重跑**源站变过**的页（比对服务端 HTML 指纹，不起浏览器） |
| 补抓缺失抓包 | `queue <host> --missing-har` | 只重锻缺 `network.har` 的页 |
| 响应式变体还原 | `multi-snapshot` / `responsive-upgrade` | 多视口快照；低分页自动升级，**分数提升才保留** |
| 画布内容光栅化 | 捕获阶段自动 | JS 画的 `<canvas>` 转成静态图，否则脚本一剥就是空白 |
| 视频封面截取 | 捕获阶段自动 | 没有 poster 的 `<video>` 浏览器画的是**纯黑**（不是第一帧）；归零到第 0 帧截一张当封面 |
| 去重 | `dedupe <host>` | 内容寻址 + 硬链接，同一文件只占一份磁盘 |

**断点续跑怎么工作**：`workspace/<host>/queue.json` 逐页记状态。中断后再跑，
已完成页直接跳过。控制台在检测到有未完成页时，菜单里会多出「继续整站克隆（剩 N 页）」。

**单页熔断**有两条线：硬超时管"跑太久"，无进展管"卡死了"。任何一条触发都只杀当前这一页，
不影响整批 —— 判错的代价是把一个正常但慢的页面判死，所以两条线分开设。

## 三、验证"到底像不像"

| 功能 | 命令 / 位置 | 产出 |
| --- | --- | --- |
| 单页还原度 | 克隆时自动 | `score.json`：像素 / DOM 结构 / 字段覆盖 三维 + A/B/C 分级 |
| 差异热图 | 克隆时自动 | `diff.png`：红的地方就是不一样的地方 |
| **差异形态分析** | `score.json` 的 `shape` | 区分「某块内容缺失（集中）」与「文字抗锯齿差异（弥散）」 |
| 多视口体检 | `verify <host> --all` | 375 / 768 / 1440 三档各跑一遍，给出**最差视口** |
| 交互回放 | 体检的一部分 | 按钮 / 折叠 / 标签页的状态比对，不是只看静态图 |
| 同步滚动对比 | 报告页 → 克隆档案 | 原站与镜像同屏滚动，人工核对用 |
| 资产缺口 | `assets <host>` / 页面表「缺口」列 | 分四类：视觉缺口 / 元数据 / 追踪像素 / 设计替代 |

> **为什么要分"形态"？** 同样是 96% 的相似度，含义可能完全相反：
> 集中差异意味着"这一块内容没搬过来"（真问题），弥散差异往往只是字体抗锯齿（不是问题）。
> 只看一个总分，会把这两种情况混为一谈。

**AI 校准**（`fixup`）就接在这一步：它按差异形态自判值不值得修，最多修 2 轮，
**修不动就保留原样并写明原因**。校准曲线记在 `fixup-history.json`，控制台「质检」页能看到；
如果没跑，那里会写**为什么没跑**（模型未启用 / 缺产物 / 是动画噪声），而不是留一个空格子。

## 四、审计与竞品分析

| 功能 | 命令 / 位置 | 产出 |
| --- | --- | --- |
| SEO 审计 | `audit <host>` / 菜单「SEO 审计」 | 66 条规则 / 六分类：抓取与索引、内容与语义、结构化数据与社交、性能与体验、链接与架构、安全与合规 |
| 服务端 vs 渲染后对比 | 审计的一部分 | 识别 JS 渲染依赖（服务端 HTML 是空壳的站，规则口径会不一样）；含 hreflang 校验 |
| 变更监控 | `watch <host>` / 「运行监控」 | 基线快照 + 去噪，报出标题 / 描述 / canonical / 正文变化 |
| **SEO 回归门禁** | `audit --baseline F --fail-on-regression` | 可接 CI：与基线比对，出现回归就让流水线红 |
| 跨站对标矩阵 | `matrix <site1> <site2>` | 多站点并排：分数 / 覆盖率 / LCP / 页面类型 |
| 竞品情报 | 克隆时自动 | `intel/intel.json` + 跨页 Excel：标题 / H1 / CTA / 价格 / 链接 |
| 设计资产 | `tokens` / `components` | 从 CSSOM 归纳色板、字阶、间距、圆角、阴影；抽取常见组件成独立预览 |

**规则数由测试钉住**：`core/test/seo-rule-count.test.mjs` 从源码数出真实条数并断言它等于文档里写的数字
（README、CLI、MCP、控制台都在检查范围内）。这个数字在文档里写错过两次，所以不再靠人记。

> **真实用户指标（CrUX）** 做成可选：要自备 `HEIMDALL_PSI_KEY`。
> 没有 Key 时报告里会**如实写"只有实验室数据"**，而不是拿估算值冒充实测。

## 五、交付：把东西交出去

| 功能 | 命令 / 位置 | 产出 |
| --- | --- | --- |
| 静态交付包 | `deliver <host>` | `deliverable/<host>-<date>/`：镜像 + 原站 CSSOM/DOM + 差异热图 + 还原度 CSV + 接手 README |
| 交互镜像包 | `live <host>` | 自包含可部署包：`serve.mjs` + Dockerfile + 清洗过的 HAR + 健康报告 |
| **改站起点清单** | 报告页 → 改站起点 | `edit-manifest.md`：换域名 / 图片 / 文案各要动哪些文件 |
| **域名替换** | 同一张卡片 | 预览 → 确认替换；**改前逐文件备份，可逐字节还原** |
| 交付包保留策略 | `deliver-prune [--keep N]` | 每站点每类型留最近 N 份；认不出的命名绝不自动删 |
| 沙盒改造台 | `sandbox <host> <page>` | 起一个本地沙盒：改 HTML/CSS，与原版实时对比 |
| 书签入口 | `browser` | 生成安装页：在任意网页点一下书签，就把当前页送进 Heimdall |
| MCP 服务器 | `mcp` | 把上面这些能力暴露给 agent 客户端 |

### 交付包里的三个"可核验"设计

1. **校验和清单**（`checksums.json`）：每个文件的 sha256
2. **与上次导出的差异**（`changes.json`）：新增 / 变化 / 删除 / 不变各多少
3. **健康报告**（`health.json`）：离线打开会 404 的资源有几个，一条条列出来（默认还只算**必须处理**的那批）

> **为什么不做"给已部署的包打补丁"？** 因为补丁协议本身会成为新的不确定性来源 ——
> 包对不上、用户改过文件、跨了两次导出……代价远大于省下的那点传输量。
> 正确做法是把增量压到**传输层**（重新导出一份，diff 告诉你变了什么），见 [../DELIVERY.md](../DELIVERY.md)。

## 六、运维：别让磁盘悄悄满掉

| 功能 | 命令 / 位置 | 说明 |
| --- | --- | --- |
| 内容寻址存储 | 自动 | 资产按内容哈希存一份，其余用硬链接 |

## 七、动效：到底复刻到什么程度

这一条以前在文档里只有一句"JS 驱动的动画不逐帧复刻"，说了没做什么、没说能做什么。真实情况分三层：

| 类型 | 静态镜像 | 交互镜像 | 为什么 |
| --- | --- | --- | --- |
| **CSS 动画**（`@keyframes` + `animation`） | ✅ 活的 | ✅ 活的 | 镜像只剥脚本；CSS 动画本来就由样式表驱动，打开就播 |
| **CSS 过渡**（`:hover`、`transition`） | ✅ 活的 | ✅ 活的 | 同上 |
| **JS 动效**（打字机 / GSAP / Framer / 轮播） | ❌ 停在被捕获那一帧 | ✅ 活的 | 静态镜像剥脚本；交互镜像保留原脚本并把 URL 重指到代理 |
| **滚动揭示**（IntersectionObserver） | ⚠️ 定格在捕获时状态 | ✅ 活的 | 采集时会滚动扫掠一遍，把揭示后的状态定格下来 |

所以不是"没做"，是**分在哪一层看**。静态镜像是"冻结的照片"，交互镜像才是"会跑的快照"。

### 动效档案与可复用的关键帧

交付包里附 `motion.md` + `motion.json`：逐页列出 CSS 动效有几处、哪些是无限循环、
哪些是**靠内联样式挂载**的（Vue / React 常见，不查内联样式就会漏判）。

每页还会抽出一份 `raw/<page>/motion-css.css`，分两段：

- **A · 在用的** —— 打开镜像就在播的，照抄即可
- **B · 定义了但捕获时没被引用的** —— **这段往往才是重点**。入场 / 滚动揭示类动效几乎都长这样：
  关键帧常驻样式表，而引用它的那条规则（`.fadeInDown-enter-active{animation:…}`）只在过渡的
  那几百毫秒里存在，静止采样时它已经没了。我们抓不到**引用**，但**代码本身已经在手上**。

实测 thordata 首页 18 组关键帧里 15 组属于 B 段。

> **这是离线做的**：`@keyframes` 与 `animation:` 就在已经存下来的 `cssom.css` 里，
> 不需要再访问一次原站、不需要重克隆。所以历史产物也能补出这份档案。

### 一个踩过的坑（写在这里免得再犯）

冻结样式（`animation-duration: 0s !important`）只是为了让**截图**可复现 —— 动画在飞的时候，
原站和镜像各截各的，比出来的是时序差不是相似度。但它一度跟着 `dom.html` 混进了交互镜像，
于是**每一页镜像都被我们自己的截图工具冻住了**（实测 apify 61/61 页，hover 过渡全是瞬移）。
现在冻结样式只有一份实现（`core/src/freeze.mjs`）并带标记，写 `dom.html` 时剥掉，
`build_live` 再兜一道 —— 历史上被冻住的产物 `live <host> --rebuild` 即可修复，不必重爬。

## 命令速查

完整列表跑 `node core/src/cli.mjs`。最常用的这些：

```bash
# 侦察
node core/src/cli.mjs recon example.com 60        # 抓 60 页，深度 2

# 克隆
node core/src/cli.mjs forge https://example.com/ home   # 单页
node core/src/cli.mjs queue example.com                 # 整站
node core/src/cli.mjs queue example.com --incremental   # 只重跑变了的页

# 验证与审计
node core/src/cli.mjs verify example.com --all
node core/src/cli.mjs audit example.com --max 20
node core/src/cli.mjs assets example.com

# 交付
node core/src/cli.mjs deliver example.com
node core/src/cli.mjs live example.com --offline
node core/src/cli.mjs live example.com --root mirror    # 纯前端站部署用这个

# 治理
node core/src/cli.mjs storage
node core/src/cli.mjs dedupe example.com
node core/src/cli.mjs cas-gc                            # 只看不删
```

## 边界：它不做什么

| 不做 | 为什么 |
| --- | --- |
| 被访问控制挡住的内容 | 只碰公开页面，或操作者本人**有权访问**的页面；不实现任何绕过。需要登录的站点走「人工登一次」 |
| 外链分析 / 关键词研究 / 排名追踪 | 那是需要买数据源的生意，不是这个项目的定位 |
| 逐帧复刻 JS 动画 | JS 动效在**交互镜像**里是活的（原脚本保留、URL 重指到代理）；静态镜像只停在被捕获的那一帧。CSS 动画与过渡在**两个镜像里都是活的**，见下 |
| "换皮上线" | 这是技术分析与自用改造的**起点**，不是商用授权。见 [../../RISKS.md](../../RISKS.md) |
