**三个分水岭问题：**

1. **指标自证**：`total = 0.5×pixel + 0.3×dom + 0.2×data` 中，dom/data 是拿"克隆页"与"生成克隆页所用的同一份 dom.html"对比，天然≈1.0 —— 相当于 50% 的分数白送。实测 pricing：pixel 94.7%，总分却 97.4%。对外宣传的"96.8% 还原"因此系统性高估约 2-3 分，且无法反映交互、全页、响应式差距。
2. **活镜像不可交付**：`deliver.mjs` 只打包 `clone/`（死镜像），不打包 `live/`；`/lm/` 活镜像依赖引擎常驻 + 原站可达 + 正则改写 + `MAGIC` 全局 Proxy stub。它不是"能直接部署直接用"的产物。
3. **控制台不是工作台**：唯一的 `Atlas.vue` 680 行，承担星图/站点切换/页面清单/详情/锻造/主题/SEO 全部职责；没有任务中心、项目管理、搜索筛选、批量结果、失败重试；并发锻造时 `forge`/`esForge` 是单例，UI 状态会被后一个任务覆盖。

## 2. 关键发现（按严重度排序）

### P0-1 还原度指标自证，必须重做口径（产品诚信问题）

**证据链**：`build_clone.mjs` 从 `capture` 產出的 `dom.html` 派生 `clone/index.html`；`diff.mjs` 随后用 `domSimilarity(dom.html, clone/index.html)` 与 `dataScore(dom.html, clone/index.html)` 打分。样本 `pricing/score.json`：`nodeRatio=1, tagCos=1, classJac=1, data=1`，pixel=0.9471，total=97.4。

**问题**：
- dom 的 30% 与 data 的 20% 是"同源自证"，不构成独立证据；
- pixel 只测 1440×900 首屏，不含全页、移动端、hover/菜单/滚动状态；
- `fixup` 直接以同一张截图的分数为奖励信号，存在过拟合单帧的风险（Goodhart）；
- 对外只暴露一个综合分，用户无法知道"看起来像不像 / 能不能点 / 手机上像不像 / SEO 好不好"。

**建议**：拆成四张独立成绩单，综合分只作内部信号、不对外当承诺：
1. **视觉保真**：多视口（375/768/1280/1440/1920）× 全页 × 多状态（default/hover/focus/menu-open/tab/accordion），用 SSIM + pixelmatch + 区域聚类；动态区域单独标注、不计入分子也不掩耳盗铃；
2. **结构保真**：与"实时重渲染的原站"对比（不是缓存 dom.html），保留 style-probe 的 computed-style 逐元素差异作为证据；
3. **功能保真**：录制交互回放（点击/输入/展开/滚动），对比执行后 DOM/状态，输出 通过/失败/跳过；
4. **数据保真**：情报字段与实时原站对比。
   每条结论可下钻到证据（diff 图 → 差异区域 → 元素路径 → 原始/克隆属性值）。

### P0-2 活镜像必须从"开发机胶水"升级为"可交付运行时"

**现状**：`build_live.mjs` 用字符串替换把绝对 URL 改成 `/lm/<host>/...`，注入 `<base>` + fetch/XHR patch + 第三方 stub，再依赖 `engine-server` 的 `/lm`、`/px`、Referer 兜底三条代理路径。实测已出现 chunk 404、裂图、54 条 console error；`deliver.mjs` 不打包 live。

**建议**：
- **停止改写 JS 字符串**（正则改 bundle 是脆弱的根源）；
- 捕获层改为 **Playwright 全网络录制**（document/js/css/font/img/media/XHR/fetch/WS + HAR），建立资源依赖图；
- 活镜像改为 **Service Worker 拦截 + 本地资产优先 + 原站回源**（或本地反向代理），HTML 只改必要的 base/URL，不在 bundle 里做手术；
- API 用 **HAR 录制 → 本地回放/可选回源**；第三方脚本分三类标注：保留 / 降级 / 剥离，不再用无限递归 `MAGIC` Proxy；
- 导出三种形态：`snapshot`（离线静态）、`runtime`（可交互，需回源）、`deploy`（Docker / Edge Worker 一键起）；
- 验收：断网打开 snapshot 无外链；断原站后 runtime 的本地覆盖率有报告；`docker compose up` 后目标页可用。

### P0-3 控制台并发锻造状态覆盖 + 缺少任务中心

**证据**：`Atlas.vue` 中 `forge` 与 `esForge` 是单例；`forgeAll`/`forgeChecked` 用两个 worker 并发 `startForge`，第二个任务会覆盖 `forge.value` 与 `esForge`，前一个任务的 exit 事件会改到后一个任务对象上，并 `close()` 掉后者的 EventSource。

**建议**：
- `forge` 改为 `Map<taskId, task>`；每个任务独立 EventSource；进度写入统一 Job store；
- 新增**任务中心**（排队/运行/成功/失败/取消/重试/日志/耗时），SSE 断线重连 + 任务恢复；
- 批量操作走"选择页面 → 加入队列"，结果不依赖当前选中项；
- 引擎侧补：任务持久化（SQLite）、取消、日志落盘、失败重试、host 级后处理去重（现在每锻一页都重跑 xlsx+linker+index-page，60 页会做 60 次全站汇总）。

补充（站点管理整洁度）：`/api/sites` 会把 `coreclaw.com` 这类 **0 页 / 0 边** 的空侦察结果当成正常站点展示（实测控制台出现 `coreclaw.com 0F`）。建议 atlas 增加 `status`/`failureReason`，UI 把失败站点标红并提供重试/删除，而不是与正常站点混排。

### P0-4 仓库卫生（立即处理，收益最大）

- `console/node_modules` 已被 git 跟踪（4,353 个文件，含 20MB 单文件）→ `git rm -r --cached console/node_modules`（**不要删本地目录**），加根 `.gitignore`；
- 根目录 6 个 `.log` 被跟踪 → `git rm --cached`，日志改 `logs/` 并忽略；
- 无根 `.gitignore` / `.gitattributes` / LICENSE / 根 `package.json`；
- 若仓库要长期开源或多人协作，建议用 `git filter-repo` 清理历史中的 node_modules（会改写历史，需与协作者协调）；
- `.env` 已正确忽略、未见硬编码密钥（好）；但 `HANDOFF.md` 暴露内部 LLM 中转地址，若仓库公开需移除。

### P0-5 安全边界（内网多人使用前必须做）

- `/lm/<任意host>`、`/px/<任意host>` 与 Referer 兜底 = **无鉴权的开放代理 / SSRF 面**；`CORS: *`；
- `/static` 的路径校验用 `file.startsWith(workspace)`，Windows 下建议改为 `path.relative` 规范化校验；
- 引擎无认证、无速率限制；建议：绑定 127.0.0.1 或内网 + token 鉴权 + 目标 host 白名单/黑名单 + 出站请求审计；
- 把 RISKS.md 的红线落成代码：robots/ToS 检查、登录区拒绝、速率限制、产物默认 `noindex` 与内部水印。

### P0-6 SEO 模块是种子，但离"工具"还远

- 当前仅 6 项：title 长度（有 bug）、description 长度、H1 数量、img alt、og:title、lang；
- `seoLite` 只有 7 个字段，存于 atlas 节点；没有独立 `seo.json`、没有规则引擎、没有站点级汇总、没有报告、没有回归对比；
- 建议：独立 `seo/` 模块（采集 → 规则 → 评分 → 报告 → 监控），先做 40-60 条高价值规则，后接 Lighthouse/axe/Schema 校验；把"克隆时顺带采集"与"SEO 审计"解耦，审计可单独对任意站点跑。

### P0-7 最近的回归：Graph3D 能力与 UI 文案不一致

- `console/src/Graph3D.vue` 在 `7ef004e` 中删除了 **Ctrl+拖拽平移**与 `autoRotate` prop 实现（-63 行），但 `console/src/Atlas.vue` 仍向它传 `:auto-rotate="autoRotate"`，仪表面板仍有"星图自转"开关，底部快捷键栏仍写"Ctrl+拖拽 = 平移"——**开关无效、文案与实现不一致**；
- SEO Title bug 在 HEAD 仍在：`core/src/crawler/recon.mjs` 的 `seoLite` 没有 `title` 字段，而 `console/src/Atlas.vue` 的 `seoChecks` 读取 `sl.title`（实测显示"Title 0 字符"）；
- 建议：恢复功能或同步删除 UI 入口，避免"两个真相源"；为 UI 控件 ↔ 实现加一条交互冒烟测试（点击自转开关、Ctrl 拖拽、SEO tab 断言）。

### P1 资产捕获矩阵不完整（"每个图标一致"的拦路虎）

当前 `capture.mjs` 抓取范围：`link[rel=stylesheet]`、`img`（src/srcset）、`source[srcset]`、`link[rel*=icon]`（仅记录不下载）、CSSOM 的 `url()` 引用。**未覆盖**：

| 类型 | 现状 | 影响 |
|---|---|---|
| `<svg><use href="/sprite.svg#id">` | 未捕获 | 导航/图标裂图（thordata 实测） |
| `<picture>` / `source[srcset]` 多候选 | 只取第一个 | 高 DPI/响应式图错 |
| `<video>/<audio>/<source>` | 未捕获 | 媒体缺失 |
| `<iframe>` | 未捕获 | 嵌入内容缺失 |
| inline `style="background:url()"` | linker 后补扫描 | 首屏可能先缺 |
| `manifest.webmanifest`、apple-touch-icon | 未专门处理 | PWA/图标缺失 |
| `favicon` 下载 | 记录但不下载 | 死镜像 favicon 常缺 |
| canvas/WebGL/动态绘制 | 不可能静态捕获 | 需标注"不可复刻"或录制为图片/视频 |
| API/XHR/RSC payload | 未录制 | 活镜像数据依赖回源 |

**建议**：捕获层统一产出 `resources[]`（URL → SHA256 → 本地路径 → 类型 → 来源 → 状态），用 CAS 存储；页面 manifest 只引用哈希；对未捕获/不可捕获项输出"缺口清单"，让报告诚实且可行动。

### P1 工程质量

无单元测试、无 E2E、无 CI、无 lint、无类型检查；`build_live.mjs` 残留大量 `console.error('[2f-entry]...')` 调试输出；`fixup.mjs` 失败静默 `exit 0`；`keeprate.mjs` 的 worst 统计写死 `page`（无害但说明缺测试）；Node 25 非 LTS，无 `engines` 约束。

## 3. 目标模型 v2：从"工具"到"可管理的工作台"

建议引入稳定的领域模型（先写进 PRD/数据库，再改 UI）：

```
Project（项目/站点群，可含多个竞品域名）
  └─ Site（域名：apify.com / thordata.com / 自有站）
       └─ Page（URL：path、标题、类型、状态、分数、SEO 分、大小、最后更新）
            └─ Artifact（快照 snapshot / 镜像 mirror / 报告 report / 情报 intel / 资产 assets）
Job（任务：recon | capture | forge | verify | audit | publish | export）
  └─ Run（一次执行：状态机 queued→running→succeeded/failed/cancelled，事件流、日志、重试）
```

关键原则：
- **一切产物有 manifest + schema version + 内容哈希**，可追溯、可重建、可增量；
- **页面类型由多种证据推断**（URL 模式 + 标题/H1 + 结构化数据 + 链接图 + LLM 兜底），替代当前纯正则（实测大量 use-cases/resources 被判为"通用页"）；
- **一个页面可以有多种镜像模式**（M0 静态 / M1 活体 / M2 可部署 / M3 重写），报告分别计分；
- **一个任务只做一件事**，host 级汇总（xlsx/linker/index/report）由队列末尾统一触发。

数据层建议：SQLite（pages/jobs/runs/scores/assets/issues/events 表）+ 内容寻址资产库（`data/assets/<sha256>`）+ 每页 JSON 导出兼容现有产物。当前 `workspace/` 约 780MB（apify 502MB + thordata 278MB）、交付包约 448MB，且 76% 的资产字节是重复的；整个工作区约 1.4GB。建议迁到 `HEIMDALL_DATA_DIR`（默认 `~/.heimdall/data`），仓库只留 schema 与 fixture。

## 4. 镜像引擎 v2：把"100% 复刻"拆成可工程化的四层

### 4.1 先定义"复刻"的四个层级（对外话术与验收一一对应）

| 层级 | 名称 | 内容 | 保真承诺 | 今天的状态 |
|---|---|---|---|---|
| L1 | 视觉快照 | HTML + CSS + 资产，无 JS | 像（默认态像素级） | ✅ 已达成（口径待修） |
| L2 | 可交互镜像 | 原 JS + 本地资产 + 回源 | 能点、能用（依赖原站） | ⚠️ POC |
| L3 | 可部署镜像 | L2 + HAR 回放 + 代理/Worker + 一键部署 | 断原站也能跑核心路径 | ❌ 未做 |
| L4 | 可维护重建 | 组件/设计 token/页面代码重写 | 自有代码、可长期迭代 | ❌ 未做 |

**建议对外只说 L1/L2 已达成、L3 在路线图、L4 是增值方向**；不要用单一"100%"承诺，改为"四张成绩单 + 明确边界"。

### 4.2 捕获层（capture v2）

- Playwright 上下文开启 `recordHar`；`page.on('response')` 全量归档；
- 记录：document、JS/CSS、字体、图片（含 picture/source/srcset 全候选）、媒体、iframe、manifest、SVG sprite、XHR/fetch、WebSocket 帧、重定向链、cookie/localStorage/sessionStorage/IndexedDB（可选）；
- 环境确定性：统一 UA/时区/语言/视口；冻结时钟与 `Math.random`（可复现）；处理 cookie banner、A/B 分桶、地理位置差异；对不稳定的页面输出"确定性报告"；
- 产物：`raw/network.har`、`assets/<sha256>`、`page.manifest.json`、`dom.html`、`cssom.css`、多帧截图、`gaps.json`（未捕获/不可捕获清单）；
- 增量：同一站点第二次捕获只拉新增/变更资源，哈希复用。

### 4.3 构建层（build v2）

- **snapshot（死镜像）**：parse5 重写 HTML、postcss 重写 CSS（`url()`/`@import`/`image-set()`/`@font-face`）、资源指向 CAS 相对路径；脚本剥离但输出"交互缺口清单"；
- **runtime（活镜像）**：保留原 JS；注入 Service Worker（请求拦截：本地 CAS 命中 → 本地；未命中 → 原站/代理；可选 HAR 回放）；`<base>` + SW 双保险处理根相对/动态 URL；SPA 路由 fallback 到快照或原站；
- **deploy（可部署）**：静态托管包 / Docker（Node 代理 + CAS）/ Edge Worker（Cloudflare 等）三种导出；
- **组件抽取（L4 增值）**：按 DOM 子树 + 计算样式 + 使用频率，抽取导航/Hero/定价卡/FAQ 为 HTML+CSS 片段或 React/Vue 组件，同时输出 design tokens（颜色/字体/间距/圆角/阴影）。

### 4.4 验证层（verify v2，替代单帧自证）

```
视觉：多视口 × 全页 × 多状态 → SSIM/pixelmatch → 差异区域聚类 → 可修/动态/不可复刻分类
结构：实时原站重渲染 vs 镜像 → DOM 路径配对 + computed style 差异（复用 style-probe）
功能：交互脚本双侧回放 → 每步断言 → 通过率（按钮/表单/菜单/Tab/搜索）
数据：情报字段实时对比 → 覆盖率
性能：Lighthouse（Performance/A11y/Best Practices/SEO）每页
SEO：规则引擎（见下一节）
```

评分建议：**分维度展示 + 各自权重透明**；综合分只在"站点健康度"内部使用，并且必须附"证据可下钻"。fixup 只允许在训练视口上优化，另设 holdout 视口与全页检查防止过拟合。

### 4.5 资产治理

- CAS：`sha256 → 文件`，全站共享；实测可把 apify 259.6MB 资产压到约 62MB（-76%）；
- 引用计数 + GC；资产账本（总量/唯一量/按类型/缺失/坏链/来源页面）；
- 资产浏览器：按站点/页面/类型/状态筛选，预览、下载、定位到引用它的页面；
- 站点群：Project 支持多域名，跨站资产去重、跨站 SEO/克隆对比。

## 5. SEO 审查与测试工具 v1（第二核心目标）

把现有 recon 的字段扩成独立产品线，不与克隆耦合：

### 5.1 采集信号（每页一份 `seo.json`）

- 抓取/索引：HTTP 状态、重定向链、canonical、meta robots、X-Robots-Tag、hreflang、robots.txt、sitemap 覆盖、noindex/nofollow、分页、参数规范；
- 内容：title、description、H1-H6 层级、正文词数、关键词密度、重复 title/description、薄内容、图片 alt、内链锚文本、外链；
- 结构化数据：JSON-LD/Microdata/RDFa 存在性与字段完整性（Product/FAQ/Breadcrumb/Organization/Article…）；
- 性能体验：LCP/CLS/INP/TBT（Lighthouse 或 PSI）、资源体积、图片格式/尺寸、懒加载、渲染阻塞；
- 移动/国际化/安全：viewport、响应式断点、lang、hreflang 互指、HTTPS、混合内容；
- 站点级：孤儿页（入链为 0）、点击深度、链接图、重复内容聚类、sitemap vs 实际抓取差异。

### 5.2 规则与报告

- 规则引擎：每条规则有 `id / 类别 / severity / 触发条件 / 证据 / 修复建议 / 参考链接 / 文档`；先做 40-60 条高价值规则，后续可插 Lighthouse/axe/schema-validator；
- 每页分数 + 站点加权分 + 按类别分；问题列表可排序筛选、可导出 CSV/Excel/JSON；
- 报告：HTML（内部查看）+ Excel（给运营/产品）+ JSON（给 CI/API）；每条问题附证据（截图/DOM 片段/请求/字段值）；
- **竞品对标矩阵**（与克隆/情报打通）：自有站 vs N 个竞品，按页面类型聚合 title 长度/H1/结构化数据/内容量/内链深度/性能分。

### 5.3 SEO 测试（回归与监控）

- 快照基线 + 每次爬取 diff：title/meta/canonical/robots/hreflang/JSON-LD/状态码/链接变化；
- CI Gate：PR 触发的目标页审计，规则回归即失败（阈值可配）；
- 定时监控：每日/每周爬取，变更告警（飞书/企微/邮件），趋势曲线；
- 与克隆共享缓存/限速/合规层，避免重复造爬虫。

## 6. 控制台 UX 重设计（面向"每一位同事"）

### 6.1 信息架构：从"星图即全部"到"工作台 + 探索视图"

```
Heimdall 工作台
├─ 总览 Dashboard     进行中任务 / 最近站点 / 质检告警 / 快捷入口 / 使用引导
├─ 站点 Sites         表格或卡片：域名、页面数、已克隆、平均视觉分、SEO 分、最近更新
├─ 页面 Pages         表格：URL、标题、类型、状态、视觉分、交互分、SEO 分、大小、最后更新
│                      支持搜索、筛选、排序、批量选择、批量克隆/审计/导出
├─ 任务 Jobs          队列：排队/运行/成功/失败、进度、日志、取消、重试、耗时
├─ 报告 Reports       克隆质检 / SEO / 原站变更 / 跨站对比，可按站点与时间筛选
├─ 资产 Assets        CAS 浏览器：站点/页面/类型/状态筛选，预览、下载、引用定位
├─ 星图 Atlas         3D 探索视图（保留品牌亮点，但不再是唯一入口）
└─ 设置 Settings      引擎、LLM、并发、数据目录、合规开关、导出、主题与语言
```

页面详情抽屉：概览 / 质检（视觉·交互）/ SEO / 资产 / 情报 / 日志 / 版本历史。

### 6.2 交互原则

- **首启引导**：3 步向导（输入 URL → 选择范围与模式 → 开始），空状态给示例站点与预置产物；
- **术语中文化 + 术语表**：死镜像 → 静态镜像（只读）、活镜像 → 可交互镜像、锻造 → 克隆、情报 → 分析报告；界面中英混排要统一（现在是 pages/edges/OBSERVATORY/FIDELITY VERDICT 混中文）；
- **可观测性**：每个数字可点击下钻到证据（分数 → diff 图 → 差异区域 → 元素路径 → 原/克隆属性）；任务有实时日志；
- **错误可行动**：错误提示给"原因 + 建议动作 + 重试按钮"，而不是一串异常；
- **批量心智**：选择页面 → 队列 → 任务中心统一看结果，不依赖当前打开的详情；
- **快捷键与命令面板**（⌘/Ctrl-K）：搜索页面、发起任务、跳转站点；
- **无障碍**：正文 ≥14px、辅助文字 ≥12px（当前大量 10-11px）、对比度、键盘可达、reduced-motion、焦点可见。

### 6.3 视觉方向：保留"深空观测站"，但降噪、增信

- 保留：深渊底、青色=侦察、琥珀=进行中、紫色=AI 参与、细线仪器框；
- 收敛：发光只用于状态语义，不做装饰性霓虹；提高文字对比与字号；统一 4/8px 间距网格；卡片层级用底色与描边而非更多边框；
- 重做：HUD 数字必须与数据源一致（现在 368 vs 1544）；档案卡片墙支持筛选/搜索/排序，深色页面缩略图加浅色描边或自动提亮，避免 19/60 张"黑卡"；
- 明确双主题：深色为默认，浅色要达到同等可读性（当前仅换 token，3D/节点配色仍是硬编码）。

### 6.4 组件化重构（Atlas.vue 680 行 → 组件树）

```
AppShell（导航 + 顶栏 + 命令面板 + 通知）
├─ DashboardView
├─ SitesView / SiteDetailView
├─ PagesView（虚拟表格 + 筛选器 + 批量操作条）
├─ JobsView（任务表 + 日志抽屉）
├─ ReportsView
├─ AssetsView
├─ AtlasView（Graph3D 保留）
└─ SettingsView
共用：TaskStore（Pinia）+ API 客户端（统一 SSE 重连/错误）+ 模型类型（TS）
```

技术建议：Vue 3 + Pinia + Vue Router + TypeScript；图表/表格用成熟库（TanStack Table）；3D 星图按需懒加载（首屏不为它付代价）；状态从"组件内 refs"迁到 store。
