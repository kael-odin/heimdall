# Heimdall 路线图

更新：2026-11-28。本项目已剥离比赛命题方向（项目验收工作台与无参照物 QA 巡检），全面聚焦于**通用网站克隆、多视口还原度验证、AI 可维护代码重建与独立离线交付**。2026-10-13 前的逐项历史在 [归档路线图](archive/ROADMAP-through-2026-10-13.md)。

## 主目标：独立站点克隆与高保真重建

目标是持续提高可克隆站点的覆盖率，并使导出包在声明的范围内真正脱离原站运行。每个包按 [产品定义](../PRD.md) 标注可查看快照、可离线浏览、可离线交互或完整业务替代等级；覆盖率、失败原因和未测范围与等级一起交付。

### 1. 真实站点克隆与离线门禁待办

1. **无限滚动与懒加载页的还原度**：滚动后页高一直增长的页面，验证器需支持两侧一致的有界状态（例如固定加载 N 屏）再比较，而不是放宽收敛判据。
2. **从已批准契约到可运行后端**：将 `read-data-plan.json` 批准的公开只读查询与 B3 后端脚手架、`live-verify` 断网验收进一步打通。
3. **大站 sitemap 分层抽样**：10,000 URL 上限触发后按 sitemap 索引分层抽样，改善超大站点的页面类型代表性。
4. **真实离线门禁**：在候选包中启动独立服务，用浏览器加载每个声明的页面并阻断所有外联；动态请求、脚本报错、本地 HTTP 失败和未测页都进入 `health.json`，未通过不得发布为离线可用。
5. **页面状态与依赖图**：从 URL 图扩展到 URL、视口、会话与操作后的状态；记录每个状态实际使用的脚本、样式、媒体、API 和跨域资源，支持有界的点击/输入/滚动探索，并明确未探索的分支。

### 2. AI 重建与后端行为克隆待办（吸收自 REA 与 craft-anything）

已落地的两项：
- **内容缺口检测**：修复包（Fix Packet）点名参考页里有文字而候选页找不到的元素。
- **未批准/未证明原因显式化**：契约的 `api-capture-not-approved` 与验证的 `unproven` 给出明确放行或补证命令。

下一步待办：
1. **列表查询角色学习**：从多个样本判断 `page / limit / sort / filter` 各自的角色，让回放适配器能回答同一数据集里已捕获数据的组合查询；没有证据的数据仍不编造。
2. **写后读回确认**：写操作只有在随后的读取证实了效果时才进入可回放范围，否则带原因扣下，并提示该补录什么。
3. **源站序列差分对照**：用重新录制的探针序列对照候选后端，按自然键重映射 ID、时间字段只比格式。
4. **施工方未知项账本**：让分段重建代理把没弄清的交互或状态问题记入 `.heimdall/` 账本，附上证据后关闭。
5. **地标结构相似度**：按 `header / nav / main / footer` / 列表 / 表单的骨架比对，补充在像素与文字相似度之外。
