## 1. 规模（最大的一块）

当前默认并发 2、侦察有页数上限，**跑不动十万页的站**。定位是几百页量级的竞品站。

- [ ] **并发可配**：现在写死 2，应该由站点配方给（大站给高并发，小站不必）
- [ ] **增量重克隆**：只重跑变化的页。现在 `queue` 有断点续跑（跳过已完成的），
      但没有"站点改版后只重跑变了的那几页"——需要先有内容指纹比对
- [ ] **单页超时熔断**：一页卡住不该拖垮整批

**为什么排在前面**：这三项决定"能不能用来做真活儿"。现在几页到几十页好用，
上百页就开始难受。

---

## 2. 审计深度（对标一流 SEO 工具的部分）

已有 56 条规则 / 六分类，且能识别 JS 渲染依赖与 hreflang 问题。缺的是：

- [ ] **分页 / 分面导航处理**：电商站高频问题，目前完全没覆盖
- [ ] **真实用户指标（CrUX field data）**：我们量的都是 lab 数据（Playwright）
- [ ] **历史趋势**：已有基线与变更监控，但没有随时间的分数走势曲线
- [ ] 结构化数据深度校验：现在只判断 JSON-LD 能否解析 + 类型是否存在，
      不做必填字段与类型匹配校验

**明确不做**：外链分析、关键词研究、排名追踪 —— 那是数据生意，需要买数据源。
我们的定位是"站内技术审计 + 可核验的复刻"，不宣称对标 Semrush。

## 3. 保真度（"更精细"的方向）

- [ ] **画布之外还有没有同类盲区**：canvas 已修（捕获阶段光栅化）。
      已排查过视频（正常，文件已本地化）与 iframe（外站嵌入，固有边界）。
      尚未系统排查：WebGL 画布（`toDataURL` 需要 `preserveDrawingBuffer`）、
      CSS `@font-face` 可变字体轴、`<video>` 的 poster、
      **闭包在 shadow DOM 里的样式**（现在只处理了 light DOM）
- [ ] **动效的可复刻度**：现在动效要么抓一帧、要么丢失。能否对常见类型
      （轮播、打字机、滚动触发）做"初始态 + 终态"双帧捕获？
      这会让 `dynamicShare` 那个缺口变小

## 4. 工程

## 判断依据

排优先级时问三个问题：

1. **它挡住真实使用吗？**（规模 → 挡）
2. **它会让结论变得不可信吗？**（保真度盲区 → 会；报告口径错 → 会）
3. **演示时讲得清价值吗？**（审计深度 → 讲得清；i18n → 讲不清）

三个都是否的，不做。
