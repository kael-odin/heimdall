### 本轮最大发现：data URI 内嵌的 `url()` 被当成外部引用

`url()` 的正则扫描不区分"顶层引用"与"data URI 内容的 `url(...)`"。于是：
`url("data:image/svg+xml,…<g mask='url(%23f)'/>…")` 里的 `%23f` 被当成外部引用 →
去原站抓 `https://host/%23f`（SPA 兜底 200 HTML）→ 落盘成 `refNNN.html` →
**再把 data URI 内的 mask 引用改写掉**，静默破坏内联 SVG 图标。
vitest.dev 实测 34 处中招；修好后 refs 从 53 → 26，`linked-*.bin` 里的 HTML 假资产 27 → 0。

## 3. 缺陷清单（分级 · 有证据）

### P0 —— 阻断"别人拿去用"

**P0-1　`heimdall forge <url>` 在没有引擎时会失败**
- `core/src/pipeline.mjs:38`：`CLONE_URL = ${SELF_URL}/static/${host}/pages/${NAME}/clone/index.html`，`shot_clone.mjs` 必须 `goto` 这个地址。
- 后果：`pnpm -C core cli forge https://x.com` 走到第 3 阶段（渲染校准）就报错退出。对"工具交给别人、一条命令克隆一个站"是硬阻塞。
- 修法：`shot_clone` 在 URL 为 `file://` 时可直接 `goto`；`pipeline` 在引擎不可达时回退为 `file://` + 绝对路径（我实测克隆页用 `file://` 打开 **0 失败请求**，完全可行）。

**P0-2　第三方大模型无法在控制台配置**（你明确提出的需求）
- `core/src/env.mjs:15`：`getEnv()` 结果**模块级缓存**；`core/src/llm.mjs:24`：`const ENV = getEnv()` 在**模块加载时固化**。
- `core/src/engine-server.mjs:236,240`：只有 `GET /api/llm/status`（只读）和 `POST /api/llm/test`（测当前 `.env` 的配置）。
- 控制台 `Atlas.vue` 设置页原文：*"模型配置：编辑 `core/.env` 的 … 改完重启引擎生效"* —— 这跟"用户能直接在控制台配置"差得远。
- 修法（建议）：
  1. 新增 `core/src/settings.mjs`：读写 `core/.env`（或独立 `core/settings.json`），**Key 单独存储、接口永不回显**（只回 `hasKey: true` + 末 4 位）；
  2. 引擎新增 `GET/PUT /api/settings/llm`，`PUT` 后**热重载**（把 `llmConfig()` 从"模块常量"改成"每次读设置"，并清 `getEnv()` 缓存）；
  3. `POST /api/llm/test` 支持传**草稿配置**（不落盘就能先测通再保存）—— 这是最关键的用户体验，避免"存错了要改文件回滚"；
  4. 控制台设置页做成一等公民：预设模板（OpenAI / Anthropic / DeepSeek / OpenRouter / 自建中转）+ 协议自动探测 + 连接测试 + "设为快速模型"。

**P0-3　默认值写死 apify / thordata（14 处）**
- `crawler/recon.mjs:15`、`capture.mjs:20`、`build_live.mjs:19`、`queue.mjs:15`、`index-page.mjs:14`、`linker.mjs:19`、`fullshot.mjs:15`、`shot_clone.mjs:6`、`differ/diff.mjs:25`、`domdiff.mjs:81`、`fixup.mjs:25`、`harvest/harvest.mjs:145`、`xlsx.mjs:17`、`deliver.mjs:17`、`console/src/Atlas.vue:20`（`host = ref('apify.com')`）、`Atlas.vue:950`（`fetch('/apify.com/recon/atlas.json')` 兜底）。
- 后果：新用户第一次跑，任何参数漏填都会静默地作用在 apify 上；控制台首屏默认就是 apify。
- 修法：默认值全部改为**必填校验**（缺失→打印用法并退出，不猜）；控制台首屏改为"站点列表 / 新建站点"。

**P0-4　`build_live.mjs:81` 里有一行按站点名分支的运行时逻辑**
```js
var CONSERVATIVE = H.indexOf('/lm/apify') === 0;   // apify：chunk 对无限递归 stub 挂死 → 用保守版/不 stub
```

### P1 —— 影响保真与通用性

**P1-1　CSS `url()` 的解析基准是错的（靠适配器补丁兜住）**
- `core/src/crawler/build_clone.mjs:49`：`abs = new URL(ref, origin)` —— 以**页面 origin** 为基准，但 CSS 规范要求以**样式表自身 URL** 为基准。
- 实测证据（tailwindcss.com）：
  | 解析方式 | 结果 |
  |---|---|
  | `https://tailwindcss.com/media/InterVariable-*.woff2`（当前实现） | **404** |
  | `https://tailwindcss.com/_next/static/media/InterVariable-*.woff2`（正确基准） | **200, font/woff2** |
- 今天没出事的两个原因（都是运气，不是设计）：① `adapters/index.mjs:26` 有一条 nextjs 专属的 `/media/ → /_next/static/media/` 重写；② 字体被 DOM 的 `<link rel=preload as=font>` 带进捕获清单，`localizeCss` 的 basename 兜底找到了。
- 失守场景：站点用 `../fonts/xxx.woff2` 且字体**未被 DOM preload 引用** → 静默掉字体（正是 HANDOFF §8.1 修过的那类问题，只修了症状没修根因）。
- 修法：`cssom-refs.json` 里**已经记了 `sheets[].href`** —— 按 sheet 分组解析：`resolveCssRef(ref, sheetHref, origin)`，候选链 = [sheet 基准, origin 基准, 适配器候选]，全部失败才计入 gaps 并**写进报告**（现在 `failed` 只打日志，用户看不见）。

**P1-2　CSS 里下载的资产扩展名靠猜，落成 `.bin`**
- `core/src/crawler/build_clone.mjs:50`：`extOf('', abs)` —— content-type 传空串，只能靠 URL 后缀猜；带查询串的 CDN 图（`?w=1000&q=80`）一律落成 `refNNN.bin`。
- 实测：探针克隆里 `clone/assets/ref003.bin` 前 4 字节 `ff d8 ff e0` = **JPEG**。
- **诚实结论**：我实测了影响 —— Chrome 下 `<img>` 与 CSS `background-image` **都能嗅探渲染**（两者像素非白数一致 50/50），所以**不是保真事故**。风险在于：跨浏览器未验证、直接打开会触发下载、导出包里 6 个 JPEG 叫 `.bin` 语义脏。
- 修法：用 `fetch` 响应的 `Content-Type` 定扩展名 + magic bytes 兜底；`engine-server.mjs:50` 的 MIME 表补 `.bin/.mp4/.webm/.ogg/.woff/.ttf/.otf/.map`。

**P1-3　`engine-server.mjs` 的 `/static` 是 `readFileSync` 全量入内存**
- `engine-server.mjs:466/642/847/865` 全是 `readFileSync(file)`；MIME 表只有 15 项。
- 后果：383MB 交付包 / 70MB 合并 HAR 走这条路会吃满内存；`.mp4` 等类型会以 `octet-stream` 下发且不支持 Range（视频没法拖动）。
- 修法：`createReadStream` + `Content-Length` + `Range`；MIME 用 `mime-types` 之类的表或自带扩展。

**P1-4　爬取不遵守 robots.txt（文档红线 vs 代码事实）**
- `recon.mjs` / `capture.mjs` 里**没有任何 robots.txt 读取**（只有 `seo/audit.mjs` 为了分析而抓它）。BFS 并发 3、无 crawl-delay。
- 后果：`HANDOFF.md` §7 写的红线（"严格反爬站白名单拒收"）在代码里没有落点。
- 修法：`recon`/`capture` 开工前取 `/robots.txt`，`Disallow` 命中的路径不入队；`Crawl-delay` 转成节流；被禁列表写进 `atlas.json.failures` 并在控制台显示。

**P1-5　`recon.mjs:46` 的页面分类是纯英文路径正则**
- `classify()` 只认 `pricing|blog|docs|...`。中文站（`/价格`、`/关于我们`、`/帮助中心`）全部落 `generic`。
- 后果：`queue.mjs` 靠 `type` 排除 auth/legal、星图图例靠 `type` 上色 —— 中文站直接退化成一张灰图。
- 修法：正则补中文/日文关键词；`type` 增加一档"由页面 DOM 特征推断"（`<form type=password>` → auth，含价格数字+表格 → pricing）。

**P1-6　删除站点不回收 CAS 资产**
- 控制台 `deleteSite` 的文案自己写着"CAS 资产保留"。`assets-cas` 已经 775MB / 150,444 文件。
- 后果：删掉 10 个站，磁盘只涨不跌。
- 修法：删站时跑一次"引用计数"（扫其余 host 的 `asset-map.json` / clone 引用），无引用即从 CAS 摘除；控制台给出"将释放 X MB"预览。

| L1 死镜像 | 静态移植，离线可开，像素级 | **A**（apify 61/61 A，探针站 99.92%） |
| L2 可交互 | 保留脚本，功能可用 | **B-**（依赖活镜像；死镜像剥脚本，交互全丢） |
| L3 可部署 | 自包含包，drop-in 部署 | **A-**（HAR 回放 + 零依赖 serve + Docker，apify 未覆盖 0） |
| L4 可维护 | 可读代码 / 可改 / 可增量同步 | **D**（产物是 CSSOM 巨型 CSS + 剥脚本的 DOM） |

**"别人能一次跑通"缺的东西**

1. **一条命令、无前置依赖** → 修 P0-1（`forge` 不依赖引擎）
2. **不写死站点** → 修 P0-3（默认值校验）
3. **换站不用改代码** → 见下方「站点配方」（解决 P0-4）
4. **首次体验** → 内置一个 demo 站点产物 + 首次向导（§7）
5. **失败可解释** → 现在失败只体现在任务中心的 `error` 字段；需要"为什么这页只有 72%：3 个缺口 / 2 个未捕获字体 / 响应式变体缺失"的下钻

**核心架构建议：站点配方（Site Recipe）—— 把 host 硬编码挤出去**

现在所有站点特化都散在三处：`adapters/index.mjs` 的代码分支、`build_live.mjs:81` 的字符串判断、以及开发者的记忆里。建议改成数据驱动：

```
core/sites/<host>.json          # 站点配方（可提交、可分享、可被工具生成）
{
  "host": "apify.com",
  "adapter": "nextjs",                      // 或 "auto"
  "live":   { "stubStrategy": "conservative", "thirdPartyAllow": ["..."], "replayApi": true },
  "capture":{ "waitUntil": "domcontentloaded", "consentSelectors": ["#onetrust-banner-sdk"], "scrollSweep": true },
  "clone":  { "stripScripts": true, "freeze": ["carousel"], "keepVariants": [375,768] },
  "verify": { "viewports": [375,768,1440], "threshold": 0.97 },
  "notes": "chunk 对无限递归 stub 挂死，用保守版"
}
```

- 好处：`adapters/` 里只留**通用能力**（CSSOM 采集、路径基准、资源嗅探），站点差异全在 JSON；用户克隆新站时，工具**自动生成**一份配方（把本次成功用到的参数固化），下次一键复现；配方可以互相分享（"这是某站的克隆配方"）。
- 这也顺手解决 `adapters/index.mjs:26` 那条特例重写：它本质是"这个站点的 CSS 引用基准偏移"，应该是一条配方规则，而不是 if 分支。

### 4.2 目标二：SEO 优化 / 审查 / **测试** 工具

现状：**审查（audit）很扎实，测试（test）几乎是空的。**

- ✅ 已有：40+ 规则 / 6 分类 / 严重度 / 证据 / 修复建议 / HTML+CSV+JSON / 跨站对标矩阵 / 变更监控（两次采样去噪）/ LCP 等性能信号 / 与克隆共用浏览器采集。
- ❌ 缺"测试"应有的四件事：
  1. **基线门禁**：`seo-baseline.json` + `--fail-on-regression`（CI 用）。现在 `watch --fail-on-change` 只覆盖元数据变化，不覆盖"分数掉线"。
  2. **页面类型维度的阈值**：定价页和法务页不该用同一套标准（现在 `site.noindexIntent` 是个补丁式豁免）。
  3. **与 Lighthouse 的可比性**：现在是自研信号，无法跟外部数字对齐；建议接入 Lighthouse（或至少输出可对照的口径说明）。
  4. **可执行清单**：报告是"问题列表"，不是"排好序的待办"（按 影响 × 修复成本 排序 + 一键导出 Issue/CSV）。
- 建议再补两块高价值内容：**内容缺口分析**（本站 vs 竞品：他们有而我没有的主题/关键词页）与**结构化数据校验**（Schema.org 合法性 + 富结果资格）。

## 5. 控制台重设计方案

### 5.1 问题诊断

| 问题 | 证据 |
|---|---|
| 单体 | `Atlas.vue` **1819 行**，5 个 `v-if` 视图 + 详情坞 + 全部样式挤在一个文件 |
| IA 仍是"星图优先" | 底部导航切 5 个视图，但星图占满全屏，其余是**浮在上面的面板**（`section.work-view` 覆盖在 canvas 上） |
| 状态无中心 | 60+ 个 `ref` 全在组件内；任务状态用 `tasks` 数组 + `jobHistory` 两份数据 |
| 无路由 | `view = ref('atlas')` 手动切；刷新即回星图，无法分享"某站某页"的链接 |
| 无类型 | `types.js` 24 行常量；API 返回结构全靠约定 |
| 视觉密度 | 正文 10–11px 多；`--abyss #0B0B10` 上的 `--text-faint #64748B` 对比不足 |

### 5.2 目标 IA（工作台，而非演示台）

```
AppShell（顶栏：站点切换器 · 全局搜索 ⌘K · 任务铃 · 主题 · 语言）
├─ 概览 Dashboard    进行中任务 / 站点卡片墙 / 质检告警 / 快捷入口 / 首启引导
├─ 站点 Sites        卡片或表：域名 · 页面数 · 已克隆 · 平均视觉分 · SEO 分 · 磁盘占用 · 最近更新
│                    （新增：磁盘占用 + "释放空间"——直接对应 §3 P1-6）
├─ 页面 Pages        虚拟滚动表：URL/标题/类型/状态/视觉分/交互分/SEO/体积/更新；批量操作条
├─ 资产 Assets       CAS 浏览器（已有雏形，独立成页）：站点/页面/类型/体积/孤儿/去重账本
├─ 任务 Jobs         队列表 + 实时日志抽屉 + 取消/重试 + 进度与 ETA
├─ 报告 Reports      克隆质检 / SEO / 活镜像体检 / 变更监控 / 跨站对标 / 设计 token / 组件
├─ 星图 Atlas        3D 探索视图（保留品牌亮点，**但不再是默认首页**）
└─ 设置 Settings     模型服务（含控制台配置！）/ 引擎 / 并发 / 数据目录 / 合规开关 / 主题语言
```

配套：**页面详情抽屉** 概览 / 质检（视觉·交互）/ SEO / 资产 / 情报 / 日志 / 版本历史。

### 5.3 技术重构

- Vue 3 + **Vue Router**（每视图一个路由，可分享链接）+ **Pinia**（taskStore / siteStore / settingsStore）
- **TypeScript**：至少给 API 返回结构建模（`core` 侧的 `score.json` / `verify-summary.json` / `atlas.json` 都是稳定契约）
- 组件树：`AppShell` / `TaskCenter` / `SiteSwitcher` / `PageTable` / `QualityPanel` / `AssetExplorer` / `ReportGrid` / `AtlasView`(懒加载 3D)
- 统一 API 客户端：SSE 自动重连、错误归一化、请求去重（解决 P2-3 的 N 次请求）
- 3D 星图按需 lazy load：首屏不为它付费

### 5.4 视觉方向（两条路，需你选）

**路线 A · 渐进重构（推荐）**：保留"深空观测站"HUD 语言（深渊底、1px 细线仪器框、青色=侦察、琥珀=进行中、紫色=AI），只做三件事 —— ① IA 从星图优先改工作台优先；② 降噪提对比（发光只给状态语义、字号抬到 14px 起、统一 4/8px 网格）；③ 组件化。风险低，品牌辨识度不丢。

**路线 B · 彻底重做**：用 `impeccable` / `ui-ux-pro-max` 重新定方向（例如"工程控制台"气质：更高信息密度但更克制的中性色 + 单一强调色），星图作为独立"探索模式"。视觉上限更高，但要接受重做成本与风格断裂。

两条路我都能做，且都可以先出关键页面的可视稿再定。

## 9. 高价值想法清单（按投入产出排序）

1. **站点配方**（§4.1）—— 一次调参，永久复现，可分享。**这是"能克隆任何站"的正解。**

8. **镜像水印 + noindex + 内网默认**：合规护栏产品化（报告页已有 noindex，克隆页没有）。
9. **设计系统导出**：`tokens` 已有 → 输出 Tailwind config / CSS 变量 / Figma 变量。
