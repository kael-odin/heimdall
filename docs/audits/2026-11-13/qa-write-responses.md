# 写入接口应答实测

2026-11-13。QA 的页面动作可在既有策略明确允许后执行写请求，原响应声明却只接受 GET/POST，无法核对 PUT/PATCH/DELETE 的原始应答。本轮只扩展现有声明，不增加网络动作、依赖或运行模块，不改冻结验收器与 SEO/GEO 口径。

## 行为与边界

- `responses[].method` 接受 GET、POST、PUT、PATCH、DELETE；主框架、精确来源与路径、状态和 JSON 标量检查复用同一观察器。方法仍区分大小写，其他方法被拒绝；只有公开 GET 可声明查询。
- CLI 与统一注册表的 HTTP/MCP 输入同步更新。仅声明响应不会授权实际写入；站点默认阻断，PUT/PATCH/DELETE 的页面动作仍需要事先按被测环境配置 `writes: "allow"`。已有精确 POST 例外保持原语义。
- 每个自然请求只观察一次，不重放；同一路径的不同方法分别匹配。重复请求仍未完成。JSON 仍限单次读取、256 KiB、未压缩、可核实大小，不输出实际值或响应正文。
- 接口不符返回 `qa_incomplete` / 退出码 3，继续要求人工结合契约核实；页面违约单独记录，不把接口待核实自动改成产品缺陷。

## 真实参考与受控故障

复用固定版本 `json-server@1.0.0-beta.15` 的实际本机服务，未复制它的实现。独立 HTTP 状态与字段保留预期来自此前冻结的 `training.json`；新载荷是明确声明的本地页面要求。版本、包、锁文件和训练样本哈希记在 `oracle.json`，前后未变。每个场景使用独立、可丢弃的种子数据库。

浏览器真实点击后依次 POST 创建、PATCH 更新资源 2、PUT 替换资源 1、DELETE 资源 1、GET 读回资源 2。页面壳为受控案例，最终展示标题和原浏览量；这不是网站克隆或视觉还原度验收。网关只接受这五个精确方法/路径组合及固定写载荷，所有写入只作用于自有回环进程。

| 场景 | 响应声明 | CI / 退出码 | 页面业务 API 请求 |
|---|---|---|---:|
| 健康 | 五个原始响应 | passed / 0，全部 matched | 5 |
| 只验页面，PUT 应答标题错误 | 无响应声明 | passed / 0，页面未暴露错误 | 5 |
| PATCH 应答状态改为 500 | 五个原始响应 | incomplete / 3，PATCH http-mismatch | 5 |
| PUT 应答标题错误 | 五个原始响应 | incomplete / 3，PUT json-mismatch，第 1 字段 | 5 |
| DELETE 应答省略 views | 五个原始响应 | incomplete / 3，DELETE field-missing，第 2 字段 | 5 |
| 默认阻断写入 | 五个声明仍存在 | incomplete / 3，首个请求被阻断，其余未发出 | 0 |
| 恢复 | 五个原始响应 | passed / 0，全部 matched | 5 |

七场景的独立页面断言均通过；三个应答故障只在网关修改返回状态/字段，真实后端状态保持原逻辑。每个获准旅程严格只有五条业务请求，观察器未增加请求。只验页面对照使用当前实现的兼容输入，不是旧源码运行；旧声明拒绝 PUT 的红灯回归单独保留。这些是人为注入故障，不是发现 JSON Server 的公共缺陷，也不是七个独立项目。

请求数仅指页面触发并到达网关的业务 API，不含页面 HTML、favicon 或参考进程启动时的 GET 就绪探测；默认阻断没有放出页面写请求。
