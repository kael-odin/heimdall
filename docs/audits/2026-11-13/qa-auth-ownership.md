# 认证与资源归属实测

2026-11-13。用固定版本 `json-server@0.17.4`、`json-server-auth@2.1.0` 的真实本机服务检验 QA 的认证与权限证据，并修复已知 Bearer 请求头在页面输出裸令牌时的脱敏遗漏。与此前 beta.15 写接口案例是不同参考环境；只增加共享函数的处理分支和现有测试，不增加运行模块、依赖或测试文件。

## 独立基线

参考服务按包文档安装中间件，以 `users: 600, posts: 600` 重写权限路径。两账号通过真实 `/register` 签发 JWT；种子资源 1、2 分别归属账号 1、2。随机密码和令牌只用于自有回环环境，不写入配置或 Git。参考包、锁文件、基线和源码均记录 SHA-256。

冻结前先直接发 HTTP 请求：匿名读取资源 1 返回 401；主人读各自资源返回 200；账号 2 读资源 1 返回 403；无效令牌返回 401；正确登录返回 200，错误密码返回 400。集合 `/posts` 实际返回两个账号的数据，因此没有把集合自动按账号过滤作为通过条件，也没有据此宣称发现公共项目漏洞。

## 十个场景的实际结果

每次 QA 都启动真实浏览器，通过环境变量引用登录头，页面按钮自然请求本机网关。网关转发到实际参考服务；越权对照在网关把账号 2 的令牌换成主人令牌，字段对照只修改返回的归属字段。页面壳刻意继续显示声明文案，验证仅看页面会漏掉的情况。这些是受控故障，页面壳不是克隆站点。

| 场景 | 原始响应核对 | CI / 退出码 | 页面业务请求 |
|---|---|---|---:|
| 匿名拒绝 | 401 matched | passed / 0 | 1 |
| 主人 1 访问 | 200，id/userId matched | passed / 0 | 1 |
| 跨账号拒绝 | 自有资源 200 + 他人资源 403 matched | passed / 0 | 2 |
| 主人 2 访问 | 200，id/userId matched | passed / 0 | 1 |
| 无效令牌拒绝 | 401 matched | passed / 0 | 1 |
| 只验页面的越权对照 | 不声明响应，漏掉实际 200 | passed / 0 | 2 |
| 越权响应 | 声明 403，实际 200，http-mismatch | incomplete / 3 | 2 |
| 归属字段被改错 | 200，第二字段 json-mismatch | incomplete / 3 | 1 |
| 恢复拒绝 | 自有资源 200 + 他人资源 403 matched | passed / 0 | 2 |
| 实际令牌脱敏 | 200 matched，标题/控制台文本已移除令牌 | passed / 0 | 1 |

十场景共 14 条页面业务请求，没有由观察器增加请求。每个场景的页面断言都通过；预期 401/403 没有产生登录环境失效。接口违约保持 `qa_incomplete`，没有自动升级为已确认产品缺陷。脱敏场景的两个跨来源探测没有收到 Authorization。

## 最小修复与验证

登录档原先只记住完整 `Bearer <token>`，共享 `scrubSecrets()` 只替换该原文。实际令牌在内存探测中证实“整头已移除、裸令牌未移除”。先用假令牌留下失败回归，再让该函数同时移除已知 Bearer 值中的裸令牌；保留至少 8 字符的门槛、其他方案原有行为和调用接口。`scrubValues()` 对嵌套键和值复用同一修复，因此页面标题、发现、运行元数据、文本和报告都受益。

- 工作区与登录测试 **22/22** 通过，覆盖大小写、空白分隔、重复出现、嵌套键/值、未知值与短片段边界。
- 原有浏览器产物脱敏测试 **1/1** 通过，改用 Bearer 登录头，继续核对 headers 与 storageState 两种档案。
- 实际签发令牌出现在页面标题和控制台后，十份工作区共 **100 个文本文件** 在落盘时对全部已签发密码/令牌扫描通过；页面可见正文和截图没有放置真实令牌。此数包含配置与报告，不是 100 个独立场景。
- 语法 **765 文件**、冻结验收 **14 文件** 检查通过。共享函数修改为 7 行，复用两个测试文件；SEO/GEO 口径、写策略与登录头来源隔离不变。

## 采集隐私复核与未知

八条真实 HTTP 观察也经过 HAR 与契约生成。`includeApiBodies: true` 按设计保留私有响应正文，原先仅扫描 JSON 序列化文本，漏掉了 base64 中的登录令牌。此处修正的是验收方法，未改变 HAR 的选项行为：原采集按原哈希隔离为私有材料，使用已有 `scrubPublicJsonValue()` 生成可分享副本，并对解码后的正文扫描。原 `baseline.json` 的 `sanitizedCredentialScanPassed` 只代表原文搜索，不能作为正文安全证明；更正与原路径映射见 `capture-privacy-correction.json`。

公开副本保留 Bearer 机制和响应状态观察，契约仍包含 `auth-unknown`；没有从有限请求臆造完整权限规则。敏感字段删去后，采集契约不能用来推断资源归属，QA 的归属预期来自独立账号基线。

参考依赖、驱动、账号数据和逐场景报告都在 `D:/Github-Star/heimdall-evidence-archive/2026-11-13/qa-auth/`。正式结果是 `real-cases.json`；可分享采集/契约是 `public-capture.json`、`public-contract.json`，私有采集不应分发。初始集合过滤假设失败已如实记录，未把调试运行算成新增样本。

本轮是一个参考项目的十场景，不是十个网站。未补写或独立部署认证后端，未验证 OAuth、MFA、令牌刷新/过期、权限变化、完整集合权限、生产账号或全站覆盖。QA 文本脱敏不处理截图像素，也不能识别未知或变形凭据。三项持续目标保持进行中。
