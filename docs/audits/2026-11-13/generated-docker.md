# 生成包 Dockerfile 的真实构建与运行

2026-11-13。补验此前只在现有 Node 镜像中挂载运行的商品后端与 IANA 本地搜索包，实际使用各自生成的 Dockerfile 构建镜像。原始生成包和采集不覆盖，所有镜像、运行证据及检查脚本均在仓库外。

## 实测发现与修复

B3 后端服务直接运行时默认监听 `127.0.0.1`，Dockerfile 没有覆盖。旧镜像容器内健康接口返回 200，宿主机映射端口请求被重置；同一旧镜像仅增加 `HOST=0.0.0.0`，宿主机即可访问，排除把健康检查通过当成部署可达。

旧镜像也没有声明运行时状态目录和卷，生成服务默认把状态写到 `/app-data`。即使挂载 `/data`，服务仍不使用它。在服务状态目录写入一条受控缺口账本记录，再删除并替换容器，旧镜像恢复到 0 条。这里验证的是人工种入的账本持久化，不是商品写入或原站业务事务。

修复只到已有生成器：Dockerfile 设置 `HOST=0.0.0.0`、`HEIMDALL_RUNTIME_DATA_DIR=/data` 和 `VOLUME ["/data"]`，生成 README 与入门指南给出映射到宿主机回环地址、明确复用命名卷的命令。直接运行 Node 的默认监听不变。修复后的真实镜像默认映射端口返回 200，使用同一命名卷替换容器后仍读取到该条账本记录。

旧包不自动改写；应另选输出目录重新生成、核对差异，再纳入已有业务代码。

## 两个真实生成包的镜像验收

本轮先取得官方 `node:22-alpine`，实际运行版本为 **Node 22.23.5**，构建解析的基础镜像摘要为 `sha256:1314fb30ec37592d5845e5a160d522c0e680972aa534549940b8d73bde88481a`。随后三个 Dockerfile 构建均使用 `--pull=false --network=none`；这个构建参数限制构建步骤网络，不代表基础镜像最初的获取没有联网。

两个镜像均按自带默认命令启动，在 `--network none --read-only` 下运行，只有 `/tmp` 临时文件系统与 `/data` 命名卷。没有宿主机目录绑定，也没有挂载 Heimdall 源码或原采集工作区。容器检查确认只有回环网卡，外部探测请求失败；每包五个关键文件的镜像内 SHA-256 与构建输入一致。商品适配器字节未改，预期也未重新采集。

映射端口与容器替换检查使用普通 bridge；它只证明访问与状态保留。断外联证据来自另行运行的 `--network none` 容器，不能把两种网络模式混称为一次断网发布。

IANA 仍是原来的候选包，248 个未捕获链接继续阻断严格发布。本轮没有更新视觉分数、运行正式视觉门禁、验证 Google 搜索等价或补齐原站后端。商品仍是快照读取实现，没有认证、写入、状态机和实时同步的等价证明。
