# 有状态后端与动态资源路由实测

日期：2026-11-13。目标是把已有只读 API 重建推进到资源创建、读回、更新、删除与独立部署持久化。本次没有改变 SEO/GEO 评分口径，也没有修改冻结验收器。

## 独立参考与冻结方式

- 固定 npm 官方 `json-server@1.0.0-beta.15`，在仓库外安装，保留版本、完整性和锁文件；只读它的 README/帮助与实际 HTTP 行为，没有读取实现源码。所有写入只作用于自有回环进程和虚构种子数据。
- 先采集 11 次训练请求，经现有 HAR 脱敏与契约生成得到 7 条观察路由；AI 据此编写仅依赖 Node 标准库的适配器。资源 ID 从 POST 返回值绑定，不假定调用者提交的 ID 会保留。
- 在采集留出响应前冻结适配器源码与九个生成包文件。生成器会规范化 manifest JSON，因此源码模块按字节比较，manifest 先按语义比较，再冻结实际生成字节。
- 留出参考只采集一次，24 个 HTTP 检查点加一次重启；参考采集的 `passed` 为 null，不能算一次被测候选通过。ID 比较只归一资源顶层 ID 的因果身份，保留其他标量、嵌套字段、状态和 MIME 的实际差异。

## 本次实际修复

1. 原 manifest 拒绝 `/posts/{postId}`，B3 契约投影也会丢掉参数路由。复用 `adapter-runtime.mjs` 中的路径验证与匹配函数，贯通 runtime、B3 健康覆盖和独立生成服务。
2. 参数只占完整单段，方法逐项声明；保留保留路径、编码分隔符和非规范路径限制。重复参数名、嵌入或不平衡花括号被拒绝；会话初始化继续限定固定 POST 路径。
3. 严格导出原来只按固定请求路径计数，导致已执行动态路由仍被标为未测试。现按同源请求匹配声明路由；没调用的参数路由仍阻断。路由执行过只表示有样本，不代表业务等价或所有 ID 都正确。
4. 生成 README 与 Heimdall 技能补充 `context.dataDir`、返回 ID 读回、持久化验证和参数测试数据要求。默认检查不发写请求、不猜参数值，未完成不会变成通过。

留出检查包含未见标量、null 和嵌套创建数据；PATCH 浅合并与保留未修改字段；PUT 替换与省略字段移除；拒绝通过更新重指派 ID；删除后 404；缺失资源的 PATCH/PUT/DELETE；创建后列表、同卷重启后的资源与列表一致。随机 ID 不要求逐字相同，但后续请求必须使用各自实际返回的 ID。

Docker 使用实际生成文件构建，构建及运行均断网。HTTP 请求通过 `docker exec` 仅发送当前方法、路径与请求体，预期比较始终在宿主进行；替换容器复用同一卷。容器和状态卷已清理，镜像与证据留在仓库外。live 补验先通过真实严格导出流程，再迁移整个交付目录，以独立状态目录运行同一旅程；运行时仍离线。它验证跨封装一致性，不算新一轮盲测。

## Heimdall 自身 QA 的故障检出

从冻结包复制四份独立候选，健康原件保持不变。受控页面真实点击后仅发一次 PATCH 和一次 GET，网关只允许精确 `/posts/2` 和固定更新载荷；工作区为自有本机可写隔离数据，显式 `writes: allow`。没有把写操作伪装成 POST 查询白名单。QA 被动声明只核对 GET 读回，PATCH 的 200 另留真实请求证据，没有新增 PATCH 响应声明能力。

独立预期来自冻结参考的 `qa-readback`：标题为 Changed by QA，原浏览量为 20。关闭泛化检测、链接及视觉基线以隔离声明行为；这不构成整站或视觉验收。

| 候选 | QA CLI | GET 读回 | 页面检查 |
