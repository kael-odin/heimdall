# 候选 URL 与视口趋势隔离实测

2026-11-13。快速对比的候选键原先丢弃 URL 查询与片段，同一地址的不同实际视口也可能进入同一趋势队列。AI 在切换查询页面或客户端路由时，会收到“变差/变好/振荡”等不属于同一候选的反馈。本轮只修正历史匹配，不改像素分数、门槛、请求流程、输入格式或 SEO/GEO 方法。

## 共享逻辑与兼容边界

- URL 身份改用 `new URL(...).href` 的完整序列化结果，保留查询和片段。项目模式仍以目录与路由为身份。类型标记与字段采用 JSON 元组编码，避免沿用旧版丢失查询/片段的混合组；旧记录和原始运行目录保留，包括目录候选在内都从新键起算。
- 历史筛选继续要求同一参考 ID 与分段声明，增加实际参与比较的视口键集合一致，顺序不影响分组。未参与比较的视口不被补成有分数；该筛选不替代覆盖与正式门禁。
- 新组首条继续使用既有 `same` 和“第一次对比”，没有 `previousRunId`，不增加状态枚举、配置或 API 参数。查询参数顺序、不同编码与片段不另做语义归并，宁可重新起算，也不推断两个地址业务等价。
- CLI、HTTP、MCP 继续调用同一 `fastCompare`；只修改原运行文件和原 F1 测试文件，没有增加依赖、运行模块或测试文件。候选键只输出哈希，原有修复包仍记录完整候选地址，不承诺全部产物不含业务数据。

## 冻结 IANA 首页与受控路由

复制此前捕获的 IANA 首页到新隔离数据根，候选另放静态目录。自有回环网关只给页面附加一段受控前端路由：`view=shifted` 或 `#/shifted` 修改背景、文字颜色与标题字号，其余路由保持原样。源页面及资源来自真实捕获，路由机制由实验明确声明；不是 IANA 线上路由或线上缺陷。
