# 镜像参考缓存与还原度实测

2026-11-13。快速对比的分段简报和参考截图原先主要核对 `clone/index.html` 的修改时间。单独更新 CSS、图片、字体、脚本或视口变体时，旧参考可能继续命中，给出不符合当前镜像的高分。本轮复用普通验证器已有的内容哈希函数修复这条链路，不新增依赖、运行模块或测试文件，不改 14 个冻结验收文件、像素评分公式或 SEO/GEO 口径。

## 实际问题与行为

- 共享镜像身份复用从 `measurementIdentity` 提取的 `cloneInputSha256`，核对 manifest 与 clone 目录全部常规文件的内容。本地冻结参考没有 manifest 时将“缺失”显式计入哈希；普通验证器仍独立要求有效 HTTP 来源。clone 或内容身份无法核实时返回 `reference_missing`；分段计划、元素详情、outline 的计划缓存和参考截图均接受身份及拍摄条件检查，旧缓存按需重建。
- 参考 ID 绑定捕获时间、内容身份、拍摄条件、实际截图及遮罩哈希；只有同一参考 ID 的运行进入趋势对比，历史记录保留。恢复原输入及图片证据后可以回到原参考队列，不将不同参考下的分数解释为候选变好或变差。
- 参考 PNG、动态遮罩与元素索引按记录哈希核对，缺失、篡改或未登记的辅助文件不复用。重新拍摄先清除本视口的旧遮罩/索引，避免新截图继续使用旧动态遮罩。内容变化后不携带旧视口测量；输入未变时可保留其他已测视口的元数据。
- 分段、元素和参考测量完成前再次核对输入，变化时停止并要求重试；不提交混合输入的缓存元数据。项目初始化复制的文件不自动覆盖，使用方法见 [AI 接入指南](../../guide/06-ai-integration.md)。

这里采纳 Craft Anything README 所描述的“检查构建与原件，再按差异收敛”的流程；具体修复来自 Heimdall 的真实缓存失效证据，没有把对方 README 的能力陈述当作已验证实现。

## IANA 冻结页面与独立目录对照

使用此前捕获的 IANA 首页副本，仅复制 manifest 与 clone 到新的隔离数据根；候选再复制到独立静态目录，用回环 HTTP 提供服务。原有捕获目录保持只读，不重抓在线站点，不修改原正式包。参考与候选在同一浏览器流程、375 / 768 / 1440 三视口测量。

受控变化只在新副本的 CSS 中改变背景、文字颜色和标题字号；入口 HTML 的字节与修改时间保持不变。额外的实际浏览器检查确认当前镜像背景为 `rgb(41, 59, 102)`、标题字号为 `60px`；候选目录始终保留原样式。
