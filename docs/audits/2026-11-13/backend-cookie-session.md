## 真实参考与重建输入

参考为固定 npm 包 `cookie-session@2.1.1` 的实际 Node HTTP 服务。受控应用只提供 Alice/Bob 会话选择、当前账号、账号 1 的资源及退出；它是自有回环环境的会话实验，不是带密码的生产身份认证，也不是公共网站克隆。包、锁文件、参考包装器与训练记录都有 SHA-256。

先观察九步训练旅程和四种缺失/篡改 Cookie 的拒绝行为，再补写只用 Node 标准库的适配器。参考依赖只安装在仓库外；候选不加载该中间件、不借用参考密钥、不请求参考服务。签名 Cookie 值与算法是候选的实现细节，客户端按不透明凭据使用，不要求与参考 Cookie 互通。

HAR 与契约只保留脱敏观察。真实 Cookie 值只在进程内、浏览器及私有测试状态中使用；公开捕获另检查 base64 解码正文，不把编码当作脱敏。契约保留 `auth-unknown`，缺失的生产规则不补成“已观察”。

## 三个实际修复

1. **B3 丢失会话 Cookie。** 原生成服务用普通对象逐项写响应头，同名 `Set-Cookie` 覆盖前项。Windows Node 26 实测只余签名 Cookie，下一次请求变成匿名 401。live 运行时已有按数组转发的正确实现，本轮导出并在生成模板复用该函数，删去重复实现；`Expires` 中的逗号也原样保留，不按逗号拆 Cookie。
2. **204 退出响应被误判。** 真实中间件和补写版的浏览器退出均已返回匿名状态，Chromium 却在收到 204 后以 `canceled: true / net::ERR_ABORTED` 结束空体传输。现只在实际与声明都是 204、仅核对状态、非缓存、无 CORS/拦截信息时认可该 HTTP 事实。未收到状态、其他状态或取消原因、JSON 断言、缓存及拦截仍未完成；没有补发请求或取正文。
3. **匿名默认检查误导认证修复。** 原默认脚本不带 Cookie 访问已观察认证材料的读取：有时把 401 算已实现，有时因未观察该 401 建议修正响应码。现在保留未完成，不自动匿名探测，并产生 `authentication-verification` 任务，要求明确登录档与权限旅程，不为让匿名检查通过而放宽认证。实际正向验收仍由下述双账号旅程与浏览器检查承担。
