# 同一次响应的多字段联合验收

2026-11-13。针对「首条商品正确，但响应总数错误仍通过」这一声明覆盖缺口，扩展现有 QA 响应断言，不增加命令、工具、依赖或运行模块。

## 行为与兼容性

`responses[].json` 兼容原有 `{ path, equals }` 对象，也接受 1–20 项数组。路径必须互不重复，全部断言针对同一次观察到的响应；正文只读取和解析一次，不重发业务请求。保留每个路径 1–8 段、有限标量、字符串长度和 256 KiB 正文限制，并拒绝稀疏数组。

首个字段缺失或值不符时，机器结果增加从 0 开始的 `failedJsonIndex`，说明文字按第 1 项起显示。不输出响应正文、查询值或实际字段值。CLI、HTTP、MCP 与 QA CI 复用同一实现；单字段输入的规范化形状保持兼容。

接口不符仍返回 `qa_incomplete` 与退出码 3，不自动认定产品缺陷；独立的页面业务断言失败仍可按已有规则阻断 CI。重复请求、来源及查询精确匹配、主框架范围、缓存和压缩响应限制保持原有语义。

## 公开数据与受控故障实测

沿用此前冻结的 DummyJSON 公开响应与 AI 编写的独立商品后端，选择 `limit=7&skip=11` 的记录。预期首条 ID 为 12、总数为 194、当前页 7 条；前端分别声明页面内容和响应字段。原始后端包不修改，错误通过本地网关注入，页面错误通过受控显示逻辑注入。

| 最终场景 | 响应声明 | CI / 退出码 | 观察结果 |
| --- | --- | --- | --- |
| 正常 | ID + 总数 | passed / 0 | 两字段与页面符合 |
| 单字段对照，总数错误 | 仅 ID，原对象写法 | passed / 0 | 该声明没有覆盖错误总数 |
| 总数错误 | ID + 总数 | incomplete / 3 | json-mismatch，第 2 项失败 |
| 总数缺失 | ID + 总数 | incomplete / 3 | field-missing，第 2 项失败 |
| 页面多显示一条 | ID + 总数 | failed / 1 | 响应符合，页面失败，1 项可提单发现 |
| 恢复正常 | ID + 总数 | passed / 0 | 两字段与页面重新符合 |

最终六次 CLI 验收每次只有一次后端 GET。冻结预期和原包五个文件的 SHA-256 前后一致。单字段对照运行的是当前实现的兼容输入，不是旧实现；另有旧源码拒绝数组输入的红灯回归记录。

这是**真实公开数据 + 本地受控故障**，不是新发现的公共 DummyJSON 缺陷，也不证明整份响应、全部商品或未声明业务规则正确。该案例关闭通用检测器、链接检查和视觉基线，以隔离页面及响应声明。

## 下游 QA 就绪状态纠错

继续检查消费者发现：站点评估仅以可提单数判断 QA 就绪，把上述错误总数和缺失总数的实际运行记录都标成 `ready`，尽管两者 `checkNeedsFix=1`、CI 为未完成。

现从已有 CI 中抽取并共用完整性判断，不复制检测规则；站点评估只读 `run.json`，检查环境、检查点、资源拦截、导航、检测器与已有基线。输出 `qa.latest.completeness` 的状态与原因类别数，不暴露导航错误或基线原因原文。旧记录缺覆盖、必要计数或覆盖项格式无效时为 `unknown`；未完成和未知都产生阻塞项与复跑动作，已有可提单发现仍独立保留。默认不要求视觉基线，不改 CI 退出语义。
