# Datasette 独立部署实战

日期：2026-11-13。

## 结论

本案例验证了三件事：

- 观察回放适配器可以在源站停止后独立启动，并继续服务已捕获的页面和公开只读 JSON。
- 旧实现会把 `9007199254740993` 舍入成 `9007199254740992`，且 B2 留出验证会错误通过。
- 修复后两个 ID 在真实 Datasette 0.65.2 + SQLite 3.50.4 响应中保持区分，浏览器 QA 从 `json-mismatch` 恢复为 `matched`。

案例数据是本机自有的 14 条公开记录，不含账号、Cookie、令牌或个人数据。源站是 Python 3.12.13 上的 Datasette 0.65.2，数据库使用 SQLite 3.50.4。

旧适配器的真实响应结果：

| 检查 | 修复前 | 修复后 |
| --- | --- | --- |
| 两个长整数 ID 保持区分 | 否 | 是 |
| B2 留出验证 | 1/1 通过，但漏掉数值错误 | 1/1 通过且保留精确 token |
| 浏览器源站 → 回放 QA | `matched`, `json-mismatch`，退出码 3 | `matched`, `matched`，退出码 0 |

修复只复用了现有 HAR、适配器和验证模块。`parseReplayJson` 用 `JSON.parse` 的原始 token 上下文保存不安全整数和溢出数字；隐私清洗仍然先执行，报告仍不输出响应值。

## 独立包验收

在停止源站进程后，候选包由自己的 `serve.mjs` 启动。Playwright 实际访问三个页面，均返回 200 并显示预期文本；离线适配器返回的 JSON 同时包含 `9007199254740992` 和 `9007199254740993`；未捕获的 `/library/books/999` 返回 404。

五个捕获页面的三视口静态验证为 5/5 完整测量，平均 99.99%，等级 A。该数字只表示捕获页面的视觉还原度，不表示整站覆盖或业务等价。

## 严格发布边界

严格导出按设计未发布。真实门禁仍报告：

- 94 个页面内部链接没有进入本次捕获范围。
- `root=mirror` 缺少源站根路径快照。
- 三条离线操作流、适配器路由和源站依赖对照因上述覆盖阻断而未完成。
- 只读数据已从源站采集并进入候选包，但离线操作流未能完成对照。

因此本案例的准确等级是“已验证的局部独立部署 + B2 只读行为回放”，不是整站严格交付，也不证明认证、权限、写入、事务、状态机或完整业务规则等价。
