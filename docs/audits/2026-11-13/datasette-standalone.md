# Datasette 独立部署实战

日期：2026-11-13 首次实战；2026-11-14 严格复验。

## 结论

本案例验证了三件事：

- 观察回放适配器可以在源站停止后独立启动，并继续服务已捕获的页面和公开只读 JSON。
- 旧实现会把 `9007199254740993` 舍入成 `9007199254740992`，且 B2 留出验证会错误通过。
- 修复后两个 ID 在真实 Datasette 0.65.2 + SQLite 3.50.4 响应中保持区分，浏览器 QA 从 `json-mismatch` 恢复为 `matched`。

案例数据是本机自有的 14 条公开记录，不含账号、Cookie、令牌或个人数据。源站是 Python 3.12.13 上的 Datasette 0.65.2，数据库使用 SQLite 3.50.4。

## 证据

旧适配器的真实响应结果：

| 检查 | 修复前 | 修复后 |
| --- | --- | --- |
| 两个长整数 ID 保持区分 | 否 | 是 |
| B2 留出验证 | 1/1 通过，但漏掉数值错误 | 1/1 通过且保留精确 token |
| 浏览器源站 → 回放 QA | `matched`, `json-mismatch`，退出码 3 | `matched`, `matched`，退出码 0 |

修复只复用了现有 HAR、适配器和验证模块。`parseReplayJson` 用 `JSON.parse` 的原始 token 上下文保存不安全整数和溢出数字；隐私清洗仍然先执行，报告仍不输出响应值。

## 独立包验收

在停止源站进程后，候选包由自己的 `serve.mjs` 启动。Playwright 实际访问三个页面，均返回 200 并显示预期文本；离线适配器返回的 JSON 同时包含 `9007199254740992` 和 `9007199254740993`；未捕获的 `/library/books/999` 返回 404。

五个捕获页面的三视口静态验证为 5/5 完整测量，平均 99.99%，等级 A。该数字只表示捕获页面的视觉还原度，不表示整站覆盖或业务等价。

## 2026-11-14 严格复验

复验使用当前代码从同一份已停止源站的工作区重新导出，命令为：

```text
node core/src/live/export.mjs 127.0.0.1 --offline --strict --root mirror --include-readonly-data --include-adapter
```

候选包保存在外部证据目录的 `.candidate-127.0.0.1-9FH8Be`。站点级输出包含 83 个 live 页面；覆盖台账为 recon 发现 24 个目标、83 个捕获副本、59 个额外查询/状态副本。显式批准的公开只读数据 68 条全部纳入，`readOnlyDataInvalid/Missing/Conflicts` 均为 0。

这次复验还修正了一个会制造假通过的健康扫描回退：带查询参数的公开数据链接必须有同一完整 URL 的可回放 HAR，只有同路径的无查询响应不能覆盖它。修复后健康报告的 1,699 个站内链接中 1,035 个被覆盖，664 个仍缺失；缺口包括 288 个 `/library/books.json` 查询变体、48 个 CSV 变体、16 个 `/library.json` 查询变体、路径别名和 1 个 `/library.db` 二进制下载。独立服务器的运行探针检查 250 条路径，失败 0 条；它仍明确返回 `/library.db` 404。

运行探针通过后，浏览器探针继续检查全部 83 页：83/83 已测，9 页触发 `ReferenceError`。复现到 `/library/` 的具体错误是 `CodeMirror is not defined`；源站 HAR 同时记录 `sql-formatter`、CodeMirror、SQL 模式和 `cm-resize` 四个脚本为 404，页面内联脚本仍无条件调用 CodeMirror。这是实际前端缺陷证据，不能把它降成“探针噪声”。

2026-11-14 用当前探针对同一候选包的 `/library/` 做单页复核（最短观察 3,000 ms）：`checked=1`、`failed=1`，脱敏失败项同时保留 `error: "ReferenceError"` 和 `message: "CodeMirror is not defined"`。这次复核只提升诊断证据的可读性，没有把候选包改写成通过；完整 83 页旧结果仍为 9 个浏览器错误。

严格候选因此仍未发布，当前阻断项是：664 个未覆盖链接、9 个浏览器 pageerror、2 个侦察失败、3 条离线操作流未测、1 条适配器路由未测。资源覆盖仍为 83/83 本地、0 个未解析或跨源静态资源；隐私审计干净。候选包不应被描述为整站等价交付。

## 严格发布边界

严格导出按设计未发布。公开只读数据的精确回放已经可用，但查询状态闭包、数据库二进制下载、离线操作流和适配器路由仍需逐项补证；源站认证、权限、写入、事务、状态机和完整业务规则没有被该案例证明。

因此本案例的准确等级是“已验证的局部独立部署 + B2 只读行为回放”，不是整站严格交付，也不证明认证、权限、写入、事务、状态机或完整业务规则等价。
