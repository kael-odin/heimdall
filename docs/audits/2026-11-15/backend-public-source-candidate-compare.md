# B3 公开源站与候选后端对照实测

日期：2026-11-15。范围：DummyJSON 的公开只读商品 API与本地候选适配器；没有登录、写入或生产凭据。

## 实际流程

同一条人工确认规则在源站和候选上分别运行：

1. `GET /products?limit=1`，确认商品列表和整数商品 ID；
2. 从第一步响应的 `products[0].id` 解析完整路径段 `/products/{id}`；
3. `GET /products/{id}`，核对详情响应的 `id` 与第一步相同；
4. 用 `heimdall backend compare` 对照两份 `business-rules-only` 报告。

源站是真实公开网络响应。候选是由 Heimdall B3 脚手架启动的本地适配器。动态 ID只在检查进程内存中使用。

## 结果

| 检查 | 结果 |
| --- | --- |
| 源站业务规则 | passed |
| 候选业务规则 | passed |
| 对照结果 | `1/1 passed` |
| 身份标签 | 源站和候选均为 `anonymous` |
| 比较报告是否含候选测试正文 | 否 |

首次实测把商品 ID 写成 `number` 时，检查器按实际 JSON 语义返回 `json_assertion`；改为 `integer` 后源站和候选都通过。这证明数字类型差异会进入规则结果，不会被宽松转换掩盖。

## 边界

该案例证明了公开只读动态资源可以从真实源站进入候选对照闭环。它不能证明认证、权限、写入、持久化、状态机、并发、外部副作用或完整后端等价。
