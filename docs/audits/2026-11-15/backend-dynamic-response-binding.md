# B3 动态响应绑定公开 API 实测

日期：2026-11-15。范围：DummyJSON 的公开只读商品 API；没有登录、写入、分页业务副作用或完整后端等价声明。

## 实际流程

源站：`https://dummyjson.com`

在临时测试工作区里用脱敏契约声明两个 GET 路由，并写入一条经过人工确认的 `business-rules-only` 规则：

1. `GET /products?limit=1`，确认返回商品列表；
2. 从第一步 JSON 的 `products[0].id` 解析完整路径段 `/products/{id}`；
3. `GET /products/{id}`，用 `equalsFrom` 确认详情响应的 `id` 与第一步相同。

动态值只在检查进程内存中使用，报告只保留规则 ID、步骤和状态。

## 结果

| 检查 | 结果 |
| --- | --- |
| 规则模式 | `business-rules-only` |
| 请求 | 2 次公开 GET |
| 业务规则 | 1/1 passed |
| 进程退出码 | 0 |
| 报告是否含响应正文或动态 ID | 否 |

这次实测证明 B3 业务规则可以覆盖“先取得资源身份、再读取同一资源”的真实公开 API 流程，并能把路径串号或响应资源错配转成可复测的失败。它复用了 QA 已有的 `response + path` 引用语义，不新增第二套响应绑定格式。

## 边界

这只证明公开只读流程的动态路径和字段关联；它不能证明认证、权限、写入、持久化、状态机、并发、外部副作用或源站完整后端等价。涉及这些范围时仍需获授权的测试账号、写入许可和独立业务旅程。
