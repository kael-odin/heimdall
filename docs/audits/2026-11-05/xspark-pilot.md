# Xspark 真实 QA 试点：先修误报与接入，暂不新增检测器

2026-11-05，在站点所有者授权下，使用 Heimdall `230e34ecbbd293981af8342e39edb6df8693afcc` 对 Xspark 执行 20 次真实 Chromium QA CI，共 184 次页面与视口检查。范围为正式官网 5 页、正式/测试仪表板各 6 页、正式/测试后台各 3 页；视口 1440×900、390×844。登录后的读取已实际跑通，自动点击探索关闭。当时使用默认方法拦截和路径前缀例外；后续发现例外范围过宽，详见文末的请求边界说明。

**结论：本机真实项目接入成立，但自动提单噪声仍高。暂停增加检测器，优先改现有检测规则、只读 POST 接入和项目检查点。**

这些是 **Codex 通过独立浏览器证据复核后的暂定标签，未获开发或产品签字**。条目受视口、环境、去重和展示上限影响；有依据的报警集中在同类下拉框没有可访问名称，不能把 33 条当作 33 个独立业务缺陷。

这里计算的是 `FP/(TP+FP)`，即报警中的误报占比 FDR。没有完整枚举正常样本 TN，因此经典 FPR 不给百分比。无报警的官网也不能声称“准确率 100%”。

小型定向复核集由两类实际现象、两个环境构成：没有名称的分类控件两处均被检出；既有台账要求的日期展示问题两处均未被通用检测指出。这个集合的漏报为 **2/4（50%）**；只计算通用规则支持的第一类，是 0/2。它是在初轮后建立的定向集，非盲测、非随机、不是四个独立缺陷，**全站漏报率仍未知**。日期格式属于需要项目检查点承接的业务展示要求；本次未重新验证日期排序。

## 用时与失败

- 五入口一轮共 23 页、46 次页面与视口检查，运行用时相加约 4 分 9 秒至 4 分 36 秒。
- 单入口单次 QA 约 33.47–73.49 秒；20 次引擎运行耗时相加 17 分 24.57 秒。取 `run.json` 起止时间，不含登录准备、复核和报告整理，不作为并行任务的现实等待时长。
- 同版本重复比较 92 对截图，视觉回归报警 0。期间未部署新版本，不代表跨版本回归检出率。
- 导航异常 0；能打开页面不代表数据已成功加载。
- 默认组有 72 条被拦写请求观察，部分放行查询后为 28 条，说明接入配置会显著影响页面内容。它们是跨运行、去重后的发现条目，不是完整请求总数。
- 首份测试后台令牌验签失败，更新后只读接口和页面恢复；失败证据保留。瞬时网络和坏图观察各 1 条，复跑未再次出现，没有据此认定持续产品故障。

查询白名单为 v1，仍有需要进一步核对的套餐配置和状态查询。配置意图是阻断可能有确认副作用的请求；本次未使用全量 `writes: allow`。旧前缀规则并不能保证所有写操作均被拦截。不把这组结果描述为完全健康的发布门禁。

## 优先改进

| 优先项 | 实际证据 | 后续处理 |
| --- | --- | --- |
| 可访问名称计算 | 浏览器为图标按钮给出 `search`、`left` 名称，现有启发式却报无名称 | 计算后代元素贡献的名称；保留真正无名称控件的正例 |
| 文字裁切判断 | 读屏专用 1×1 标题、可滚动表格、带完整提示的省略名称被当作受损 | 结合隐藏语义、滚动能力和可恢复信息，避免只凭宽度提单 |
| 只读查询接入 | 阻断 POST 查询产生空列表和控制台错误 | 补齐经核对的查询白名单、登录探活和数据加载检查 |
| 业务验收 | 正确的 ISO 时间串不触发通用无效日期检测，但仍不符合项目展示要求 | 使用现有声明式检查点，引用 PRD 或既有台账 |
| 评估独立性 | 同站、同组件、两环境和复跑重复度高 | 预先固定下一批样本，并引入不同真实项目和已知缺陷修复前后版本 |

本次没有修改产品检测规则、门槛或原巡检台账，也没有新增 MCP 工具或检测器。待上述改进重新测量，再决定是否扩充能力。

## 2026-11-08 SEO 收录指令复测

针对现有收录检查器，依据 [Google 搜索中心的 robots 指令说明](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag) 和 [JavaScript 搜索基础](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics) 修复了多标签、大小写、`none`、指定爬虫、响应头取证，以及初始 HTML 中的限制被脚本删除后漏检的问题。仅按本次浏览器实际收到的通用和 Googlebot 指令解释，不声称其他爬虫的策略已经覆盖，也没有直接模拟 Googlebot 抓取。

| 样本 | 实测结果 | 能说明什么 |
| --- | --- | --- |
| Xspark 官网原有 5 个公开页面 | 均 HTTP 200；5 页初始 HTML 均核对；0 页命中通用或 Googlebot 禁止索引 | 这 5 页本次未观察到该类限制；不等于已被收录 |
| 浏览器驱动的 18 个受控场景 | 修复后全部符合预期 | 用于证明规则边界，不是 18 个独立真实网站 |
| 初始 HTML 无法核对的回退场景 | 普通报告保留，但跳过基线比对、基线更新与趋势记分；回归、更新和分数门禁返回失败 | 避免把未核对说成已修复；旧基线与旧对比文件均不覆盖 |

真实复跑使用隔离临时数据目录，不覆盖既有案例和基线；本机进程墙钟约 8.3 秒，包含发现和采集，不能当作性能基准。5 页启发式分数仍为 90.8，发现 17 项（严重 0、高 0、中 6、低 5、提示 6）；相较 11 月 4 日的 16 项，新增的是一条图片格式提示。未配置真实用户性能数据，分数也不代表实际搜索排名或 AI 引用率。

这次没有增加新的检测器，重点是修准现有检查器和诚实标记未完成。受控场景不是随机盲测，不能用来计算真实网站的误报率、漏报率；上文 QA 试点的 53.52% 是历史报警误报占比，不适用于本次 SEO 规则。`robots.txt` 的具体抓取许可、其他搜索引擎、请求时身份与爬虫 UA 差异，以及 Google 实际收录情况仍需单独验证。

补充验证：在隔离数据目录和本地受控页面上，使用真实 MCP stdio 客户端调用 SEO 审计。引擎最初不可达，调用后按需启动；初始 HTML 未能核对时，返回“部分完成”，不引用或覆盖旧对比文件，也不创建基线。该结果只覆盖本次客户端和配置，不证明其他 AI 应用已经完成握手或其配置有效。

## 2026-11-08 请求边界更正

本机隔离夹具复现了旧路径前缀规则匹配过宽：同路径的其他方法、相似路径、子路径或其他来源的同名路径也可能被放行。此复现不代表这些请求曾到达 Xspark。原始统计 JSON 中 `scope.writes` 的 `mutations blocked` 是当时的配置意图，不是所有业务写入均被阻断的证明；为保留冻结样本，原始 JSON 未改写。没有证据表明试点发生过真实写入，但历史证据不足以排除，须结合业务审计日志核查。

新规则要求为每项例外指定 `POST`、完整来源和精确路径，旧前缀会直接报错。测试后台单页实际复测导航正常，已核对的列表查询返回 HTTP 200、业务码 0，引擎耗时 3.247 秒；检测器和视觉比较均关闭，不能用这次运行计算准确率。HTTP 方法、路径、查询参数和请求体都不能单独证明业务只读，重定向被中止时原请求也已送达服务器。

## 2026-11-09 站点地图可信度复测

本机两个隔离 HTTP 服务复现了旧 SEO 采集器会请求其他来源的地图，以及 URL 尾斜杠导致的错误缺失报警。现已复用受限地图采集器，区分已检查、已检查位置未发现、部分及不可用；跨来源声明或跳转不会被请求。XML 使用良构性解析，不表示完成完整 sitemap 模式验证。受限采集失败时不再断言页面缺失，也不更新历史或基线；SEO 门禁、依赖地图发现目标的变更监控不会假装通过。旧报告没有采集状态，矩阵不参与分数比较。

旧版基线不含地图采集证明，保留原文件并改用新路径重新建立；原路径不能直接作为回归门禁或原地更新。基线页面超过本次 `--max` 而未检查时，不将其误判为消失，也不更新基线。新 MCP 进程连接独立本机引擎与真实浏览器夹具时，地图部分失败会返回部分完成、没有等级，也不链接过期对比；这不是当前已启动客户端自动刷新的证明。
