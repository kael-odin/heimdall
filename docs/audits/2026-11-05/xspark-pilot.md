# Xspark 真实 QA 试点：先修误报与接入，暂不新增检测器

2026-11-05，在站点所有者授权下，使用 Heimdall `230e34ecbbd293981af8342e39edb6df8693afcc` 对 Xspark 执行 20 次真实 Chromium QA CI，共 184 次页面与视口检查。范围为正式官网 5 页、正式/测试仪表板各 6 页、正式/测试后台各 3 页；视口 1440×900、390×844。登录后的读取已实际跑通，自动点击探索关闭。当时使用默认方法拦截和路径前缀例外；后续发现例外范围过宽，详见文末的请求边界说明。

**结论：本机真实项目接入成立，但自动提单噪声仍高。暂停增加检测器，优先改现有检测规则、只读 POST 接入和项目检查点。**

## 优先改进

| 优先项 | 实际证据 | 后续处理 |
| --- | --- | --- |
| 可访问名称计算 | 浏览器为图标按钮给出 `search`、`left` 名称，现有启发式却报无名称 | 计算后代元素贡献的名称；保留真正无名称控件的正例 |
| 文字裁切判断 | 读屏专用 1×1 标题、可滚动表格、带完整提示的省略名称被当作受损 | 结合隐藏语义、滚动能力和可恢复信息，避免只凭宽度提单 |
| 只读查询接入 | 阻断 POST 查询产生空列表和控制台错误 | 补齐经核对的查询白名单、登录探活和数据加载检查 |
| 业务验收 | 正确的 ISO 时间串不触发通用无效日期检测，但仍不符合项目展示要求 | 使用现有声明式检查点，引用 PRD 或既有台账 |
| 评估独立性 | 同站、同组件、两环境和复跑重复度高 | 预先固定下一批样本，并引入不同真实项目和已知缺陷修复前后版本 |

本次没有修改产品检测规则、门槛或原巡检台账，也没有新增 MCP 工具或检测器。待上述改进重新测量，再决定是否扩充能力。
