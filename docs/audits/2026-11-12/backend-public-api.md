# 公开 API 后端独立部署与缺陷复测

日期：2026-11-12。用 DummyJSON 公开测试接口的实际响应验证 B1 契约、B2 回放、B3 服务和缺陷复验，不把响应回放当成原站后端实现。

## 真实样本与修复

样本为 `GET /products/category/beauty`，实际访问返回 HTTP 200，包含 5 条商品记录。正文经过既有隐私清洗，仅在仓库外用于生成观察型契约和回放模块。所有缺陷注入都在本地副本中执行，没有对源站发起写操作。

真实数据暴露了脚手架的两个校验错误：

- 契约投影复用了名称归一化，把 `discountPercentage` 等必填 JSON 字段转成小写，导致健康响应被误报；中文、空格和空字段名还会被删除。现在保留 JSON 字段的原始身份。
- 数值检查的条件先排除了 `number`，导致字符串、布尔、对象和数组绕过数值类型检查。现在按实际 JSON 类型比较，并保留整数也符合 `number` 的语义。

只修改共享脚手架生成器，在已有测试文件中增加一个参数化回归；没有新增依赖、检测器、产品命令或测试文件。

## 后续 CI 复验：并发显示读取

后端提交 `4a2ca313` 自身的远端 CI `43199967523` 最终失败：两片完整 Core 测试及其余五项任务成功，控制台 smoke 收到 `GET /api/acceptance/runs` 的 HTTP 409，错误码为 `MANAGED_RUN_INTEGRITY_FAILED`。原始日志和失败截图保留，不把本机通过替代这次失败。

Windows 与 Linux 的独立写进程压力试验复现了读取竞态。定位到两处同源问题：原子发布后，Linux 路径查询可能拿到已经解除链接的旧 inode；另一个窗口位于路径检查与打开文件之间，读取器会意外采用新版内容，再与原先捕获的内容比较而失败。

共享显示读取器现在只保留同次请求已经稳定捕获的版本。旧 inode 的解除链接只允许链接数和 ctime 变化，大小、mtime、身份、权限仍须匹配；第一次读取仍使用有界文件描述符取数。路径检查后打开了合法替换版本时，不把新内容混入本次已捕获的列表。

修复适用普通运行的显示头；固定来源快照、托管记录、证据与执行能力继续使用原有严格边界。没有过滤 HTTP 错误、放宽控制台断言、增加重试循环或修改正式验证器。
