# 多视口验证续跑：过期结果修复

## 结论

原来的 `verify --all --resume` 只比较清单和克隆入口 HTML 的修改时间。样式、图片、脚本、验证器和部分选项变化后，它仍可能把旧分数当成本次结果。这个问题也影响调用续跑的一键交付流程。

**本机浏览器反例**：对本地夹具先测得红色页面 100 分；只把克隆样式改成蓝色后，修复前续跑仍报复用 100 分并通过。修复后同一自动化测试要求重新测量，分数低于 100 分。夹具只监听 `127.0.0.1`，不能据此外推到所有真实站点。

## 现在如何判断

- 核对清单与整个克隆目录的内容、验证器相关代码、部分依赖版本元信息、Chromium 主程序、Node、平台和测量选项；不能覆盖所有依赖文件或操作系统变化。
- 核对测量结果与差异图；请求保留截图时，也核对原站与克隆截图。缺失或内容变化就重测。
- 旧结果没有新指纹、加载了本地登录态、启用了交互回放，或已观察到克隆向目录外发出 HTTP(S) 请求时，保守重测。
- 续跑要覆盖旧页结果前，先把旧 JSON 与截图复制到 `workspace/<host>/verify/.resume-history/page-*`；旧摘要也留在 `summary-*`。备份失败则该页不覆盖旧结果。历史截图可能含敏感信息，分享前须人工检查。
- 站点摘要中，成功页的 `measuredAt` 是实际测量时间，不是本次复用的时间；失败页记录的是本次尝试时间。

历史批处理与普通续跑共用验证器指纹，因此本次更换验证器后，批处理会把旧指纹记录标为待复测；历史证据不会因为本次升级被删除。

补充的本机反例还发现：只把结果 JSON 的总分从 100% 改成 50%，原来的续跑仍会复用该结果，且可能与视口分数矛盾。现在测量结果正文也有内容指纹，改动后必须重新测量；这只是检测意外变化，不是防恶意修改的签名。

## 独立导出覆盖修复

之前的隔离夹具使用人工构造的验证记录：只改克隆 CSS，独立导出的 `verifiedV2` 仍保持为 1。后续补上了**本机真实 Chromium 测量和完整导出**：首次导出计为 1 页；只改 CSS 并恢复它的修改时间后，修复前第二次导出仍计为 1 页，修复后计为 0 页。两个页面都是本地虚构夹具，不是 Xspark 新结果。

单页或全站验证完成时，现会在满足取证条件的记录中保存 `measurementProof`。独立导出只有在验证器、整个工作区克隆目录、实际打包的克隆目录、测量结果和差异图都与该记录匹配时，才将该页计入 `verifiedV2`。截图保留选项开启时，也核对两侧截图。只改文件时间不会使内容指纹变化；修改内容、证据缺失、旧格式或验证器变化都会使该页显示未验证。旧记录与旧交付包保留，不自动删除或修改。

本机真实 Chromium 回归还验证了导出净化：先测量包含无害脚本的克隆，再实际导出；导出移除脚本后，该页计数为 0。

这些计数仅说明静态克隆文件与一次视觉测量相对应，不代表分数达到某个门槛，也不证明交付包的 live 页面或业务交互通过。启用交互或登录态仍可生成视觉测量指纹，但不会因此允许续跑复用；已观察到克隆目录外 HTTP(S) 请求时不生成该指纹。导出净化若改变了克隆内容，也会显示未验证；目前还没有直接对最终包生成该指纹的工作流。

`health.json` 是导出时的快照，交付后手工修改文件不会自动刷新。原始验证证据留在工作区，不能只凭交付包重新核验该计数。`--strict` 目前不因 `unverifiedV2` 非零而单独失败。指纹不证明在线参考站、远程资源、系统字体或后续动态请求没有变化，也不是防止本机恶意篡改的签名。需要确认当前还原度时须重新测量；交付期间不要并发修改工作区或候选包。

## 控制台和 AI 的当前结果

**本机真实浏览器反例**：先对红色夹具测得 100%；仅把克隆 CSS 改成蓝色，再把修改时间改回原值。修复前，页面接口、`site` 和复用镜像的 `clone` 都仍返回旧分数；修复后不再返回该分数，站点当前已验证数由 1 变为 0。相同反例也通过真实 MCP stdio 协议测试了 `heimdall_site` 与 `heimdall_clone`。这些测试只使用本机虚构站点，不是 Xspark 新验收。

- `/api/pages`、AI 站点和克隆结果统一核对测量证明。内容或证据变化显示 `stale`；旧格式、未完成、忙碌、超时和不可用分别显示状态。旧记录不删除。
- 全站覆盖从当前逐页校验结果计算。扫描无法完成时，数量与平均分为未知，不冒充 0 或通过。AI 总览不扫描全部大站：`verified` 为未知，`historicalVerified` 明确只是旧摘要中的数量；需要当前数量时调用 `heimdall_site` 的 `coverage`。
- 控制台只有在全站摘要逐页对应当前测量时间、总分和最差视口时，才沿用摘要的通过结论。单页重新测量后应重跑全站验证。
- 响应式升级在使用基准前核对证明和逐页摘要。交接命令检查本次验证退出码和新摘要，不能把旧摘要当成本次通过；`--skip-verify` 仍可跳过，但不宣称通过验证。
- 页面最初克隆时生成的 `score.json` 是另一份历史快照，不是本次多视口证明；原站可能变化时应重新测量。显式允许的有界测量仍保留原有口径；独立导出覆盖只统计完全收敛的视口。

校验在工作线程执行，每个进程最多同时处理两个扫描，超过时返回忙碌，超过 60 秒返回超时。本机虚拟性能试验构造 120 页、每页逻辑大小 16 MiB，数据通过硬链接复用同一文件；两次并发扫描约 1.9 秒，期间健康接口响应 2 毫秒，第三次扫描报告忙碌。该结果只说明本机该夹具的情况，不保证其他机器或实际站点的速度。

内容指纹只反映扫描时读到的文件，不锁定文件，也不是防篡改签名。校验期间仍应避免并发修改；它不能证明在线原站、远程服务、系统字体或之后加载的内容未变。历史记录不带证明时须重测；没有重新访问 Xspark，也没有改变试点误报或漏报的分母。
