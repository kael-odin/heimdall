## 1. 愿景与定位

**愿景**：任何 AI 代理，用一句话，就能让 Heimdall 把一个自己有权访问的站点，变成代理可以理解、重建、验证、交付的东西——并且每一步都有可复核的证据。

**定位**（给谁、做什么、与谁不同）：

> 对**用 AI 代理做前端迁移、重建和验收的人**，Heimdall 是**代理的眼睛、尺子和裁判**：
> 确定性地取证、度量、判定，让前沿模型写出来的代码**可以被证明**对不对。
> 不同于让模型照截图「画」一个相似页面的做法，Heimdall 给模型真值（渲染态、原件资产、HAR）和反馈（区域级修复包），
> 并在模型失败时交付镜像兜底。

### 能力上限地图

这一节回答「大大增强上限」：每一行是一个维度，从今天到第一阶段（比赛）到赛后。

| 维度 | 今天 | 第一阶段（比赛 MVP） | 赛后 |
| --- | --- | --- | --- |
| 谁能调用 | 本机的人；手写 stdio MCP（13 个工具） | 任何会 MCP、会跑命令或会调 HTTP 的代理；Claude Code 插件一键安装 | 团队共享的远程服务（OAuth）；MCP Apps 在聊天里出界面；SDK |
| 代理看到什么 | 分数、热图（给人看） | 简报、分段、修复包（给代理看，压缩过，可按预算展开） | 旅程视图、契约视图 |
| 产出什么 | 冻结的静态 / 交互镜像 | 镜像 + 可维护的重建项目（HTML+CSS、Vite+React）+ 门禁报告 | Vue、Next.js、Astro；后端脚手架 |
| 保真反馈 | 一个标量分数 + 热图 | 区域级修复包：原因、对应元素、属性差值、裁剪对比图 | 动效对照、无障碍对照 |
| 交互逻辑 | 对声明的流程做断网回放 | 行为规格 lite（来自操作发现）+ 同流程回放对照（加分项） | 旅程录制、行为环全量 |
| 后端 | HAR 回放（静态 / 只读 GET）；适配器协议（手写） | 契约草案 B1（夹具上演示） | B2 行为 mock → B3 服务脚手架 → B4 所有者协作 |
| AI 的角色 | 三处：CSS 校准、语义情报、验收解读 | 外部代理是建造者；Heimdall 是裁判 | 内置 Autopilot；失败自愈（提议站点配方补丁并复测） |
| 自动化 | `handoff` 一条命令；SEO 门禁（手动触发） | 代理闭环 + 预算 + 断点续跑 | 无人值守：PR 门禁、变更监控后自动出更新 |
| 可信度 | 分数带口径，缺口可枚举 | 再加：出处标注、Floor=Mirror、飞行记录器 | 证据包签名与回放 |

## 2. 目标与非目标

### 2.1 目标

带【假设】的数字是目标，不是承诺；Phase 0 实测后用实测值替换（[10 §3](10-roadmap-risks.md)）。

| # | 目标 | 衡量 |
| --- | --- | --- |
| G1 | **接入快**：全新机器到在 Claude Code 里跑通第一次重建 | ≤ 10 分钟（装插件、`doctor`、内置示例站）【假设】 |
| G2 | **精度高**：重建达到门禁 | 夹具集 F1–F3 的分段中，≥ 80% 无需人工改动达到 Silver（三视口 ≥ 97%）【假设；比赛期内为 n = 2 的内部观察，对外引用需 n ≥ 3，见 [09 §2.6](09-quality-metrics.md) H4】。Ph0：thordata.com 两个分段，6 次运行全部在 4 次对比内达到 silver，其中 5 次到 gold（Opus 5.5 四次、DeepSeek 一次；GLM-5.3-flash 第 3 次到 silver） |
| G3 | **不比今天差**：每次运行都有可交付物 | 100% 运行至少产出镜像 + 报告（Floor=Mirror） |
| G4 | **成本可控**：单页成本与耗时 | 默认档（Sonnet 5.5，balanced）中位页 ≤ 3 美元、≤ 15 分钟；Gold 档（Opus 5.5）≤ 6 美元【假设 A-1，估算见 [05 §6.4](05-frontend-rebuild.md)】。Ph0：Gold 档实测每段 1.55–3.13 美元，外推每页约 15–30 美元，**未达**，降本手段与修订规则见 [05 §6.4](05-frontend-rebuild.md) |
| G5 | **安全**：不泄秘密，不被页面内容劫持 | 自动化测试中工具输出 0 次含秘密；100% 来自网页的文本字段带围栏 |
| G6 | **兼容**：一等客户端行为一致 | Tier-1 客户端的一致性测试全过（[02 §6.5](#65-客户端兼容矩阵)） |
| G7 | **叙事成立**：演示讲得清「AI 用在哪」 | 彩排 ≥ 3 次，最后 3 次均一次通过（不触发降级）；问答预案覆盖 Q1 / Q3 / Q6 |
| G8 | **可维护**：新增能力只写一处 | 注册表生成物与源码同步，CI 检查 |

### 2.2 非目标

| # | 不做 | 原因 |
| --- | --- | --- |
| NG1 | 托管 SaaS、多租户 | 超出比赛窗口；赛后随远程 MCP 再议 |
| NG2 | 绕过访问控制、验证码、2FA、反爬；代替用户登录 | 项目红线（[RISKS](../../../RISKS.md) §1），**不可配** |
| NG3 | 承诺任意站点 100% 还原；WebGL、运行时画布、视频、滚动编排的逐帧复刻 | 只报上限，不夸大（[05 §7](05-frontend-rebuild.md)） |
| NG4 | 替代用户的代理客户端（不做聊天界面） | 我们做工具，不做代理 |
| NG5 | 训练或微调模型 | 无必要 |
| NG6 | 克隆「未被观察到的业务逻辑」，或声称后端等价 | 只做行为克隆；完整等价需要源码 / 规格 / 数据库 |
| NG7 | 重写 `engine-server.mjs`；修改验收「指纹」冻结的 10 个文件 | 风险高、无收益；用门面 + 组合调用 |
| NG8 | 比赛 MVP 内做：全量旅程录制器、契约环 B3+、内置 Autopilot、远程 OAuth、MCP Apps | 单人窗口内打穿一条闭环比铺三条重要 |
| NG9 | 关键词、外链、排名等数据生意 | 沿用现有边界 |
| NG10 | 内置 robots 强制或默认节流 | 沿用既有决定（[RISKS](../../../RISKS.md) §1.4）。本方案的「预算」是成本护栏，不是爬取礼仪，默认宽松；节流仍是可配项 |

## 3. 设计原则

每条原则都落到具体需求上，评审时可以拿来逐条核对。

| # | 原则 | 含义 | 落到哪 |
| --- | --- | --- | --- |
| P1 | **AI 提议，确定性门禁裁决** | 模型可以改任何东西，但「通过」只由确定性检查说了算；模型提出的门禁改动一律不接纳 | E7-04、E7-09；沿用验收子系统「AI 解释不改门禁」 |
| P2 | **地板是镜像，天花板是重建** | 重建没过门禁就交付镜像 + 报告，不让用户拿到比今天更差的东西 | E7-10 |
| P3 | **一个注册表，多个外壳** | 能力只定义一次，CLI / MCP / HTTP / 文档由它生成 | E1-01 ~ E1-05 |
| P4 | **证据先于断言** | 每个「通过 / 失败 / 缺口」都带证据引用（URI + 摘要哈希）；拿不出证据就不准说通过 | E6-08、E7-07 |
| P5 | **渐进披露** | 简报 → 分段 → 原始文件；每个读工具有 token 预算参数，默认保守 | E6-01 ~ E6-04 |
| P6 | **每个结果带下一步** | 机器可读的 `next_actions` + 一句人话摘要；错误也一样 | E1-07、E11-06 |
| P7 | **出处标注** | 生成物里每条规则 / 端点 / 字段标 `observed`（观察到）、`inferred`（推断）、`invented`（占位） | E9-05 |
| P8 | **默认安全，显式放权** | 默认只读；破坏性操作和写源站需要本机确认；令牌分作用域 | E12-01 ~ E12-04 |
| P9 | **模型无关，为前沿模型优化** | 协议层不绑 Claude；技能和提示按模型能力分档，弱模型走更细的分段 | E4-06、E10-03 |
| P10 | **傻瓜式** | 默认值可用；一条命令起步；错误会说下一步；第一次成功不需要读文档 | E11 全部 |
| P11 | **跨平台** | Windows 原生（无 WSL）是一等公民，Linux CI 同样要过 | E3-08、E11-02 |
| P12 | **只加不改** | 新代码挂在新路由、新命令、新目录；旧演示路径原封不动 | NG7；每个阶段的退出条件 |

## 5. 场景

优先级含义：**P0** = 比赛 MVP 必须；**P1** = 比赛加分项或赛后第一批；**P2** = 赛后。「裁判」列说明由谁判定通过。

| # | 用户对代理说的话 | 闭环 | 裁判 | 产物 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| S1 | 「把 <URL> 这一页重建成 React 项目，三个视口 ≥ 97%」 | 重建环 | 快速对比 + 正式验收（Mirror） | 重建项目 + 门禁报告 | **P0** |
| S2 | 「把整个站迁移成 Next.js / Vue 项目」 | 重建环 × N + 共享组件 | `verify --all` 复验 + 断网门禁 | 多页项目 + 交接说明 2.0 | P1（比赛只演前几页） |
| S3 | 「给重建的页面补上菜单、标签、搜索、筛选」 | 行为环 | 同流程回放对照 | 行为规格 + 通过的流程集 | P1（加分项） |
| S4 | 「给前端生成 mock 后端和 OpenAPI，让页面断网也能用」 | 契约环 B1–B2 | 录制请求重放 + 留出集 + 断网严格门禁 | OpenAPI + 适配器 + 覆盖矩阵 | P1 / 赛后 |
| S5 | 「按这份规格 / 源码生成真实后端脚手架」（所有者协作） | 契约环 B3–B4 | 同上 | 服务项目 + 测试 | P2 |
| S6 | 「每个 PR 都对照参考页验收，不达标给修复线索」 | 门禁 | 正式验收 | CI 评论 + 报告 | P1 |
| S7 | 「审计 SEO，修掉 critical 问题并复测」 | 审计—修复—复测 | 64 条规则引擎 | 改动 diff + 前后对比 | P1（便宜、确定、好演示） |
| S8 | 「提取这个站的设计系统，给我令牌和组件库」 | 提取 | 重建对照 | `tokens.css` / Tailwind 主题 / 组件 | P1 |
| S9 | 「把这个竞品的定价、功能、CTA 整理成表」 | 情报（现有 harvest） | 字段覆盖 | xlsx / json | P1（几乎只是暴露现有能力） |
| S10 | 「这个站改版了，更新我的克隆并告诉我变了什么」 | 监控 → 增量 → 补丁 | 变更监控 + 回归 | PR / 报告 | P2 |

S1 是**主线**，贯穿整个 MVP；S7、S9 几乎是「把已有能力接到代理上」，成本低、演示效果好，作为 P1 垫底。

## 6. 四种入口怎么分工

### 6.1 每个入口的角色

**结论：都做，但它们是同一套能力的四个外壳，不是四个产品。** 角色比喻：Skill 是**脑**（怎么闭环），CLI 和 MCP 是**手**（动作与读数），HTTP 是**骨**（稳定契约），插件包是**皮**（分发）。

| 入口 | 谁用 | 强项 | 局限 | 在方案中的角色 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| **CLI** | 会敲命令的代理（Claude Code、Codex CLI、Gemini CLI、OpenCode、Cursor 的终端代理）、CI、人 | 最省 token（一条命令就是一次调用）；可组合；无需协议；跨平台易调试；与「代理在项目目录里工作」天然契合 | 没有自描述；没有图片通道（靠写文件 + 路径）；长任务要有 `--wait` | 手（含重建工作区里的本地回路） | **P0** |
| **MCP** | 没有 shell 的聊天 / 桌面 / IDE 代理（Claude Desktop、ChatGPT、VS Code Copilot、Cursor 聊天、国内 IDE）；团队共享的远程服务 | 自描述；结构化结果与图片内容；注解让客户端知道风险；资源与提示词；远程与 OAuth；Apps 可出界面 | 各客户端行为有差异；工具多了占上下文；Tasks 支持参差；本机要管进程 | 手 + 读（资源） | **P0** |
| **Skill** | 所有支持 `SKILL.md` 的代理 | 把「怎么闭环」按需放进上下文；跨厂商；写一次多处用 | 只能指导，不能执行；依赖代理遵循 | 脑 | **P0** |
| **HTTP v1 + OpenAPI** | Dify、Coze、n8n、CI、自研代理；也是 MCP / CLI 的下层 | 契约稳定、语言无关、可鉴权限流审计 | 没有「代理体验」，要自己编排 | 骨 | **P0**（最小面）/ P1（完整） |
| **插件包 / MCPB** | 装机的人 | 一条命令装好技能 + MCP；Desktop 双击安装 | 平台绑定 | 皮 | **P0**（Claude Code 插件）/ P1（MCPB、Codex） |
| **SDK（TS / Python）** | 集成方 | 类型安全 | 要维护 | 可选 | P2 |

### 6.2 按客户端类型选路

| 客户端类型 | 推荐路径 | 说明 |
| --- | --- | --- |
| shell 型编码代理（Claude Code、Codex CLI、Gemini CLI、OpenCode、Cursor Agent） | **技能 + CLI** 为主，MCP 为辅 | 代理在项目目录里读写文件，CLI 最省 token；需要看图时用 MCP 资源或读 `.heimdall/` 下的文件 |
| 聊天 / 桌面 / IDE 聊天（Claude Desktop、ChatGPT、VS Code Copilot Chat、Cursor 聊天、CodeBuddy / Qoder / Trae 等国内 IDE） | **MCP** 为主 + 控制台提示词库 | 没有 shell 或不便用；MCPB 一键装；技能视客户端支持 |
| 工作流平台（Dify、Coze、n8n） | **HTTP v1**（导入 OpenAPI），或 MCP（若平台支持） | 长任务用 `jobId` 轮询 + webhook |
| CI | **CLI `--json` + 退出码**，GitHub Action | 门禁与评论 |
| 自研代理 | HTTP v1 / SDK，或 MCP | — |

### 6.3 为什么不只做一个

- **只做 MCP 的问题**：工具定义每轮占上下文；shell 型代理在项目目录里干活，需要和文件系统组合；各客户端对图片、资源的支持不齐。
- **只做 CLI + 技能的问题**：聊天 / 桌面代理没有 shell；远程共享用不了；没有结构化结果与图片内容；没有工具注解，客户端只能一律弹确认。
- **都做的代价很小**：因为两者都从**同一个注册表**生成。真正的成本在注册表和控制面，而不是在外壳。
- **暂不做**：A2A（代理对代理）协议、服务器发现卡片（`/.well-known`）、浏览器扩展（已有书签入口）。前两项随赛后的远程 MCP 一起评估。

### 6.4 工具面设计准则

依据 Anthropic 关于「为代理写工具」的工程指南，加上本项目的实际情况。

| # | 准则 | 做法 |
| --- | --- | --- |
| T1 | **少而精** | 面向任务而不是面向 API。当前 18 个工具，MVP 8 个；新增能力必须证明它不能合并进现有工具，`clone` 一个工具取代 `recon / forge / queue / verify / live` 五个入口 |
| T2 | **返回格式可选** | `response_format: concise \| detailed`，默认 concise；大结果返回摘要 + 资源 URI |
| T3 | **分页、范围、截断** | 每个读工具有默认上限（约 2.5 万 token）并在被截断时说明怎么取更多 |
| T4 | **错误可行动** | 错误码 + 原因 + 下一步（一条命令或一次工具调用），不返回堆栈 |
| T5 | **命名空间** | 统一 `heimdall_` 前缀，动词明确 |
| T6 | **确定性顺序** | `tools/list` 顺序固定（新规范建议，有利于缓存） |
| T7 | **注解齐全** | `readOnlyHint` / `destructiveHint` / `idempotentHint` / `openWorldHint` 全部标注 |
| T8 | **描述写给模型** | 写清「什么时候用、什么时候不用、参数怎么填、返回什么、下一步」。工具 `description` 用英文（精确、省 token），`title` 用中文；技能的 `description` / `when_to_use` 中英触发词并列（受 1,536 字符上限约束） |

完整目录见 [附录 A](appendix-a-tools.md)。

### 6.5 客户端兼容矩阵

分层承诺，**以 Phase 0 实测为准，不凭文档断言**。

| 层级 | 客户端 | 承诺 |
| --- | --- | --- |
| **Tier-1** | Claude Code、Claude Desktop、Cursor、VS Code（Copilot）、Codex CLI | 一致性测试全过；安装向导一键配置；写进演示 |
