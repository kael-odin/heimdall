  **第一次重复测量**（夹具 F1，silver，模型 DeepSeek-v4.1-flash-1017，每臂 2 轮，除 A1 为 1 轮）：

| 臂 | n | 375px 中位数（min–max） | 768px | 1440px |
| --- | --- | --- | --- | --- |
| 脚手架（空） | — | 13.4% | 24.3% | 33.7% |
| A1 只有简报 | 3 | 61.2%（52.0–66.1） | 74.8%（68.1–75.6） | 76.1%（68.9–76.9） |
| A2 简报 + 标量反馈 | 3 | 58.7%（52.9–61.3） | 66.1%（65.1–73.2） | 70.7%（68.6–74.7） |
| A3 完整修复包 | 1 | 63.7% | 66.1% | 74.5% |
| A3 定向反馈（只给前 5 个区域） | 4 | 58.9%（44.9–61.8） | 63.7%（61.7–73.1） | 66.9%（64.8–68.5） |
| 人写（按技能手写） | 1 | 100% | 100% | 100%（gold） |

  三条结论，都没挑数据：

  1. **简报是最大的杠杆**：空脚手架 → 一次模型调用，61% / 75% / 76%。
  2. **第二轮平均不涨**：八个「第 1 轮 → 第 2 轮」的样本，平均 **−0.88 个百分点**（A2 三次都是正的 +1.6 ~ +2.9；A3 定向三次是负的，最差一次掉 11.6）。也就是说，**整页重写式的修复循环在这个模型上不收敛**——模型每次都把整页重写一遍，把已经对上的地方一起改坏。这直接否定了「弱模型 + 修复包就能逼近 silver」的预期。
  3. **修复包的优势没有出现**：A3 与 A2、A3 定向都在方差之内，离 silver（97%）还差 20 多个百分点。按 PRD 09 §2.6 照实记，不做对外结论（n 小、单页）。

  下一步该改的是**循环的形态**，不是换模型：让模型只输出「改动」，而不是每次重写整页（surgical edit），再比一次。这条已记为下一轮实验。

  **加了「变差即回退」之后**（PRD 03 §5.4 的规则，实现在 `bench run` 里，默认开）：又跑了两组 3 轮。

| 臂 | 第 1 轮 | 第 2 轮 | 第 3 轮 | 最终保留 |
| --- | --- | --- | --- | --- |
| A2（3 轮） | 72.7 / 82.8 / 80.4 | 50.7 / 80.3 / 78.3 → 回退 | 51.9 / 82.8 / 80.4 → 回退 | 第 1 轮 |
| A3 定向（3 轮） | 67.3 / 84.4 / 83.3 | 61.9 / 82.8 / 80.8 → 回退 | 57.1 / 84.0 / 79.2 → 回退 | 第 1 轮 |

  两组都是**第 1 轮最好、后面每一轮都更差**，回退把它们全部挡住。结论更尖锐了：在这个模型上，**整页重写式的「修复」是有害的**（注意：当时修复包只有文字提示，见下面「并进计算样式之后」的补充）；循环里真正起作用的是**回退守卫**，不是「再改一轮」。要让迭代涨分，必须换成只改局部的输出形态（surgical edit），否则宁可停在第一版。

  **再试「外科式改动」**（`--edit surgical`：模型只输出 `` ```html <分段 id> `` 的整段替换与 `` ```css add `` 的追加样式，第一轮仍整页写；3 轮 × 2 组）：一组模型只给了 CSS 追加（62.3% → 63.1% → 62.7%），另一组替换了 1–2 个分段后 375 视口直接掉到 **43.2%**，另两个视口几乎不动。**整页重写、追加 CSS、替换分段三种改法，都没有让第二轮稳定变好**——但下面的「精确证据」实验说明，这不是模型的全部问题。

  **分段循环**（`bench sections`：一次只比一段、只改一段，技能里推荐的做法；6 段 × 最多 2 轮，同一份 A1 起稿）：

  - **只给大纲**：整页 64.0% / 68.1% / 79.7% → **67.3% / 71.5% / 75.9%**（375、768 各 +3，1440 −3.8）；6 段里第二轮 2 段变好、3 段变差、1 段持平，没有一段到 `pass-candidate`。
  - **给这一段的精确证据**（`heimdall brief --section-id` 的 slice：每个元素的计算样式、伪元素、写死的高度、亚像素偏移；`bench sections --evidence slice`）。n = 2：

| 次 | 起稿（A1，整页） | 分段循环后（整页） | 到 pass-candidate 的段 |
| --- | --- | --- | --- |
| 1 | 60.1% / 58.6% / 67.9% | **95.8% / 94.3% / 98.0%** | 1/6 |
| 2 | 56.4% / 45.2% / 80.7% | **94.9% / 97.0% / 98.7%** | 2/6 |

  逐段分数在 88–98%，页脚与 CTA 是短板；较差的起稿（45.2%）也能被拉回 95% 以上。

  **前面那条结论要改写**：瓶颈**不是**模型把文字翻成 CSS 的能力，而是**证据的分辨率**。同一个模型、同一个循环，只把「大纲」换成「每段每个元素的计算样式」，三个视口高了 22–30 个百分点，1440 已经摸到 gold（98.0%）。这也说明 A1 / A2 / A3 三臂（都用整页大纲）**低估了产品**：它们测的是「弱证据 + 模型」，不是「产品的正常用法」。

  仍然要修的两处：①**CSS 是全局的**，外科式追加会波及其它分段（只给大纲那一组 1440 掉了 3.8 点，多半来自这里），要让分段循环真正成立，样式得按分段隔离或每段一个样式块；②**修复包还不带参考元素的计算样式**——现在整页卡在 94–96%，门禁差的就是这一档。下一步：把 slice 的计算样式并进修复包的区域条目，让整页臂也能拿到同样的证据；然后用精确证据重跑 A1 / A2 / A3，那才是能对外引用的对比。

  **把参考计算样式并进修复包之后，整页臂也翻盘了**（同日实现：元素索引顺带存一份精简计算样式，`packet.txt` 每个区域多一行「参考样式: …」）。同一份 A1 起稿 **59.6% / 64.7% / 67.9%** → A3 两轮 **65.2% / 78.0% / 93.3%**（第 1 轮 62.9 / 68.3 / 71.7，第 2 轮 65.2 / 78.0 / 93.3，回退未触发；输入 11,687 / 输出 21,872 token）。这是整页重写第一次在两轮内明显变好，提升集中在 1440（**+21.6 点**）。所以前面「整页重写有害」要加限定：**有害的是只有文字提示的重写**；给出精确数值后，重写也能收敛。

  三条合起来的结论：**模型的瓶颈是「没数字」，不是「不会改」**。Heimdall 的核心资产因此可以更明确地写：不是「能拍三视口截图」，而是**把参考拆成可抄的数值证据**（每元素每视口的计算样式）——这一条比任何提示词技巧都值钱。

  **带计算样式的三臂重跑（n = 3，silver，每臂 2 轮，A1 一轮）**：

| 臂 | 375px 中位数（min–max） | 768px | 1440px |
| --- | --- | --- | --- |
| A1 只有简报（大纲） | 61.3%（59.3–63.4） | 76.3%（73.5–81.4） | 79.9%（72.2–91.7） |
| A2 简报 + 标量反馈 | 46.2%（40.5–59.6） | 74.2%（66.6–76.3） | 70.4%（67.8–87.9） |
| A3 简报 + 修复包（带计算样式） | **67.1%（54.0–72.3）** | **83.2%（81.9–85.5）** | **94.5%（84.2–94.8）** |

  读法：**有数字的修复包（A3）明显好过只有分数（A2）**，1440 差 24 个百分点；A2 甚至不如一次成稿（A1）——"只有一把尺子、没有刻度"时，重写只会把已经对上的地方改坏。这是本次实验里第一张三臂都满足 n = 3、可以直接对外讲的表（仍限于一个夹具）。

  **协议修正（2026-10-27）**：`rebuild init` 默认拒绝非空目录，早先几次"重新 init"其实是失败的，起点是上一次跑完的页面而不是空脚手架。对**整页重写**的臂影响有限（第一轮本来就把整页重写掉），但**分段循环**的起点依赖它，所以这条必须记下来。现在 `rebuild init --force` 才真的重置，复现步骤已更新（[09 §1.1](09-quality-metrics.md)）。

  附：11 次模型调用里有 3 次没按格式给出两个代码块，已加重试并记为 `retries`；模型把中文标题写成英文、把业务文案换成自造的（第一次因简报传空导致）这类问题也在样本里出现过。
- E7-07 正式裁判已落地（`core/src/agent/gate/formal.mjs`、CLI `heimdall gate formal --project .`）：按 E7-19 供正式基线 → `POST /api/acceptance/runs`（mirror 模式、375/768/1440）→ 轮询 → 读 `report.json`；同时跑评估器的六维；**验收与评估器都过才算 `passed`**。实测：人写的那页（像素 100%）拿到 **`passed`**（验收视觉 3/3、结构 3/3、健康 12/12）；模型跑出的 72–95% 那版被判 `failed`，未通过的维度逐条列出。**一个必须记下的坑**：验收的结构检查比控件语义时包含 href，基线里的绝对链接（`http://127.0.0.1:5090/signup`）与重建页里的相对链接（`/signup`）指向同一站内目标，却被判成结构缺陷——像素 100% 一致的页面也因此 failed。解法**不动验收**：供基线前把绝对 href 归一成站内路径（链接不参与渲染），验收子系统的指纹冻结文件一个字节都没动。
