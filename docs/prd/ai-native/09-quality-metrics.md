# 09 质量、评测与指标

上一篇：[08 安全、治理与成本](08-security-governance.md) · 下一篇：[10 路线图与风险](10-roadmap-risks.md)

本章定义**怎么证明这套方案有效**：用什么评测集（§1）、怎么比较、怎么算成本（§2）、哪些回归测试守住底线（§3）、看哪些指标（§4）、怎么接进 CI 又不烧钱（§5）。对应需求 E14-01 ~ E14-14，并为 [10 §3](10-roadmap-risks.md) 的 11 条假设（A-1 ~ A-11）逐条提供验证实验（§2.7）。

**三条总规则**

1. 评测集优先用**离线夹具**：可复现、不联网、能进 CI；真实站点只作补充。
2. 带模型调用的评测既花钱，也不可能复现到字节（5.x 模型已不再接受采样参数【调研】）。所以靠**重复次数**和**相同的起始工作区快照哈希**控制方差，不靠随机种子。
3. 结论只覆盖所测的夹具与站点；失败和未测范围如实写进报告（§2.6）。

## 1. Heimdall-Bench

### 1.1 三个评测集

| 评测集 | 目的 | 数据来源 | 入库 | 联网 | 用在哪 | 阶段 |
| --- | --- | --- | --- | --- | --- | --- |
| **Suite F**（Fixture） | 可复现的主实验、缺陷注入、后端留出集；进 CI | `core/test/fixtures/bench/`（**待建**），由小型 node 服务提供 | 是 | 否 | 假设验证、消融、回归 | F1–F3：Ph2；F4–F6：Ph3 |
| **Suite O**（Own site） | 真实站点的现实感；对外演示的数据来源 | 自有站 `thordata.com` 的若干页，取自本机工作区 `core/workspace/thordata.com/pages/` | 否 | 否（用已有镜像做参考，不碰活站） | 演示、现实噪声观察 | 1 页：Ph2；3 页：Ph3 |
| **Suite P**（Public） | 体量大、结构杂的泛化观察 | 本机工作区已有克隆产物的公开文档 / 营销站若干页（例如 `vitest.dev`、`cn.vuejs.org`、`svelte.dev`、`angular.dev`、`tailwindcss.com`、`astro.build`） | 否 | 否 | 压力与泛化观察 | Ph3 起抽样 |

约束：
- Suite P **仅内部评测，不进对外材料**，沿用 [RISKS](../../../RISKS.md) 第 3 条；不设必过线，不承诺通过率。
- 参考一律用**已冻结的镜像**，不对活站评测——活站会漂移（广告、实验分流、内容更新），数字没法比较。
- Suite F 沿用仓库现成的夹具写法：[`acceptance-site.mjs`](../../../core/test/fixtures/acceptance-site.mjs) 导出冻结的 case 清单，并用同一个服务同时提供 baseline 与 target 两侧；[`smoke-forge.mjs`](../../../core/scripts/smoke-forge.mjs) 示范了「随机端口 + 临时数据根 + `HEIMDALL_LLM=0`」的无外网跑法。Bench 夹具照做。

**驱动器（2026-10-27）**：`heimdall bench score|run|sections|summary`（源码 `core/src/agent/bench/`）。`score` 只测量已有候选，**不调模型、不写候选账本**（`record:false`），适合把脚手架 / 人写 / 镜像变体放进同一张表；`run` 复用同一测量口径跑模型臂，三臂的差别只在过程反馈（A1 无反馈、A2 只有标量、A3 完整修复包），起点快照统一由 `rebuild init` 生成；`sections` 按分段循环；`summary` 按臂汇总中位数与极值。每次结果写 `workspace/<siteId>/agent/bench/*.json`。

复现一次整页臂（本机实测命令）：

```bash
heimdall rebuild init <siteId> --page home --dir <工作区> --stack html-css --no-install --port 5196
cd <工作区> && node serve.mjs --port 5196 &          # 另一个终端，保持运行
heimdall bench run --site <siteId> --page home --project <工作区> --arm a3 --iterations 2 --max-tokens 16000
heimdall bench summary --site <siteId> --page home
```

模型臂的起点必须是同一份快照：每次跑之前重新 `rebuild init` 并删掉 `.heimdall/ledger.jsonl`。

目录约定（提议）：

```

├── server.mjs        小型 node http 服务；参数 --port、--inject <caseId>；导出冻结的 case 清单
├── public/           静态资源（字体、图片、样式）
```

### 1.3 缺陷注入集

为了**客观**衡量修复包（A-10、A-5），F1–F3 各支持一组可注入的视觉缺陷。每类原因（对应修复包的 `cause`）至少两个实例（不同位置、不同幅度），F1–F3 合计目标不少于 48 个；F3、F4 另加行为类。

| 注入 | 对应 `cause` | 注入方式（示例） | 真值字段 |
| --- | --- | --- | --- |
| `inj-shift` | `shift` | 某区块整体偏移（如 dx = 12 px、dy = −8 px） | 选择器、各视口包围盒、`dx / dy` |
| `inj-size` | `size` | 卡片宽高或图片缩放改变 | 选择器、包围盒、期望尺寸 |
| `inj-color` | `color` | 按钮 / 文字颜色偏移（一小一大两档） | 选择器、属性、参考值 |
| `inj-font` | `font` | 字号、字重、字体族回退 | 选择器、属性、参考值 |
| `inj-spacing` | `spacing` | `padding` / `margin` 改变 | 选择器、属性、参考值 |
| `inj-image-missing` | `image-missing` | 图片 404 或被移除 | 选择器、资源 URL |
| `inj-overflow` | `overflow` | 窄视口出现横向溢出 | 选择器、视口 |
| `inj-missing-content` | `missing-content` | 删掉一块文案或组件 | 选择器、包围盒 |
| `inj-behavior-*` | `behavior` | 菜单点击不展开、切换不更新文本（沿用 `acceptance-site.mjs` 的 `mobile-menu`、`menu-state` 思路） | 流程 ID、预期断言 |

每个注入随附一份**注入清单** `{id, cause, viewports, selector, bbox, expected}`，只给评分器读取。

### 1.4 每次运行记录的指标

每次 Bench 运行（以及 E14-04 要求的每次正常重建运行）写一份 `metrics.json`；字段分组如下。账本行的字段定义见 [附录 C](appendix-c-schemas.md)，`metrics.json` 是账本的汇总，不是替代。

| 分组 | 字段 |
| --- | --- |
| 标识 | `runId`、评测集与夹具 / 页面、模型 ID 与版本日期、消融臂、`fidelity`、`gate.level`、技术栈配置、重复序号、起始工作区快照哈希 |
| 过程 | 终态（`passed` / `passed_with_residuals` / `failed_with_residuals` / `budget_exhausted` / `cancelled`）、每分段与每页迭代数、停滞 / 回退 / 振荡次数、工具调用数（分工具）、人工干预次数 |
| 结果 | 各视口 `visual.pixel` 与 `visual.maxBlob`、`structure`、`style`、`assets`、`health`、`behavior`（如声明）、门禁逐维判定、残差清单 |
| 成本 | 输入 token（未缓存 / 缓存读 / 缓存写）、输出 token、美元、墙钟、`compare(fast)` 耗时分布 |
| 质量代理 | 构建通过、lint 通过、组件数、重复 CSS 比例、产物体积——只作「是否可维护」的粗代理，不进门禁 |
| 兜底 | `Floor=Mirror` 是否完整交付、「误判通过」标记（正式裁判通过但独立复核不通过） |
| 后端 / 行为 | 流程通过率；训练集重放通过率、留出集等价度、属性测试失败数、覆盖矩阵、出处分布（`observed` / `inferred` / `invented` 条数）、对源站写请求数 |

### 1.5 重复与方差

- 每个（夹具 × 模型 × 消融臂 × 保真档）单元格**n ≥ 3**才能作为对外引用的结论；报告**中位数、四分位距（IQR）、最小、最大**——n = 3 时 IQR 很粗，所以同时给极值。
- Ph2 的预算只够 n = 2（§2.3 的预算表）：n = 2 只用于内部判断「值不值得补跑」，**不得**写进对外材料。
- 起始状态必须一致：每个 run 从同一份工作区快照（记录哈希）开始，同一个提示，同一个预算。
- 不剔除失败的 run；不挑选最好的一次（§2.6）。

## 2. 评测协议与消融

### 2.1 模型矩阵

模型 ID、价格、上下文来自随 Claude 工具链内置的 API 文档快照（2026-10-06）【调研】；每次运行记录**实际模型 ID 与日期**。

| 档位 | 模型 | 价格（每百万 token，输入 / 输出） | 在评测里的角色 |
| --- | --- | --- | --- |
| 旗舰 | `claude-opus-5-5` | $4 / $20（缓存读 $0.20），1M 上下文 | 主实验。`output_config.effort` 显式设为 `high`（该模型默认是 `medium`，写代码类任务不应吃默认值）；可选加一组 `xhigh` 对照 |
| 默认档 | `claude-sonnet-5-5` | $2 / $10 | 默认档候选：A3 臂能否稳定达到 Silver |
| 经济档 | `claude-haiku-5-5` | $0.10 / $0.50（≤ 10 万 token 提示） | 下限：economy 剧本（E4-06）能不能跑通；分类与摘要 |
| 国产模型 | 一个能经 OpenAI 兼容或 Anthropic 兼容中转调用的模型（选定后写入评测配置；仓库默认配置里出现过 GLM、DeepSeek 一类【读码】） | 以实际价目为准 | 验证「模型无关」（P9）与 economy 剧本。视觉能力不足时只能走纯文本变体（`llmVision` 会自动降级【读码】），报告里必须标注 |
| 升级对照 | `claude-fable-5-1` | $10 / $50 | 仅作为「收敛卡点升级」的可选对照，不进矩阵主体 |

国产模型这一栏在 E2 引擎（Ph5）落地前，只能经**支持自定义模型端点的代理客户端**运行，Ph2–3 视可用性而定，不阻塞其余实验。

### 2.2 消融臂（E14-02）

四个臂回答四个递进的问题。**所有臂最终都由同一个正式裁判（验收 Mirror，见 [03 §5.5](03-architecture.md)）判定**，裁判对代理不可见、不可改（E7-04），所以臂之间的差异只来自「过程中拿到的反馈」。

| 臂 | 代理拿到的 | 过程中的反馈 | 回答的问题 |
| --- | --- | --- | --- |
| **A0** | 模型 + 通用浏览器工具（如 Playwright MCP）+ 项目目录读写；**没有任何 Heimdall 工具**；一段同等长度的通用重建提示 | 自己截图、自己看 | 没有 Heimdall 时的水平（基线） |
| **A1** | A0 + 简报（`heimdall_brief`）与落地到 `public/assets` 的真实资产 | 仍是自己截图、自己看 | 「真值与证据」本身带来多少提升 |
| **A2** | A1 + `heimdall_compare`，但**只返回标量**：每视口像素分与通过 / 不通过，不含区域、裁剪、元素、属性差 | 一把尺子，没有定位 | 「有尺子」带来多少提升 |
| **A3** | A1 + 完整 `heimdall_compare`（修复包 v2：区域、原因、元素、属性差、裁剪图）+ 技能 `heimdall-rebuild` | 编译器报错式反馈 | 修复包 + 技能的**增量** |

技能的单独贡献由 E4-10 的 A/B（同一任务有 / 无技能）承担，不再增设臂，避免矩阵爆炸。A0–A2 用同等长度的通用提示，避免把「有提示」和「有工具」混在一起。

### 2.3 分阶段矩阵与预算

**单 run 的规划成本**：Opus 5.5 约 4 美元、Sonnet 5.5 约 2 美元、Haiku 5.5 与国产模型约 0.3 美元【估算；取自 [05 §6.4](05-frontend-rebuild.md) 的每页估算，Ph0 实测后替换】。预算 = Σ（单元格数 × n × 单 run 成本）。

主对比用**默认档 Sonnet 5.5**（A-1 的默认档成本目标针对它），旗舰 Opus 5.5 只在两端（A0 与 A3）复现，用来确认结论在更强的模型上是否仍然成立。

| 阶段 | 内容 | run 数 | 约合美元 | 备注 |
| --- | --- | --- | --- | --- |
| S0（Ph0 spike） | Opus 5.5 与 Sonnet 5.5 手动重建 2 页，用修复包原型；校准成本、迭代数、预算默认值 | 约 10 | 约 40 | 目的是**校准**，不出对外结论 |
| S1（Ph2 主实验） | F1–F3 + O1 共 4 个目标 × Sonnet 5.5 × `balanced` × A0–A3 × n = 2 | 32 | 约 64 | 验证 A-1、A-2、A-5、A-8 |
| S1b（Ph2 旗舰复现） | 同样 4 个目标 × Opus 5.5 × `balanced` × {A0, A3} × n = 2 | 16 | 约 64 | 确认结论在 Gold 档模型上成立；A-1 的 Gold 档成本 |
| S2（Ph2 保真旋钮） | Opus 5.5 × A3 × F1–F2 × {`faithful`, `idiomatic`} × n = 2（`balanced` 复用 S1b） | 8 | 约 32 | 验证 A-9 |
| S3（Ph2 模型梯度） | Haiku 5.5、国产模型 × A3 × F1 × n = 2（Sonnet 复用 S1） | 4 | 约 2 | 验证 economy 剧本 |
| 小计（S0–S3） | | 约 70 | **约 200** | |
| 开发迭代与彩排 | 演示彩排、回归哨兵、临时重跑 | 约 20 | 约 70 | 在 [README D-2](README.md) 的 300 美元上限内 |
| S4（Ph3–4，E14-08） | F4–F6：行为流程评测、契约环（含留出集） | 按余量 | 约 30 以内 | 验证 A-7；超出部分记入赛后预算 |

**熔断规则**：S0 实测的单 run 成本若高于规划值的 1.5 倍，立即把 S1 缩到 A0 / A2 / A3 三臂或 n = 1，并向 Owner 报告；累计花费到上限的 80% 时停止新增矩阵单元格。

### 2.4 控制变量、成本口径与报告模板

**控制变量**（每条都在 `metrics.json` 里留痕）

- 同一提示文本（存仓库、记哈希；各臂只在「可用工具说明」上不同）、同一预算（`maxUsd`、`maxWallMinutes`，迭代上限同 `heimdall.config.json`）、同一技术栈配置（主用 `vite-react-ts-tailwind`，`html-css` 作补充）。
- 同一夹具与注入集、同一起始工作区快照哈希、同一终局裁判与**同一版阈值**。
- 同一渲染环境：Playwright 锁定的同一 Chromium；验收 Mirror 已固定语言 `zh-CN`、时区 `Asia/Hong_Kong`、浅色与减少动效【读码，见 [验收工作台](../../competition/acceptance-workbench.md)】。
- **并发 = 1**：像素比对对时序敏感，抢 CPU 会让同一页的分数漂移（`verify --jobs` 默认 1 的同一理由【读码】）。
- 无采样种子；记录模型 ID、`effort`、日期。

**成本口径**

```
usd = ( 输入未缓存 × p_in + 缓存读 × p_cache_read + 缓存写 × p_cache_write + 输出 × p_out ) ÷ 1,000,000
```

- 价格取价目表快照；快照里没有列出缓存写入价，以官方价目表为准【待核对】。
- 用量优先取客户端汇报的字段（如 Claude Code 无头模式 JSON 输出里的用量与花费【待验证】），缺失时按 token × 价目自算并标 `estimated`。
- **分母包含失败与中止的 run**；包含所有子代理的调用；Heimdall 自身的确定性计算不计费；评测时 `HEIMDALL_LLM=0`，若开启则单列 `heimdallLlmUsd`。
- 中转的折扣与汇率按**名义价目**计，实际账单另记。

**报告模板**（`—` 表示尚未测量，不是 0）

| 夹具 | 模型 | 臂 | 保真 | n | 正式门禁通过 | 最差视口像素（中位 / IQR） | 迭代数（中位） | 美元（中位） | 耗时（中位） | 人工干预 | 终态分布 |

### 2.5 行为评测与后端评测

**行为评测**

| 指标 | 定义 |
| --- | --- |
| 流程通过率 | 候选上通过的声明流程数 ÷ 参考上通过的声明流程数。参考侧自己失败的流程记 `baseline_failed` 并排除（沿用验收「基线通过而目标失败才归因为目标缺陷」【读码】） |
| 视觉后行为回归 | 视觉门禁通过后重跑全部流程，确认视觉修复没破坏行为 |
| 行为注入召回 | 被检出的 `inj-behavior-*` ÷ 注入总数（F3、F4） |
| 断言类型分布 | 用到的 `expect` 类型（含 `count` 等扩展，E8-04）及各自通过率 |

**后端评测**（F5 的隐藏后端提供真值）

| 指标 | 定义 |
| --- | --- |
| 已触达端点召回 | 契约草案里与真值匹配（方法 + 路径模板）的端点 ÷ 旅程**实际触达过**的真值端点。A-7 用它 |
| 总召回（含未触达） | 同上，分母是真值端点全集。**必须同时报告**——没被旅程触达的端点无法被恢复，这是方法的固有上限 |
| Schema 准确度 | 字段名、类型、必需性的精确率与召回率 |
| 训练集重放通过率 | 对训练集每条录制交互，候选响应与录制响应在「结构等价 + 选定值等价（忽略 id、时间戳、令牌等易变字段）」意义下一致的比例 |
| **留出集等价度** | 同口径，但作用在代理从未见过的请求上：未访问的页码、未用过的筛选值、新 id、非法参数。与训练集重放的差值就是过拟合度 |
| 属性 / 契约测试 | 由契约生成请求（边界值、缺省参数、非法参数）：5xx 次数、响应符合 schema 的比例、错误形状一致的比例 |
| 出处准确度 | 抽样核验 `observed` 条目的证据真实性（应为 100%）；`inferred` 条目在真值中成立的比例；`invented` 占比 |
| 严格离线 | 前端 + 适配器在 `live --offline --strict --include-adapter` 下通过（现有裁判【读码】） |
| 写请求安全 | 夹具源站日志里，来自 Heimdall 或代理的非 `GET / HEAD / OPTIONS` 请求数，**必须为 0**（E9-09、E12-10） |
| 未知清单规模 | `unknowns` 条数，随结果一并报告 |

## 3. 一致性与回归测试

原则沿用仓库已有的做法：**能被数字钉住的东西就用测试钉住**（`mcp.test.mjs` 钉死 13 个工具名，`seo-rule-count.test.mjs` 钉死规则条数），不让文档里的数字悄悄漂移。现有测试由 [`test-core.mjs`](../../../core/scripts/test-core.mjs) 只选 `test/*.test.mjs` 运行，新增的单测照此放进 `core/test/`；独立 package 的测试放在各自目录，由新增 CI job 运行（§5）。

### 3.1 MCP 一致性（E2-10）

用**官方 client SDK**（`@modelcontextprotocol/client`）去连 `packages/mcp/`，而不是自己手写 JSON-RPC 客户端——手写客户端会和手写服务器犯同样的错。

| 检查项 | 做法 |
| --- | --- |
| `server/discover` | 返回支持的协议版本、能力、服务器身份 |
| `tools/list` 稳定 | 连续两次调用字节一致；顺序确定；带 `ttlMs` 与 `cacheScope` |
| schema 合法 | 每个工具的 `inputSchema` / `outputSchema` 是合法的 JSON Schema 2020-12 |
| 注解正确 | `readOnlyHint / destructiveHint / idempotentHint / openWorldHint` 与注册表 `effects` 的映射一致；默认代理档的 `tools/list` 不含破坏性工具（E12-01） |
| 结构化结果 | `structuredContent` 通过对应 `outputSchema` 校验；同时有文本回退 |
| 资源 | `resources/list`、`read`、模板补全可用；秘密文件不可读 |
| 图片内容 | 单图不超过上限（E2-03 为 1.5 MB）；同时给资源 URI |
| 错误 | 错误码与信封一致；错误里带 `hint` 与 `nextActions` |
| 兼容握手 | 仍用 2025 版 `initialize` 的客户端能连（legacy stateless） |
| 长任务 | 发起 → `heimdall_jobs` 轮询 → 取结果，全程不依赖 Tasks 扩展；若协商了 Tasks，则 `jobId` 同时是 `taskId`，失败时回落 |
| 并发 | 同时发起 3 个同类任务：1 个运行、2 个排队（E1-08），无 `409` |
| 旧工具迁移 | 旧 13 个工具名经 `legacy` 映射仍通过原 `mcp.test.mjs`（E1-15） |

### 3.4 围栏与提示注入回归（E6-15、E12-08）

| 类别 | 手法 |
| --- | --- |
| 指令覆盖 | 「忽略之前的指令……」及变体 |

| 外泄诱导 | 引导读取环境变量、令牌、`~/.ssh` 并发往某个 URL |

### 3.5 秘密植入与 SSRF 回归（E12-02、E12-05）

**秘密植入**：往测试工作区植入 20 类带 `HMD-CANARY-<n>` 标记的假秘密，然后对**所有输出面**做一次全量扫描，命中必须为 0。

| 植入的 20 类 | |
| --- | --- |
| 会话文件里的 cookie 值与 localStorage 令牌 | HAR 请求头 `Authorization: Bearer`、`Cookie`，响应头 `Set-Cookie` |
| JWT（`eyJ…`）、查询串 `?token=` / `api_key=`、表单 `password=` | 邮箱、手机号、URL 里的 `user:pass@` |
| `sk-`、`AKIA`、`ghp_` 形态的假密钥 | 响应正文 JSON 里键名为 `password / secret / token` 的字段 |
| `operation-plan.json` 的输入值、`operation-discovery.json` 的登录态候选 | `.env` 里的 `LLM_API_KEY`、环境变量 `HEIMDALL_TOKEN` |
| 旅程的原始录制（`network.journey.har`） | 命名登录态文件（`session.<name>.json`） |

扫描面：全部 MCP 工具输出与资源、`artifacts` 接口、CLI 的 `--json` 与人读输出、SSE 事件、审计日志、错误信息、`rebuild init` 生成的 `AGENTS.md` 与 `.heimdall/` 文件、给代理令牌看的控制台接口。方法：精确匹配 canary 子串 + 通用正则（JWT / Bearer / `sk-` / `AKIA` / `ghp_`）两路并行。同时断言 `isSecretFile` 仍拦住静态通道。

**SSRF（远程 / 非回环模式）**：

| 类别 | 例子 |
| --- | --- |
| 回环的各种写法 | `127.0.0.1`、`127.1`、十进制 `2130706433`、十六进制、八进制、`[::1]`、`::ffff:127.0.0.1`、`localhost` / `*.localhost` |
| 私有与链路本地 | `10/8`、`172.16/12`、`192.168/16`、`fc00::/7`、`169.254/16`（含云元数据地址）、`fe80::/10`、`0.0.0.0` |
| 解析陷阱 | DNS 名解析到私有地址；**DNS rebinding**（第一次解析公网、连接时变私网，要求连接时校验）；公网 → 内网的重定向（逐跳校验） |
| 协议与写法 | `file:`、`ftp:`、`gopher:`；`http://public@127.0.0.1/` 这类 userinfo 技巧；端口白名单 |

断言：以上全部被拒绝并返回 `forbidden` 类错误（具体错误码以 [附录 A](appendix-a-tools.md) 为准）；**本机模式行为不变**（夹具仍可用 `127.0.0.1`）。

## 4. 指标

### 4.1 北极星：已验证克隆率 / 美元

**单位是页面**，在指定的门禁等级（默认 `silver`）与固定的阈值版本下统计。

- **已验证** = 正式裁判判 `passed`，且人工干预次数 = 0，且独立复核没有推翻（误判通过 = 0）。
- 失败的、被中止的、超预算的 run **全部计入分母**。

```
已验证克隆率      R = N_pass ÷ N_attempt
每次通过的美元    C = Σ cost_usd（所有 run，含失败与中止） ÷ N_pass
北极星            V = N_pass ÷ Σ cost_usd          单位：页 / 美元
```

为什么用它：它同时惩罚「不通过」和「花得多」；失败的成本算进去，没法靠挑样本漂亮；也不奖励「悄悄降低门禁」，所以**报 V 必须带门禁等级、阈值版本、夹具集与模型 ID**，且只在同口径内比较。夹具集变了就要重新建基线。

### 4.2 先行指标

| 指标 | 定义 | 目标 | 数据来源 | 关联 |

### 5.1 现状【读码：[`ci.yml`](../../../.github/workflows/ci.yml)】

| Job | 名称 | 内容 | 超时 |
| --- | --- | --- | --- |
| `core-test` | `core (test N/2)` | 两个分片并行，`pnpm test -- --test-shard=N/2`；每片各自装依赖、装 Chromium、构建控制台 | 45 分钟 |

### 5.2 分层

**只加不改**：不动上面四个 job 的任何步骤。新 job 与它们并行、互不依赖、各自失败各自诊断——这正是审查报告当初拆 CI 的理由。

| 层 | 何时跑 | 内容 | 调模型 | 估计耗时 | job 名称（建议） |
| --- | --- | --- | --- | --- | --- |
| L1 | 每次推送 / PR | 新增单测（E14-03）进既有 `core (test N/2)` | 否 | 并入现有 | 既有 |
| L1 | 每次推送 / PR | 注册表同步（`gen:check`）、冻结文件守卫、技能体量守卫、双路径一致 | 否 | 1–2 分钟 | `ai (gen-check)` |
| L1 | 每次推送 / PR | MCP 一致性（§3.1）：构建 `packages/mcp`，起本地引擎 + Suite F 夹具（随机端口、临时数据根、`HEIMDALL_LLM=0`），需 Chromium | 否 | 5–10 分钟【估算】 | `ai (mcp)` |
| L1 | 每次推送 / PR | 围栏与提示注入、秘密植入、SSRF（§3.4、§3.5），纯 node 无浏览器 | 否 | 约 3 分钟【估算】 | `ai (safety)` |
| L1 | 推送 `main` + 手动 | 窄 Windows job（§3.8）：CLI 契约、`connect` 配置生成、MCP 连通子集 | 否 | 约 10 分钟【估算】 | `ai (windows)` |
| L2 | **仅手动** `workflow_dispatch` | 带模型调用的 Bench（Suite F） | **是** | 取决于矩阵 | `bench-ai` |
| L3 | 默认关闭 | 趋势哨兵（§4.5） | 是 | 单次约几分钟 | `bench-ai-sentinel` |

要点：
- **Suite O、P 依赖本机工作区，只能在本机跑**，CI 上只能跑 Suite F。要引用 Suite O 的结果，必须附证据目录（§4.5）。
- `bench-ai` 的输入：`models`、`arms`、`n`、`fidelity`、`budgetUsd`（默认 30，硬上限 100，超过要改 workflow 文件并走评审）。产物上传为 artifact，保留 14 天。
- 带模型的评测**永远不在 `pull_request` 上自动跑**：fork 的 PR 拿不到密钥，也不该替别人花钱。
- 本地命令（建议）：`pnpm gen:check`；`pnpm bench:ai -- --suite F --models opus-5-5 --arms A0,A3 --n 2 --budget 40`；`pnpm bench:ai:report`。
