> **一句话**：Heimdall 当 AI 的**眼睛、尺子和裁判**——确定性地取证、度量、判定；
> AI 当**手**——写代码、补逻辑、造后端。两者用「证据 → 补丁 → 复测」闭环收敛，直到门禁通过。
> 闭环失败时永远有**镜像**兜底，所以交付物不会比今天更差（模型费用另计，由预算兜底）。

**先记住四个词**：**镜像** = Heimdall 抓下来的冻结副本，是真值，也是兜底；**门禁** = 一组可判定的通过条件；**修复包** = 告诉 AI「哪里不对、差多少、怎么改」的结构化线索；**裁判** = 做门禁判定的确定性检查。更多术语见 [附录 D §3](appendix-d-references.md)。

## 0. 先回答你的五个问题

| 你问的 | 答案 | 展开 |
| --- | --- | --- |
| **1. 用 API、MCP、Skill 还是 CLI？还是都做？** | **都做，但不做四套**。做一个「能力注册表」，从它生成 HTTP v1（OpenAPI）、MCP 工具、CLI 子命令和文档，四个入口永远一致。分工：**CLI** = 手（会敲命令的代理最省 token）；**MCP** = 手（没有 shell 的聊天、桌面、IDE 代理，以及团队共享服务）；**Skill** = 脑（教代理怎么闭环：流程、判据、何时停）；**HTTP** = 骨（契约，给工作流平台和 CI）。 | [02 §6](02-strategy.md)、[03 §2](03-architecture.md) |
| **2. 价值在哪？** | 前沿模型会写代码，但**看不准**——它没有原站的真值，也没有尺子。Heimdall 恰好有：渲染态 DOM、CSSOM、原件资产、HAR、三视口像素与结构度量、断网门禁。两者拼起来，才有「可验证的 AI 重建」。对项目本身，这还解决了审查报告指出的「验收子系统体量压过主角、演示里却没位置」：它变成 AI 闭环里的**裁判**。 | [01 §3](01-background.md)、本页第 2 节 |
| **3. 能否自动化？** | 能，分三档：**代理驱动**（用户自己的 Claude Code / Codex 等跑闭环）、**内置 Autopilot**（控制台一键，带预算和断点续跑）、**无人值守**（CI 回归门禁、变更监控后自动出更新）。自动不等于无人审：门禁由确定性检查裁决；登录、验证码、写操作仍由人；预算兜底。 | [03 §5–6](03-architecture.md)、[04 E10、E13](04-requirements.md) |
| **4. 加上 Opus 5.5 这类模型，能做高精度前端克隆吗？** | **能，这是最有把握的一环**。Heimdall 把视觉差异变成「编译器报错」式的修复包（哪个区域、什么原因、对应哪个元素、哪个属性差多少、裁剪对比图），模型在小段上反复改，门禁判定。**目标**：静态内容在 375 / 768 / 1440 三视口 ≥ 97%，且永远有镜像兜底。

**Phase 0 实测**（thordata.com 首页两个分段，n 很小，只作内部观察）：Claude Opus 5.5 跑了 4 次，都在第一次快速对比就达到 gold，三视口 99.55–100%。但每段要 1.5–3 美元，成本成了新的主要风险（[05 §6.4](05-frontend-rebuild.md)）。

做不到的会如实标上限：WebGL、运行时画布、视频、滚动编排。 | [05 前端重建](05-frontend-rebuild.md) |
| **5. 能补全逻辑、克隆后端吗？** | **前端交互逻辑：能，且可验证**（录制旅程 → 行为规格 → 实现 → 原站与重建站同流程回放对照）。**后端：只能克隆「被观察到的接口行为」，不是源码**。我们的实测：对本机已抓的 7 个公开站首页或内页做统计，排除 Next.js 预取（`?_rsc=`）后，每页第一方 JSON 端点只有 0–4 个，全是埋点、特性开关、状态、问卷或配置，**没有业务读写**【实测】——所以后端信号必须来自「旅程」（人带着录制器操作自己有权的系统）。产物分 B0–B4 五级，逐条标 observed / inferred / invented，并用「留出集重放」衡量能不能泛化。要完整业务等价，仍需要源码、规格或数据库（与 [PRD](../../../PRD.md) 的「完整业务替代」等级一致）。 | [06 逻辑与后端](06-logic-backend.md) |

## 1. 一页纸方案

```
外部 AI 代理                                           用户
  Claude Code · Codex · Cursor · VS Code               控制台（Vue 3，已有）
  Claude Desktop · ChatGPT · Dify / Coze / n8n         + 连接 AI · AI 活动 · 提示词库（新）
        │ shell        │ MCP          │ HTTP                 │
   ┌────▼────┐   ┌─────▼──────┐  ┌────▼─────┐   ┌───────────┐│
   │ CLI     │   │ MCP v2     │  │ HTTP v1  │   │ Skill +   ││
   │ --json  │   │ stdio+HTTP │  │ OpenAPI  │   │ 插件包     ││
   └────┬────┘   └─────┬──────┘  └────┬─────┘   └─────┬─────┘│
        └──────────────┴───── 能力注册表 ───────────────┘     │
                        Capability Registry（新）               │
   ┌────────────────────────────────────────────────────────▼─┐
   │ 控制面（新）  任务队列 · 幂等 · 预算 · 令牌作用域 · 审计 · 事件流 │
   ├──────────────────────────────────────────────────────────┤
   │ 证据引擎（新）  简报 · 分段 · 对比 · 修复包 · 出处标注            │
   ├──────────────────────────────────────────────────────────┤
   │ 三个闭环（新）  重建环(前端) · 行为环(逻辑) · 契约环(后端)        │
   │ Autopilot（新，赛后）                                        │
   ├──────────────────────────────────────────────────────────┤
   │ 现有引擎（不改）  recon · forge · verify · live · acceptance …  │
   └──────────────────────────────────────────────────────────┘
```

**三个闭环**——每个都是同一个节拍：AI 提议 → Heimdall 度量 → 修复包 → AI 再改 → 门禁通过或预算用尽。

| 环 | AI 做什么 | Heimdall 当裁判的依据 | 产物 | 阶段 |
| --- | --- | --- | --- | --- |
| **重建环**（前端） | 把冻结的镜像改写成可维护的 React / Vue / HTML+Tailwind 项目 | 三视口像素、结构语义、关键元素计算样式、断网加载 | 重建项目 + 门禁报告 | **比赛 MVP** |
| **行为环**（逻辑） | 按录制的旅程补全菜单、标签、搜索、筛选、表单校验等交互 | 原站与重建站同流程回放，对比可观察结果 | 行为规格 + 通过的流程集 | 比赛加分项 / 赛后 |
| **契约环**（后端） | 从抓包和旅程推断接口，写 mock 适配器或服务脚手架 | 对录制请求重放、留出集重放、与源站只读对照、断网严格门禁 | OpenAPI + 适配器 + 覆盖矩阵 | 赛后（比赛仅做夹具演示） |

**一次运行是什么样**（示意，数字为虚构以说明形态）：

```
你  用 Heimdall 把 https://example.com/pricing 重建成 React 项目，放在 ./pricing-clone，
    三个视口达到 silver，预算 5 美元。
AI  heimdall_doctor        引擎在线，浏览器组件就绪
    heimdall_clone         已有镜像，复用（参考包：375 / 768 / 1440 三视口）
    rebuild init           工作区已创建：8 个分段（含 2 个共享组件），41 个原件资产已落地
    分段 1/8 页头          写 → compare 95.8% → 修复包 R1（间距）→ 改 → 97.9% ✓
    …
    heimdall_compare formal  正式门禁：视觉 ✓ 结构 ✓ 样式 ✓ 资产 ✓ 健康 ✓ → passed（silver）
    交付  ./pricing-clone（pnpm dev 即可运行）· 门禁报告 · 镜像附件 · 残差 0 · 花费 2.4 美元 · 用时 12 分钟
```

**五个关键设计决定**（理由见 [02](02-strategy.md)、[03](03-architecture.md)）：

1. **一个注册表，多个外壳**。能力只在注册表里定义一次（名称、输入输出 schema、副作用等级、是否长任务），CLI、MCP、HTTP、文档由它生成。
2. **AI 提议，确定性门禁裁决**。这是项目已有的做法（`fixup` 循环变差就回滚），现在推广到整个重建。
3. **地板是镜像，天花板是重建**。重建没过门禁就交付镜像加报告，永远不比今天差。
4. **重建工作区即合同**。`heimdall rebuild init` 生成一个目录：脚手架、真实资产、简报、`AGENTS.md`、门禁配置。任何打开这个目录的代理都知道该干什么，不依赖特定客户端。
5. **渐进披露**。简报（几千 token）→ 分段（按需）→ 原始文件（最后手段）。本机 415 个已克隆页的 `dom.html` 中位数 600 KB，直接喂给模型既贵又装不下【实测】。

## 2. 价值

| 对谁 | 价值 | 怎么衡量 |
| --- | --- | --- |
| 前端 / 全栈开发者 | 把「拆页面、写第一版、对像素」从天级压到小时级；代码是可维护的组件，不是冻结快照 | 到达门禁的平均耗时与花费（目标见 [09](09-quality-metrics.md)，【假设】） |
| 产品 / 设计 / 市场 | 在聊天里说一句话，拿到可打开的结果与人话摘要；不必碰命令行 | 首次成功时间 ≤ 10 分钟（Connect AI 向导 + 内置示例站，【假设】） |
| 站点所有者、迁移负责人 | 旧站换技术栈时，有**可验证**的保真度，缺口可枚举，改版后可回归 | 门禁报告、回归基线 |
| QA / CI | 重建项目、改版站点都能用同一个裁判做门禁，输出修复包而不只是红灯 | CI 中 `heimdall compare --gate` 退出码与评论 |
| Agent 开发者 / 集成方 | 一个稳定的 OpenAPI + MCP 面，嵌进自己的工作流 | 工具调用成功率、无需读源码即可接入 |
| 本项目 / 本次比赛 | 回答评委最难的问题「AI 用在哪」：**AI 是建造者，Heimdall 是裁判**；把占代码 1/3 的验收子系统放进主线故事；演示有现场可见的闭环 | [10 §2](10-roadmap-risks.md) 的 5 分钟脚本；彩排 ≥ 3 次通过 |

与同类方案相比（细节见 [01 §2](01-background.md)）：开源的「AI 网站克隆」技能（如 `ai-website-cloner-template`）靠代理自己看截图、自己判断像不像；`Perfect-Web-Clone` 已经把「确定性工具 + 代理写代码」的思路讲清楚，但只覆盖单页、固定技术栈。Heimdall 多出来的是：**原件资产、整站图谱、三视口度量、交互与断网门禁、HAR 证据**，以及兜底的镜像。

**工作流改造前后**（比赛主题「AI 工作流改造」的直接对应；耗时为【假设】，由 Bench 实测替换）：

| 环节 | 以前（人工） | 现在（代理 + Heimdall） |
| --- | --- | --- |
| 取证：样式、资源、字体、截图 | 开 F12、另存、逐个下载 | `clone`：自动，原件入库 |
| 拆页面结构 | 看图手工拆分 | `brief` / 分段：自动给出，带三视口边界框 |
| 写第一版 | 人写 | 代理写（建造者） |
| 对像素 | 肉眼、截图叠加 | `compare`：数字 + 区域级修复包 |
| 调细节 | 反复手改、反复刷新 | 代理按修复包改，变差自动回退 |
| 验收 | 肉眼 + 清单 | 正式裁判 + 逐维门禁报告 |
| 交接 | 口头或文档 | 生成 `AGENTS.md` + 报告 + 残差清单 |
| 耗时（一页） | 数小时到数天 | 目标：十几分钟到一两小时【假设】 |

## 3. 范围与优先级

我替你定的排序，理由和裁剪顺序见 [10](10-roadmap-risks.md)。**容量要说实话**：P0 总量按单线程估算约 35 个有效工作日，窗口内约 21 天（[10 §1.6](10-roadmap-risks.md)），所以要靠**并行会话 + 分层（Tier S 必保 / M 加厚 / L 加分）**，并在 Ph0 末用 spike 的实测速度重算。

| 阶段 | 日期 | 目标 | 退出条件 |
| --- | --- | --- | --- |
| **Ph0 预研** | 10-25 → 10-27 | 四个 spike：修复包原型、Opus 5.5 手动重建校准、MCP v2 最小服务连通 Tier-1 客户端、验收 Mirror 接入核对 | 假设表（[10 §3](10-roadmap-risks.md)）逐条有结论；范围冻结。**10-25 已出结论**，A-3 待界面手测 |
| **Ph1 手眼** | 10-28 → 11-03 | 注册表 v0、MCP v2 核心 8 工具、CLI 代理模式、简报 / 分段 / 对比 / 修复包 v1、`heimdall-rebuild` 技能与插件包 | 全新机器装好插件，Claude Code 一句话重建夹具页，快速裁判给出 `pass-candidate`（正式门禁在 Ph2） |
| **Ph2 闭环与剧场** | 11-04 → 11-10 | 收敛控制、重建工作区、Floor=Mirror 交付、控制台「连接 AI / AI 活动」、Bench v0 | Bench v0 出数；演示彩排第一轮 |
| **Ph3 加固与彩排** | 11-11 → 11-17 | 安全最小集、文档、录制回放兜底、彩排 ≥ 3 次；加分项（行为环 lite、契约草案、Vue）只在 Ph1、Ph2 准点退出时才做 | 演示清单全绿 |
| 缓冲与冻结 | 11-18 → 11-20 | 只修彩排暴露的问题 | 冻结 |
| **Ph4 赛后** | 11-21 起 | 旅程录制器、契约环 B2–B3、Autopilot（E1 / E2）、远程 MCP + OAuth、MCP Apps、CI Action、通知、SDK、公开发布 | 另立计划 |

**比赛 MVP 的底线**：E1（最小）+ E2（核心 8 工具）+ E3（代理模式）+ E4（重建技能 + Claude Code 插件）+ E6（简报 / 对比 / 修复包）+ E7（单页重建 + 裁判）+ E11（doctor / connect / 活动视图）+ E12（秘密隔离、不可信内容围栏、预算、审计）+ E14（Bench v0）。需求编号见 [04](04-requirements.md)。
**如果落后**，按这个顺序砍：元素对应与修复包 v2（只留区域级线索）→ Vue 技术栈 → 控制台提示词库 → Bench 自动化（改手工）→ 非 Claude 客户端的打包。**不砍**：安全最小集、Floor=Mirror、录制回放兜底。

**新代码一律加法**：不改验收子系统里被「指纹」冻结的 10 个文件（验收给每次运行盖一个由这 10 个源文件字节哈希组成的指纹，动一个字节新运行就无法生成基线候选；详见 [2026-10-22 审查 §4](../../audits/2026-10-22/README.md)），不动现有演示路径。新能力挂在新路由、新命令、新目录下，出问题可整体关掉。
