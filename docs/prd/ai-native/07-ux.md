## 1. 安装与首次成功

### 1.1 三条旅程的时间预算

| 旅程 | 用户 | 目标（【假设 A-3】） | 路径 |
| --- | --- | --- | --- |
| 开发者首次重建 | U1 | ≤ 10 分钟 | 安装 → `doctor` → `connect` → 在示例站上说一句话 |
| 非技术用户首次成功 | U2 | ≤ 10 分钟 | 控制台首次向导 → 连接 AI → 示例站提示词 |
| 团队接入 | U3 / U4 | ≤ 30 分钟 | 内部市场安装 → 配置令牌 → 接入 CI |

### 1.2 安装路径

**现状**【读码】：根目录 README 的「两步启动」——先给 `core` 和 `console` 各装一次依赖，再运行 `clone-heimdall.cmd`；需要 Node ≥ 20.19、pnpm 11.7+、Playwright Chromium；Dockerfile 与 `docker-compose.yml` 已有。

**目标**：一条命令走完，且每一步失败都有人话提示。

| 阶段 | 形态 | 说明 |
| --- | --- | --- |
| Ph1 | `node bin/heimdall.mjs doctor --fix` | 检查并修复；不重复安装已有的东西 |
| Ph2 | `node bin/heimdall.mjs setup`（E3-11） | 检查 Node → 装依赖（`core`、`console`、`packages/mcp`）→ 装 Chromium（镜像源可配）→ 构建控制台 → 起引擎 → 打开浏览器 → 引导「连接 AI」 |
| Ph4 | `npx` 一条命令、PowerShell / bash 一键脚本、MCPB（Claude Desktop 双击）、Docker | 公开发布依赖 [README D-1](README.md) 的许可决定 |

`setup` 的每一步：

| 步骤 | 成功时 | 失败时的人话提示 |
| --- | --- | --- |
| Node 版本 | 「Node 24.x ✓」 | 「需要 Node 20.19 以上，当前 18.x。装法：…」 |
| 依赖 | 「依赖已就绪 ✓」 | 「安装依赖失败：网络不通？可以设置镜像源：`heimdall setup --registry <url>`」 |
| Chromium | 「浏览器组件 ✓」 | 「没找到浏览器组件。运行 `heimdall doctor --fix` 自动安装」 |
| 引擎 | 「引擎已启动，端口 8900 ✓」 | 「8900 被占用。换端口：`--port 8901`，或关闭占用它的程序」 |
| 数据目录 | 「数据目录可写 ✓」 | 「数据目录不可写：…」 |

### 1.3 `heimdall doctor`

```
Heimdall 体检
  ✓ Node 24.1.0（需要 ≥ 20.19）
  ✓ pnpm 11.7.0
  ✗ 浏览器组件（Chromium）未安装
      修复：heimdall doctor --fix
  ✓ 引擎在 http://127.0.0.1:8900 运行，数据目录一致
  ✓ 数据目录可写（D:\heimdall-data，剩余 214 GB）
  ○ 模型服务未配置（可选；只有 Autopilot 和 AI 校准需要）
  ○ 尚未连接任何 AI 客户端 → heimdall connect
下一步：先运行 heimdall doctor --fix，然后 heimdall connect
```

`✓` 通过、`✗` 必须修、`○` 可选。`--fix` 只做**安全**的事（装 Chromium、起引擎），不改用户配置。`--json` 输出同样的结构（E3-01）。

### 1.4 内置示例站（E11-05）

没有真实站点、没有网络，也要能体验。引擎自带一个**离线夹具站**（即 Bench 的 F1，[09 §1](09-quality-metrics.md)）：

- 控制台首页的「用示例站体验」按钮：自动在本机随机端口起夹具服务、克隆、生成参考包。
- 预置提示词：「用 Heimdall 把示例站首页重建成 React 项目，三个视口达到 silver。」
- 同一个夹具也是 CI、演示、回放兜底的共同底座，所以它的质量直接决定首次体验和演示的稳定性。

### 1.5 首次运行清单（控制台，E11-08）

| 项 | 状态 | 动作 |
| --- | --- | --- |
| 引擎在线 | ✓ | — |
| 浏览器组件 | ✓ / ✗ | 一键修复 |
| 连接 AI | ○ | 「连接 AI」向导 |
| 试试示例站 | ○ | 「用示例站体验」 |

四项都绿，清单自动收起；之后只在「设置」里可再次打开。

## 2. 连接 AI

### 2.1 流程（`heimdall connect` 与控制台「连接 AI」同一套逻辑）

1. **检测**：已安装哪些客户端、是否已配置 Heimdall。
2. **展示**：将写入的配置**差异**（逐行），说明会备份哪个文件。
3. **确认**：用户点「写入」。
4. **写入**：先备份原文件，再写。
5. **自测**：用写入的配置**原样**启动一次 MCP 服务器，执行 `server/discover`、`tools/list`、调用 `heimdall_overview`。
6. **结果**：「看到 8 个工具 ✓　引擎在线 ✓　数据目录一致 ✓」；失败给人话原因和修复建议。

### 2.2 客户端与配置位置

Ph0 S3 在一台 Windows 11 开发机上逐个查过（2026-10-25）。「本机实测」只说明文件位置与格式，客户端是否真的连上，要按 spike 目录里的手测步骤由人在界面里确认（[10 §3](10-roadmap-risks.md) A-3）；`connect` 的实现以实测为准。

| 客户端 | 配置位置 | 格式 | 本机实测 | 备注 |
| --- | --- | --- | --- | --- |
| Claude Code | 用户级 `~/.claude.json`（`claude mcp add` 写这里）、项目 `.mcp.json`、插件自带的 `.mcp.json` | JSON，键 `mcpServers` | `~/.claude.json` 存在且已有用户级服务；命令行 2.1.310 已装但未登录 | 优先走**插件安装**，技能与 MCP 一并装好。无头 `claude -p` 要先登录或设 `ANTHROPIC_API_KEY`，`--bare` 只认 API Key |
| Claude Desktop | `%APPDATA%\Claude\claude_desktop_config.json` | JSON，键 `mcpServers` | 文件存在，目前没有 MCP 服务 | 改完要重启应用；非技术用户首选 MCPB |
| Cursor | 全局 `%USERPROFILE%\.cursor\mcp.json`，或项目 `.cursor/mcp.json` | JSON，键 `mcpServers` | 已装，全局文件尚不存在，`connect` 需要新建 | — |
| VS Code（Copilot） | 用户级 `%APPDATA%\Code\User\mcp.json`，或工作区 `.vscode/mcp.json`；也可用 `code --add-mcp` | JSON，键 **`servers`**（不是 `mcpServers`），每项带 `type: "stdio"` | 已装，用户级文件尚不存在 | 键名与其他客户端不同，`connect` 要分别生成 |
| Codex CLI | `%USERPROFILE%\.codex\config.toml` | **TOML**，表 `[mcp_servers.<名字>]` | 配置文件存在，命令行不在 PATH | 技能走 `.agents/skills/` |

### 2.3 Windows 是一等公民（P11、E3-08）

- 配置里的命令用 `node` + **绝对路径**（指向 `packages/mcp/bin/…`），**不依赖 `npx`**——部分客户端在 Windows 原生环境下调用 `npx` 需要 `cmd /c` 包装，容易出错，绕开最稳。Ph0 S3 用 `node` 绝对路径（`C:/Program Files/nodejs/node.exe`，含空格）拉起 stdio 服务，官方客户端连通【实测】；路径用正斜杠，JSON 里就不必转义反斜杠。
- 路径含空格、含中文、含反斜杠转义，都要在自测里覆盖。
- 不依赖 WSL、不依赖 bash。

### 2.4 卸载与回退

`heimdall connect --remove <client>` 还原备份。控制台的「连接 AI」页对每个客户端显示状态（已连接 / 已检测 / 未找到）与「移除」。

### 2.5 令牌

本机默认不设令牌，行为与今天一致。要给别人用（共享服务）时，向导里「创建令牌」→ 选作用域（只读 / 克隆 / 构建）→ 设预算和有效期 → 复制配置片段（Ph2 起，E1-12）。

## 3. 提示词库（E11-04）

### 3.1 形态

控制台一页卡片，每张：标题、一句话说明、参数表单、**生成的提示词**、「复制」。参数有默认值，用户只要填 URL。共 10 张，正文见 [附录 B §6](appendix-b-playbooks.md)：

| # | 卡片 | 对应场景 |
| --- | --- | --- |
| 1 | 把这一页重建成项目 | S1 |
| 2 | 把整个站迁移成新技术栈 | S2 |
| 3 | 给重建的页面补交互 | S3 |
| 4 | 给前端生成 mock 后端和 OpenAPI | S4 |
| 5 | 提取这个站的设计系统 | S8 |
| 6 | 整理竞品的定价与功能 | S9 |
| 7 | 审计 SEO 并修复 | S7 |
| 8 | 检查我的新版本有没有改坏 | S6 |
| 9 | 这个站改版了，更新我的克隆 | S10 |
| 10 | 为什么这一页没过？解释并给修复建议 | — |

### 3.2 提示词写法

一条好提示词包含：目标、对象（URL 或 siteId）、技术栈、门禁等级、预算、交付位置、禁止事项。示例（卡片 1 生成的内容）：

> 用 Heimdall 把 {url} 这一页重建成 {stack} 项目，放在 {dir}。三个视口都要达到 {level}，花费不超过 {budget} 美元。不要外链任何资源，不要改动门禁配置。完成后告诉我：通过了没有，还有哪些残差，以及怎么运行。

### 3.3 为什么要有它

很多用户第一次不知道该对代理说什么。卡片把「正确的说法」固化下来，同时也是**演示脚本的一部分**：现场复制提示词到 Claude Code 里，比即兴说一句更稳。

## 4. AI 活动（E11-03）

### 4.1 目的

让人**看见**代理在做什么——建立信任、能随时介入、也是演示的主画面。

### 4.2 布局

```
┌ 顶栏：站点 · 当前页 · 代理（客户端名）· 预算条（花费 / 时间 / 调用）· [暂停] [停止代理] [导出报告] ┐
│                                                                                              │
│ 左：星图（当前页高亮）        中：时间线（工具调用流）           右：当前分段                    │
│  分段小方块着色：              12:03:11 brief   首页      0.4s    分数曲线（每次迭代的 pixel）    │
│  灰=未开始 黄=进行中           12:03:20 compare hero      6.1s    ▁▃▅▆▇  95.1→97.4              │
│  绿=通过 红=卡住               12:03:41 compare hero      5.8s    修复包前后对比滑块 ref|cand|diff │
│                               12:03:52 compare formal …   42s     门禁卡：visual ✓ structure ✓    │
│                               每行：时间·工具·摘要·耗时·花费        style ✓ assets ✓ health ✓    │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
        [回放] 徽标：回放模式下顶栏显著显示「回放 — 非实时」
```

### 4.3 数据来源与延迟

审计日志（工具调用）+ 任务事件（SSE）+ 账本（迭代分数）。从代理动作到视图更新延迟 ≤ 2 秒（E11-03 的验收标准）。

### 4.4 复用与新增

复用：`Graph3D`、`ActivityRail`、`Sparkline`、`AuthImage`。新增：`AiConnect.vue`、`AgentActivity.vue`、`PromptGallery.vue`，以及一个前后对比滑块组件。

### 4.5 「停止代理」

一个按钮做两件事：**撤销该代理的令牌**（后续调用全部 `forbidden`）+ **取消它名下正在跑的任务**。这是人对代理的最后一道手动闸。

### 4.6 回放

同一视图读取账本即可回放（E7-14）。**回放必须在视图顶部持续显示徽标**，导出的截图、录屏也带；这是 [RISKS](../../../RISKS.md) 诚实性清单对「演示数据来自真实流水线」的延伸——回放的内容来自真实运行，但不是现场运行，要说明。

### 4.7 窄屏与无障碍

窄屏单列；对比度 ≥ 4.5:1；键盘可达；使用 ARIA 标签（审查报告记录过现有控制台的对比度与 ARIA 缺陷，新视图不重蹈）。

## 5. 人话与错误

### 5.1 摘要规则（E1-07、E11-06）

每个结果的 `summary`：≤ 3 行；先结论后数字；带一句「下一步」；不用内部代号；数字带口径。

| 情况 | `summary` 示例 | `nextActions` 示例 |
| --- | --- | --- |
| 成功 | 「首页重建通过 silver：375 / 768 / 1440 三个视口分别 97.8% / 98.1% / 97.4%，无残差。」 | 导出项目；继续下一页 |
| 部分 | 「hero 段还差 1.2 个百分点（间距），已用 3/4 次迭代。」 | 按修复包 R3、R5 继续；或升级到 faithful |
| 失败 | 「预算用尽，未通过。已交付镜像 + 报告，重建项目标为草稿。」 | 提高预算重跑；只看残差清单 |

### 5.2 错误结构与人话表

结构：`{code, message, hint}`。`message` 说**发生了什么**，`hint` 说**怎么办**（一条命令或一个按钮）。

| code | 人话 | 修复 |
| --- | --- | --- |
| `chromium_missing` | 没找到浏览器组件 | `heimdall doctor --fix` |
| `engine_unreachable` | 引擎没在运行 | `heimdall serve`，或点「启动引擎」 |
| `data_root_mismatch` | 这个引擎写的是另一个数据目录，产物会对不上 | 关闭另一个引擎，或设置 `HEIMDALL_DATA_DIR` 一致 |
| `candidate_unreachable` | 访问不到你的开发服务器 `http://127.0.0.1:5199` | 先运行 `pnpm dev`；检查端口 |
| `reference_missing` | 这一页还没有克隆，没有可对照的参考 | `heimdall clone <url>` |
| `render_not_settled` | 页面一直没加载完（可能有长轮询） | 加 `--allow-bounded`，或在站点配方里调等待策略 |
| `queued` | 前面还有 1 个任务，已排队（这是状态，不是失败） | 等待；或 `heimdall jobs wait <id>` |
| `budget_exceeded` | 已达到预算上限（2 页） | 调高预算，或结束 |
| `forbidden` | 这个令牌没有克隆权限 | 换用有权限的令牌，或在控制台调整 |
| `idempotency_conflict` | 同一个请求键对应了不同的参数 | 换一个新的请求键 |

完整的错误码表在 [附录 A §1.5](appendix-a-tools.md)，`doctor` 的检查项在 [附录 A §2.8](appendix-a-tools.md)；二者合起来覆盖 `doctor` 的所有检查项和常见失败（E11-07）。

### 5.3 控制台任务卡

每张任务卡显示 `summary`，失败时显示 `nextActions` 的按钮（沿用 2026-10-22 审查提出的「人话错误卡片」）。

## 6. 文案规范（E11-11）

| 规则 | 说明 |
| --- | --- |
| 中文为主 | 英文术语首次出现附中文解释，如「修复包（Fix Packet）」 |
| 统一术语 | 还原度、缺口、验收 / 裁判、简报、分段、修复包、旅程、契约、出处 |
| 不出现内部黑话 | 不出现 D1–D6、Schema4、托管、候选这类内部里程碑名词（审查指出 README 开头就是这个问题） |
| 按钮用动词 | 「连接 AI」「复制提示词」「停止代理」 |
| 诚实措辞 | 禁止「100% 还原」「任意站点」；写成「在 X 视口、Y 页面、Z 流程上」 |
| 回放必须标注 | 见 §4.6 |
| 帮助链接 | 指向 `docs/guide/06-ai-integration.md`（开发阶段补写，E11 配套文档） |
