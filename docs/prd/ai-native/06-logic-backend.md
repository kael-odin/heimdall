# 06 逻辑补全与后端克隆

上一篇：[05 前端高精度重建](05-frontend-rebuild.md) · 下一篇：[07 傻瓜式体验](07-ux.md)

本章回答「能不能让 AI 补全逻辑、克隆后端」。结论先说：**前端交互逻辑可以补全并验证；后端只能克隆被观察到的行为，而且要诚实标出覆盖了多少**。能不能做、做到哪一级，取决于有没有被执行过的操作作为信号——所以先讲旅程（§1）。

---

## 1. 旅程（Journey）

### 1.1 为什么必须有旅程

[01 §1.4(c)](01-background.md) 的实测：被动抓取页面，第一方 JSON 端点每页 0–4 个，全是埋点、开关、状态、配置，没有业务读写。**没有被执行过的操作，就没有业务信号**。行为环和契约环都需要「有人真的搜索过、筛选过、翻过页、提交过表单」。

### 1.2 信号从哪来

| 来源 | 谁执行 | 能得到什么 | 限制 | 风险 |
| --- | --- | --- | --- | --- |
| 被动抓取（现有） | 机器，仅载入页面 | 资源、渲染态、埋点 / 开关类请求 | 没有业务操作 | 低 |
| 操作发现（现有 `discover-operations`） | 机器，只点**人审核过**的候选；阻断写请求、跨源、WebSocket、Service Worker | 菜单、标签、展开、同源分页的状态变化与请求类别 | 不填表、不写；GET 仍可能有副作用 | 低到中 |
| **旅程录制（新）** | **人**，在可见浏览器里操作自己有权的系统 | 搜索、筛选、翻页、表单提交、登录后操作的完整请求—响应对 | 需要人投入；数据敏感 | 高：含个人和业务数据 → 秘密级处理 |
| 所有者提供（B4） | 所有者 | OpenAPI、数据库 schema、源码 | 需要协作 | 低 |

### 1.3 录制器设计（E8-05）

沿用「登录并保存会话」的模式：**人在真浏览器里操作，机器只记录**。

| 方面 | 设计 |
| --- | --- |
| 启动 | `heimdall journey start <siteId> --name "<名称>"`，弹出可见 Chromium，带 HAR 录制与事件钩子。页面上有悬浮条「● 录制中　暂停　结束」 |
| 记录什么 | 步骤事件（导航、点击、输入、提交），每步：稳健选择器（角色 + 名称优先）、脱敏 DOM 快照、截图；网络条目写入 `network.journey.har` |
| 输入值 | **默认不记录明文**，只记录「填了什么类型的值」；用户可显式标记某些值「可作夹具」 |
| 用户控制 | 开始 / 暂停 / 结束 / 丢弃；结束时展示「将保存什么」清单和敏感字段命中提示，确认后才落盘 |
| 登录 | 人自己登录；**不自动填表、不处理验证码或 2FA**（[RISKS](../../../RISKS.md) §1，不可配） |
| 写请求 | 只有人在录制中产生的写请求会被记录（它们发生在用户有权的系统上）。**工具链不存在对源站重放写请求的代码路径**（E9-09、E12-10） |
| 经 MCP 触发 | `heimdall_journey(action: start)` 返回 `waiting_input` 并说明「请在弹出的浏览器里操作，完成后点结束」；客户端支持 MRTR 时用 `input_required`，否则返回 `jobId` + 人话提示 + 控制台入口（E2-15） |
| 数据保管 | `network.journey.har` 是秘密级：文件名天然命中 `isSecretFile`，另加按目录兜底的 `isSecretPath()`；任何工具和资源都不返回，默认不进交付包。AI 只能看到清洗后的视图（§3.1） |
| 推荐环境 | 测试环境、自有系统或本地夹具（Bench F5）；对真实生产系统录制前，由使用者自行确认授权与副作用 |

## 2. 行为规格与行为环

### 2.1 行为规格（BehaviorSpec）

把「页面上有哪些会变的东西、怎么变」写成机器可验证的描述。结构见 [附录 C](appendix-c-schemas.md)，要点：

- **组件**：`menu / tabs / accordion / carousel / modal / form / search / filter / pagination / …`，每个有状态集合与转移（事件 → 新状态 → 可观察效果）。
- **流程**：有序步骤 + 期望（对应 `operation-plan.json` 的语言）。
- **网络关联**：某个流程触发了哪些端点（供契约环使用）。
- 每一项带**出处**（§5）：来自操作发现和旅程的标 `observed`；AI 推断的标 `inferred`。

### 2.2 候选从哪来

| 来源 | 内容 |
| --- | --- |
| 操作发现 | 菜单、标签、展开控件、同源分页候选 |
| 静态 DOM 检测 | `<details>`、`[aria-expanded]`、`[role=tab]`、`<dialog>`、`<form>` 及控件、搜索框、轮播标记 |
| 旅程 | 人实际做过的步骤 |
| 动效档案 | `motion.json` 里的触发关系 |
| AI 推断 | 补全上面没有覆盖的，标 `inferred` |

### 2.3 行为环

1. **收集**：`heimdall_spec(kind: behavior, action: infer)` → 行为规格草案。
2. **审阅**：人 / 代理选定要保留的流程，生成 `operation-plan.json` 草案；**人审后才执行**（沿用现有安全姿态）。
3. **实现**：代理在重建项目里实现交互（菜单展开、标签切换、折叠、轮播、客户端搜索 / 筛选、表单校验……）。
4. **双侧回放**：同一流程在参考（镜像或源站只读）和候选上执行，比较**可观察结果**；差异转成修复包（`cause: behavior`）。
5. **收敛**：同 [05 §5](05-frontend-rebuild.md)；门禁 `behavior` 维度要求声明的流程全部通过。

### 2.4 「可观察结果」的定义

| 断言 | 状态 |
| --- | --- |
| `visible`、`hidden`、`text-includes`、`url` | 现有 |
| `count`（元素数）、`value`（输入值）、`attribute`（含 ARIA）、`class` | 新增（E8-04），向后兼容 |

不比较动画时序；不比较视觉（视觉由像素维度负责）。

### 2.5 局限

- 随机、时间相关的行为：需要遮罩或固定种子，否则标 `needs_review`。
- 需要登录的流程：只复用**人保存**的命名会话；离线包仅支持匿名切换（现有限制）。
- 服务端副作用：不回放写；GET 仍可能有副作用，运行前应确认授权范围（现有提示）。

## 3. 契约推断

### 3.1 输入：「给 AI 看的 HAR」

原始 `network.har` 带 cookie 和 `Authorization`，**不出库**（`isSecretFile` 已拦截）。AI 看到的是清洗视图：复用 `live/har.mjs` 的规则（私有路径父级、敏感键名、敏感头、正文扫描、正文 ≤ 1 MiB、非 UTF-8 丢弃），再加上字段值按敏感键脱敏。每条保留：方法、主机、路径、状态、MIME、请求 / 响应的 JSON 形状、出现次数。E9-01 的测试：向 HAR 植入 20 类假秘密，视图里 0 命中。

### 3.2 确定性推断流水线（E9-02）

| 步 | 做什么 |
| --- | --- |
| 1 过滤 | 排除静态资源（沿用 `STATIC_MIME` / `STATIC_EXT`）；第三方埋点按域名分类标 `telemetry`（后续用桩处理） |
| 2 聚类 | 按（方法, 主机, 路径模板）聚类。模板化：UUID → `{uuid}`、纯数字 → `{n}`、长哈希 → `{id}` |
| 3 参数 | 路径参数；查询参数（出现频率、取值集合，取值少且样本足够时标 `enum`）；请求体（JSON → schema） |
| 4 响应 schema | 多个样例合并：类型并集、`required` = 所有样例都有、枚举与格式检测（`date-time` / `uuid` / `email` / `uri`）、数组元素合并、可空；观察到的数值范围只作为 `x-observed` |
| 5 分页 | 同一端点在不同参数下响应的变化：`{page, limit}`、`{offset, limit}`、`{cursor, nextCursor}`；总数字段 |
| 6 错误形状 | 4xx / 5xx 响应体聚类 |
| 7 认证方案 | 只记录**形式**（Bearer 头、Cookie 会话、API Key 头）和名称，**绝不记录值** |
| 8 易变字段表 | 重复请求里值会变的字段（时间戳、随机 ID、nonce）：重放比较时只比类型 |
| 9 观察统计 | 每端点样本数、方差、置信度（样本数与参数变化覆盖的函数）；`unknowns`：只见一次的端点、从没变过的参数、没触发过的错误路径、只见 GET 没见写方法、需要的角色未知 |

### 3.3 AI 增强（全部标 `inferred`）

命名（`operationId`、`summary`）、实体与关系推断、业务规则假设（排序、过滤语义、校验）、种子数据。**每一项增强必须附依据**（指向哪些观察），没有依据的只能标 `invented`。

### 3.4 输出

`heimdall.contract/1`：OpenAPI 3.1 + `observations.json` + `fixtures/` + `unknowns.json`（字段见 [附录 C](appendix-c-schemas.md)）。示意片段：

```yaml
paths:
  /api/items:
    get:
      operationId: listItems            # inferred：AI 命名
      x-heimdall-provenance: observed
      x-heimdall-observations: { samples: 14, variance: low, confidence: 0.92 }
      parameters:
        - { name: page,  in: query, schema: { type: integer }, x-heimdall-provenance: observed }
        - { name: sort,  in: query, schema: { enum: [price, name] }, x-heimdall-provenance: inferred }
      responses:
        "200":
          content: { application/json: { schema: { $ref: "#/components/schemas/ItemPage" } } }
```

当前最小落地形态是交付包内的 `api-contract.json`：它把同一份清洗 HAR 生成的 OpenAPI 3.1、观察统计、未知项和 B0/B1 摘要放在一个文件里，供 AI 直接读取。它只保留方法、路径模板、查询参数名、请求体 Schema、状态码、MIME、响应 JSON 结构和鉴权形态摘要；不保留请求值、认证值、响应示例或业务规则。鉴权摘要只说明观察到的 `bearer`、`cookie`、`api-key` 等形态，不说明哪些接口强制鉴权。`--include-api-har` 才会把可推断的 API 请求 / 响应形状纳入输入，但它仍不能与 `--strict` 同用；没有观察到接口时契约明确标为 B0 / `no-observed-api`。

## 4. 后端验证与分级

### 4.1 五级

| 级 | 名称 | 产物 | 进入条件 | 可以声称 | 不可以声称 |
| --- | --- | --- | --- | --- | --- |
| **B0** | 回放 | HAR 回放 + 许可分发的只读 GET 数据（**现有**） | 有捕获 | 录制过的请求能得到录制过的响应 | 任何泛化 |
| **B1** | 契约 | OpenAPI 观测形状 + 未知清单 | 清洗 HAR 足够 | 我们观察到的接口形状 | 接口之外的行为 |
| **B2** | 行为 mock | 适配器（`runtime-adapter`）实现契约，带状态（内存 / SQLite），种子 = 夹具 | B1 + 旅程覆盖 | 对已观察的请求类型返回同形状、近似值的响应；会话内状态一致（创建后列表可见） | 与真实后端等价 |
| **B3** | 服务脚手架 | 可运行的服务项目：路由、校验、持久化、迁移、测试、Dockerfile；规则多为 `inferred` | B2 + 所有者同意作为起点 | 一个通过同一验证套件的**起点实现** | 业务正确 |
| **B4** | 所有者协作 | 导入所有者的规格 / 源码 / 数据库 schema，与推断结果 diff，补全 `unknowns` | 所有者提供材料 | 依据所有者材料的实现 | — |

和 [PRD](../../../PRD.md) 的等级对照：B2 + 声明流程 + 断网门禁 ≈「可离线交互」；「完整业务替代」需要 B4 并由所有者做业务验收。

### 4.2 验证套件（E9-07）

| 套件 | 做什么 | 通过标准（【假设】） |
| --- | --- | --- |
| **训练集重放** | 对每条训练样本，把录制的请求发给候选：状态码一致；响应符合 schema；非易变字段值相等 | ≥ 98% 样本通过（B2） |
| **留出集重放** | 约 20% 样本在生成阶段**对代理不可见**（按端点分层抽样，样本 ≥ 3 的端点至少留 1 条） | 留出等价度 ≥ 90%（B2，A-7）。这是衡量**泛化**的唯一办法 |
| **属性 / 契约测试** | 按契约生成请求（边界值、缺字段、类型错误），不得 5xx，响应满足 schema，错误形状与观察到的一致 | 0 个 5xx；schema 合规 ≥ 99% |
| **源站只读对照** | 对声明的只读 GET 流程，比较候选与源站（沿用 `--compare-source`、`read-data-plan.json`） | 一致，或差异均被解释 |
| **前端端到端** | 重建前端 + 适配器在断网严格门禁下通过行为流程 | 声明流程全部通过 |

**评测用的地面真值**：Bench F5 / F6 带**已知隐藏后端**。候选在留出集和未见过的新请求（按契约模糊生成）上与隐藏后端比较，得到「行为等价度」（[09 §2](09-quality-metrics.md)）。真实站点没有地面真值，所以只报告重放与对照结果，不报告「等价」。

### 4.3 覆盖矩阵

报告里必须有一张矩阵：端点 ×（观察到、训练重放通过、留出通过、属性测试通过、源站对照）。**未覆盖的格子显式列出**，`unknowns` 也在这里汇总。

### 4.4 写操作

适配器里的 `POST / PUT / DELETE` 用夹具和内存状态实现，不接触源站。来自旅程的写请求样本只用来推断请求 / 响应形状和状态变化（例如「创建后列表多一项」），并标 `inferred`。

### 4.5 适配器协议约束（现有，必须遵守）

`runtime-adapter/index.mjs` + `manifest.json`：路由 ≤ 200；可带命名会话；数据目录必须在包外；请求体 ≤ 4 MiB；单次处理超时 15 秒；不得占用 `/`、`/static`、`/__heimdall`、`/lm` 路径。**已知局限**：本机严格探针不隔离适配器进程的出网（`health.adapter.serverEgress=not-tested`），无外联部署验收靠 Linux CI 的 Docker 无外联网络。

## 5. 出处标注

| 出处 | 定义 | 例子 | 对「通过」的作用 |
| --- | --- | --- | --- |
| `observed` | 有证据直接支持 | 录制到的 `GET /api/items?page=2` 的响应 | 可作为通过的证据 |
| `inferred` | 由观察推断或泛化；带依据与置信度；**AI 生成的规则默认是它** | 由 14 次请求推断的分页方式；「按价格升序」的排序语义 | 可作为参考，不能单独作为通过的证据 |
| `invented` | 为让系统可运行而编的占位 | 种子数据、未观察到的错误文案、默认值 | **不得**作为通过的证据；单列并在报告开头声明数量 |

传播规则：由 `invented` 派生的条目仍是 `invented`；`observed` 与 `inferred` 混合得到 `inferred`。展示规范：每份简报、行为规格、契约、适配器 README 的第一屏必须给出三类计数。示意：

```
契约 B2：端点 18（observed 14 · inferred 3 · invented 1）
覆盖：训练重放 17/18 通过 · 留出 5/6 通过 · 未覆盖 3（见 unknowns）
声明：这不是源站后端的等价物，只覆盖被观察到的请求。
```

## 6. 能与不能

| | 内容 |
| --- | --- |
| **能** | 重现已观察到的请求—响应形状；保持会话内状态一致；让前端在断网时跑通已录制 / 已声明的流程；生成可读的 OpenAPI 和类型；暴露 `unknowns` |
| **不能** | 恢复从未被触发的分支（权限矩阵、边界条件、风控规则）；服务端秘密与算法（推荐、排序、定价、风控）；后台任务、邮件、支付、Webhook 等外部集成；数据本身（除录制样本）；多用户并发语义与事务隔离；限流与配额；数据库约束、索引与性能特征 |
| **需要什么才能** | 所有者提供规格 / 源码 / 数据库；更多旅程覆盖；受控的测试环境 |
| **交付声明（必须）** | 后端交付物 README 头部：分级（B?）、覆盖矩阵、`invented` 数量、「不是源站后端的等价物」 |

「克隆后端」在本方案里的准确含义是：**把你观察到的后端行为，变成一份可验证的契约和一个能让前端跑起来的替身；并明确告诉你哪些部分是观察、哪些是推断、哪些是编的。**
